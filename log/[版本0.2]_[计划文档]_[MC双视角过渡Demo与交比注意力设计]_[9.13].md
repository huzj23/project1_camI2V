# MC 双视角过渡 Demo：Wan2.1 VACE 与交比注意力设计

撰写日期：2026-09-13。承接 [0.1 版整体设计](<./[版本0.1]_[初步整体设计]_[交比融入视频模型]_[9.12].md>)，本次只细化第一轮 demo。文中的网络、阈值和训练配方是待验证方案；目前尚未运行 VACE、训练模块或得到视频实验结果。

**建议路线：Wan2.1-VACE-1.3B 首尾帧 baseline → 人工确认 MC 同名点线 → 小型交比注意力分支 → 学习随去噪逐渐增强的几何权重 → 在生成视频中独立检查结构。** 用户所说的“van2.1”“首位帧”，这里按 Wan2.1 和首尾帧理解。

最先要验证的假设是：在相同首尾图、视频底座和训练预算下，交比是否能减少房屋边沿、窗格、岩层长边在过渡中的错位和变形。交比不能单独确定中间相机路径，也不能保证整段视频严格三维一致。

## 1. 现在采集什么，才能支持后续实验

**两张截图可以立即跑 baseline；要训练可学习分支，最好同时保存连接两端的短录屏。** 没有中间帧时，可以验证点线匹配与交比公式，但无法直接构造常规视频流匹配训练目标。不要把简单溶解、图片插值或 baseline 自己生成的视频当作真实几何监督。

### 1.1 第一批先做小而清楚的场景

| 类别 | 怎么拍 | 验证什么 |
|---|---|---|
| 简单房屋 | 正面略偏左到略偏右，墙面、屋檐、窗沿保持共同可见 | 最容易检查固定结构是否漂移 |
| 有透视的房屋／长墙 | 带少量横向平移和转向，使同一长边的近远间距明显变化 | 区分交比与普通等比例位置编码 |
| 复杂地势 | 岩壁、台地、桥梁等含长直边的区域，同时保留前后遮挡 | 检查少量局部几何在复杂背景中是否有用 |
| 压力样例 | 树林、严重遮挡、低重叠或看不到足够锚点 | 检查分支能否退出，以及方法覆盖范围 |

先收集约 6 对端点图检查流程，房屋与地势各 3 对。训练试验可逐步补到约 12 个独立场景、每场景 3 条短路径；按场景划分 8 个训练、2 个验证、2 个测试，尽量让验证和测试都包含房屋、地势。同一建筑的另一面、相邻路径也算同一场景。这只是 demo 规模，不能据此声称广泛泛化。

采集时遵守以下约定，具体数值是起步建议：

1. 使用相同分辨率和 FOV，固定资源包、光影和画质设置；保留原始 PNG。统一隐藏 HUD、手持物和准星，关闭视角晃动、动态 FOV、运动模糊等干扰。
2. 固定时间、天气，避开动态生物、流动水面、摇摆植被等主要运动源。世界几何应保持静态。
3. 先做短距离、平滑视角变化，目测约 60%–80% 内容重叠。包含真实位置平移，避免所有样例都只是原地转头；角度大小以锚点仍清楚可见为准。
4. 每对图尽量有 3–8 条可用长线，每线 5–6 个可辨认的同名点。缩到模型输入尺寸后，关键点之间最好仍相隔 8–12 像素以上。
5. **每条路径顺手录约 5 秒视频，训练端点从同一录屏抽取。** 如果现在只方便截图，可额外保存沿途 5–9 个视角供几何审核，但它们不等同于完整平滑视频监督。
6. 可额外记录世界坐标、相机位置／朝向／FOV、游戏版本和存档，供离线核验。主实验推理只读取两端 RGB 及由其获得的点线；中间帧、相机和三维标签不能偷偷变成模型输入。

### 1.2 给 MC 结构做可辨认的标记

最方便的几何靶标是一面平墙：在同一条水平边沿上，用不同材质接缝形成 5–6 个清楚的固定交点。可以把它们放在沿线相距不等的位置，例如世界坐标的 x 为 0、1、3、6、10、15，其他两维相同。标注的是明确的接缝交点或实体顶点，不是随视角变化的色块视觉中心。

```text
同一条真实长边： A ─ B ── D ─── E ──── F ───── C
两张图都要认出同一组 A、B、C、D、E、F。
A、B、C 用于建立参照，D、E、F 用于检查参照是否正确。
实际选锚点时，应让三个锚点分布充分展开。
```

不等间距和不同材质是为了减少认错点。等距方块也满足交比，但重复结构很容易把某格误认成相邻格。人工标记样例与自然无标记样例分别报告，避免模型只在彩色靶标上有效。

建议后续数据目录如下；这是约定，本文没有创建这些数据：

```text
data/mc/scene_001/path_01/
  first.png          # 训练时从 gt.mp4 抽取的真实首帧
  last.png           # 同一片段的真实尾帧
  gt.mp4             # 训练目标或独立评测材料，不送入测试条件
  meta.json          # 场景、尺寸、FOV、游戏设置、原始帧号、split
  lines.json         # line_id、point_id、两端像素坐标、可见性、来源
  tracks_gt.json     # 可选中间帧点轨迹，只用于训练监督／评测
```

`lines.json` 中同名点共用 `point_id`，锚点三元组显式保存为 `anchor_ids`；每条线保存 `source=manual/detector/world` 和置信度。像素坐标采用左上为原点、x 向右、y 向下；所有缩放、裁剪、补边变换都记录并同步作用于标注。未知坐标写 `null`，不要用 `(0,0)` 冒充。

## 2. Baseline 如何使用 VACE 的首尾帧功能

选正式的 **Wan2.1-VACE-1.3B** 权重，先用 480P 档。不要混用早期 Preview 权重、普通 T2V 权重或独立的 Wan2.1-FLF2V-14B。官方模型列表明确区分这些模型。[Wan2.1 模型说明](https://github.com/Wan-Video/Wan2.1#model-download)

VACE 官方支持 `frameref` 的 `firstlastframe` 模式。输入应构造成：

| 输入项 | 首帧 | 中间帧 | 尾帧 |
|---|---|---|---|
| `src_video` | 第一张图 | 中性灰占位 | 第二张图 |
| `src_mask` | 黑色，值 0 | 白色，值 255 | 黑色，值 0 |

白色表示要生成，黑色表示已知条件；灰色占位约为 127／127.5，遵循所用预处理代码。**仅把两图传给 `src_ref_images` 不等于指定它们位于时间首尾。** 本实验先不加额外 reference images。[VACE 输入说明](https://github.com/ali-vilab/VACE/blob/main/UserGuide.md#31-vace-recognizable-inputs)

一个容易踩的坑：官方 `FrameRefExpandAnnotator` 的 `expand_num` 是中间补帧数。两张图之间补 79 帧，最终才是 81 帧；补 80 帧会得到 82 帧。不要直接照搬单首帧任务的默认值。预处理完成后必须实际检查帧数和首尾位置。[首尾帧预处理源码](https://github.com/ali-vilab/VACE/blob/main/vace/annotators/frameref.py)

首轮固定 81 帧、16 fps，约 5 秒，模型工作尺寸统一为宽 832、高 480；采集图若为 16:9，统一裁剪或补边并同步更新坐标。先验证官方常用长度，再用 33 帧调试训练显存；33 帧属于另一个配置，不能假定其生成质量等同于 81 帧。

建议模型实现统一选 `Wan-Video/Wan2.1` 仓库；VACE 仓库用于参考预处理。以下是在已安装依赖、下载权重并准备好条件文件后的 **baseline 命令模板，尚未执行**：

```powershell
python generate.py --task vace-1.3B --size "832*480" --frame_num 81 --ckpt_dir "models/Wan2.1-VACE-1.3B" --src_video "data/processed/scene_001_path_01_src.mp4" --src_mask "data/processed/scene_001_path_01_mask.mp4" --prompt "Minecraft 方块风格，一座静止的房屋，镜头平稳向右移动，连续镜头。" --base_seed 2026 --sample_solver unipc --sample_steps 50 --sample_shift 16 --sample_guide_scale 5.0 --offload_model True --t5_cpu --save_file "outputs/baseline_scene_001_seed2026.mp4"
```

参数名称与默认采样设置已核对官方 `generate.py`。这不是 `ali-vilab/VACE` 包装脚本的命令；两者参数接口不同。运行时锁定 Git commit、权重版本和依赖，并记录完整配置。[Wan2.1 推理入口](https://github.com/Wan-Video/Wan2.1/blob/main/generate.py)

生成前解码条件文件检查：帧数、尺寸一致，首尾 mask 全黑、中间全白，首尾 RGB 没有被抽帧丢掉；优先直接传张量或用无损中间文件，防止视频压缩污染 mask。先用相同图片同时作首尾做输入管线检查，再试真实双视角。

Baseline 保存原始生成结果。黑 mask 是条件语义，并不自动证明输出端点逐像素不变。若展示时另外覆盖首尾图片，应另存展示版，评测仍使用未覆盖的原始视频。

## 3. 共线结构怎么识别，SAM 该放在哪里

**第一轮采用人工确认 + 点线工具辅助；SAM 是可选区域工具。** SAM／SAM 2 提供可提示的图像、视频分割，适合圈出房屋或岩壁，却不直接输出精确三维直线和线上同名点。[SAM 2 官方说明](https://github.com/facebookresearch/sam2)

| 方法 | 能提供什么 | 本 demo 的位置 |
|---|---|---|
| 人工点选实体顶点／接缝 | 少量可靠同名点、线身份 | 首轮主方案，先测交比机制 |
| LSD 等线段检测器 | 图像中的候选直线段 | 减少手工找线的工作 |
| GlueStick | 两图点与线的联合匹配候选 | 第二轮自动前端，仍需检验线上点对应 |
| SAM 类分割 | 物体或区域 mask | 背景太复杂时辅助筛选候选 |
| 世界坐标／渲染器标签 | 三维共线真值、可见性等 | 可选离线标签与诊断，不要求现在安装模组 |

GlueStick 的职责是图像点线匹配；不能把它输出的线段端点自动视为同一实体点。[GlueStick 作者代码](https://github.com/cvg/GlueStick)

具体处理顺序：

1. 在两端图找同一墙沿、梁、岩层边等长直线。第一轮人工圈定，后续让 LSD／GlueStick 提出候选。
2. 在每条线两端图中确认至少 4 对同名点，优先 5–6 对；保留实体连接关系和材质上下文。检测截断点、画面裁剪边界、前后结构的假交点都不能直接用。
3. 用 3 对充分展开的锚点拟合一维射影关系；用另外的点独立验证转移误差，必要时 RANSAC 去掉错配。不能用参与拟合的三点误差充当验证。
4. 起步筛选值：在 832×480 图上，点到线误差约不超过 2 px、留出点转移误差约不超过 3 px，至少有 2 个留出点。人工两图重复点选估计标注噪声后，再在验证集固定阈值。
5. 无可靠线时返回空集合，模型正常走 baseline；不要为了凑线数接受错配。

MC 的轴对齐方块使真实长直边容易构造；**台阶状山坡的折线不是一条直线**，不同高度的几段平行边也不是同一条线。一张截图中的二维共线并不证明三维共线；纯旋转、低视差和错误对应等情况下，两图检查也可能误通过。能用存档坐标核验时最好核验，否则保留置信度和人工审核记录。

## 4. 交比如何变成注意力可以使用的信息

把交比理解为“同一条线内部的透视位置编号”。同一组四个物理点的交比在理想透视变化下保持不变，但不同线可以有相同交比，点次序也必须一致。[MIT 视觉教材的交比说明](https://visionbook.mit.edu/3d_scene_understanding_single_view.html#cross-ratio)

先固定某条线上同名的 A、B、C 三个锚点。把线上点投影到该图中拟合直线的一维有向坐标，记其坐标为 a、b、c、s。对任意采样点 P，沿用 0.1 版的交比坐标：

\[
u(P;A,B,C)=\frac{(s-a)(b-c)}{(s-c)(b-a)}.
\]

A 的编号为 0，B 为 1，C 为无穷。同一物理点 P 在另一视角使用同名锚点，编号相同。三锚点只建立参照，第四个及更多独立点用于检验；无需枚举全图所有四元组。

为处理无穷编号，实际计算使用齐次二元向量：

\[
(n,d)=((s-a)(b-c),(s-c)(b-a)),\qquad
h=(n,d)/\sqrt{n^2+d^2}.
\]

同一参照内两点的差异定义为：

\[
D_{ij}=(h_{i,1}h_{j,2}-h_{i,2}h_{j,1})^2.
\]

这个值不受 h 与 −h 的符号差别影响。实现用 FP32 计算，先归一化像素尺度、剔除重复或过近锚点；零范数样本直接标无效，不能只加 epsilon 掩盖退化。固定三锚点身份，不随每张图的左右排序重新命名。

**两图可以各自采样沿线特征，但不能把各自均匀采样的第 k 个位置当成同名点。** 必须计算 u／h 后按几何对应比较。交比相同也不能替代线身份、外观和留出点检验。

## 5. 注意力具体加在哪里

### 5.1 保留底座，加入小型参考线读取分支

Wan 使用时空 token 的自注意力；VACE 另外有条件分支并把其 hints 加入主干。修改位置以 `wan/modules/vace_model.py` 的 `BaseWanAttentionBlock` 为入口，在选定 block 的原计算及 hint 融合之后，加一个 `CRLineAdapter` 残差分支；原 self-attention、文本 cross-attention 和 VACE hints 的计算顺序保留。[VACE 模型源码](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vace_model.py)

```text
首图 + 尾图 ── 条件视频／mask ── VACE 原流程 ────────── 输出视频
     │                                  ↑
     └─ 同名点线 → 沿线干净特征 → 交比注意力 → 残差写回
                                  ↑
                     去噪进度 + 线置信度 + 可学习门控
```

官方自注意力调用 FlashAttention，当前封装没有任意逐对几何 bias 参数。第一轮不要构造全视频 N×N 稠密 bias；小分支按线分组，以普通矩阵乘法和 softmax 实现自己的几何打分即可。[Wan 自注意力](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/model.py)、[FlashAttention 封装](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/attention.py)

起步只在主干约 1/3、2/3 深度加两个 adapter。正式 1.3B 权重配置为 30 层，可先选零基索引 9、19；运行时读实际配置并断言，不采用类构造函数中的默认层数。[正式权重配置](https://huggingface.co/Wan-AI/Wan2.1-VACE-1.3B/blob/main/config.json)

### 5.2 先做 M1：首尾参考图之间的交比融合

每张干净端点图单独经冻结的 Wan VAE 编码，用同一特征投影提取沿线 token。每个 token 保存线 ID、源图位置、锚点参照、h、可见性及外观特征。VAE 的沿线纹理过粗时，再比较冻结的图像特征编码器；不同消融必须用同一编码器。

在同一线内做“首图 Query → 尾图 Key/Value”，再反向融合。几何编号相近的位置更容易互相读取，原始源特征以残差保留。融合后形成参考线特征集合，供视频 token 通过普通交叉注意力读取，再经输出投影写回主干。

M1 无需知道中间帧的线在哪里，适合先验证模型接线和训练。**它只在参考图融合处用了交比，不能宣称已经约束了目标帧交比。** 这一步是调试里程碑；下面的 M2 才实现目标帧的几何读取。

### 5.3 再做 M2：预测中间帧锚点，再按交比读取

输入图里有 A、B、C，不代表第 20 帧中的 A、B、C 已知。增加一个小型 `AnchorHead`：输入两端线特征、归一化视频时间 τ、当前噪声水平和该层已算出的目标隐特征，预测每条线在各目标时刻的锚点及可见性。

第一版使用共享小 MLP 加少量注意力：线特征作为查询，从每个目标隐帧的粗网格特征读取上下文；输出 A、C 的二维位置、B 在 AC 上的比例，以及三个锚点的可见性。让 A、C 包围 B，可用 `B=(1-r)A+rC`、`r=sigmoid(·)` 保证预测三点共线。发生投影退化或无法保持该排列时，该线退出。

端点位置通过下式绑定观测，中间仍可学习：

\[
\widehat P_\tau=(1-\tau)P_0+\tau P_1+\tau(1-\tau)\Delta P_\theta,
\quad P\in\{A,C\}.
\]

B 的比例在两端 logit 比例之间插值，再加同样带 `τ(1−τ)` 的残差。线性插值只是初始化，**不是由真实三维相机投影得到的轨迹**。AnchorHead 使用当前 adapter 之前已经存在的隐特征，每次 forward 都能定义；不需要先从本次尚未生成的 RGB 检测直线，避免循环依赖。

具体读取与写回：

1. 在预测的目标线有效可见区间采样目标特征作为 Q，按预测 A、B、C 计算这些采样位置的 h。
2. K、V 来自两张干净参考图的同一物理线；计算下一节的交比注意力。
3. 输出通过双线性 splat 写回附近视频 token；多条线重叠处按权重归一化，不能反复累加放大。线中心外的窄带仅提供纹理上下文，不赋予它精确共线含义。
4. 锚点退化、位置出界、遮挡或目标置信度低时降低门控；无有效候选时分支输出严格为零。不要把越界坐标夹到图像边缘制造假线。

不能把原始 81 帧直接当成 81 个 Transformer 时间切片。Wan VAE 有时间压缩，空间还会进一步 patchify；实际通过 `grid_sizes` 映射图像位置和目标时刻，保存预处理坐标变换。第一帧与后续压缩组有不同时间语义，尾帧也不等同于单独干净端点的 latent。实现时用带已知标记的短片审核像素到 token 的映射，源特征始终从干净端点单独编码。[Wan 编码与条件处理](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)

## 6. 可学习参数怎样随去噪增强交比影响

**视频时间 τ 是“视频进行到哪里”；去噪进度 p 是“噪声被去掉多少”。** 用 scheduler 的实际噪声量 σ 定义 `p=1−σ`，从高噪声的约 0 走向低噪声的约 1；不要直接把第几帧或原始 timestep 当作 p。训练、推理都使用同一个 σ 定义，尤其要注意 scheduler 的 shift。

对同一线内的有效候选，注意力为：

\[
S_{ij}^{\ell,h}=\frac{q_i^\top k_j}{\sqrt{d_h}}
-\beta_{\ell,h}(p)D_{ij}
+\log(c_j+\epsilon),\qquad
Y_i=\sum_j\operatorname{softmax}_j(S_{ij})v_j.
\]

其中 c_j 是参考候选置信度。参考线身份不同的候选不参与计算；额外保留一个“空候选”，其 V 为零、logit 初始为零，允许拒绝所有参考。无真实候选时直接返回零，避免对全 −∞ 做 softmax。

把几何权重设成一个只有少量参数的单调函数，例如：

\[
\beta_{\ell,h}(p)=\beta_{\max}
\operatorname{sigmoid}\!\left(a_{\ell,h}+\operatorname{softplus}(b_{\ell,h})p\right).
\]

`a、b` 可学习，`βmax` 是固定上限。它让模型学习何时加强、加强多少，同时保证在其他条件不变时，几何 logit 惩罚不会随去噪减弱。这是显式单调先验，不能写成“实验已发现自然单调规律”。

再用单独门控决定实际写回强度：

\[
g_i(p)=c_{\mathrm{line}}\widehat c_i
\operatorname{sigmoid}\!\left(a_g+\operatorname{softplus}(b_g)p\right),\qquad
X'=X+\operatorname{Splat}(g_i(p)W_oY_i).
\]

M1 没有目标锚点时省略目标置信度项；M2 的 `ĉ_i` 来自锚点可见性和有效性。即使 p 增加，错误、遮挡线的实际作用仍应降低。门控与 logit 系数各有职责，不能把一个只依赖整条线的相同常数加到所有 key 的 logit 上——那会被 softmax 抵消。

初始化 `W_o=0`，Q/K/V 投影正常随机初始化，门控保持小的非零值。这样初始输出可退回 baseline，第一步先更新 W_o，随后梯度再进入其他投影；不要把 W_o、门控和 Q/K/V 同时全设为零。

一个可直接开发的起步预算是：最多 8 条线、每图每线 16 个点、adapter 通道 256、4 个头、两个插入层；例如 `βmax=4`、初始 `β(p=0)≈0.05`，初始有效门控约 0.01。它们是验证集调参起点，没有效果保证。先比较固定权重、手工递增和可学习递增；如手工方案同样好，就不能把收益归因于“学会了调度”。

## 7. 训练如何闭环

### 7.1 更新什么参数

第一轮冻结原 Wan 主干、原 VACE 条件分支、VAE 和文本编码器；训练 adapter 的特征投影、Q/K/V、W_o、调度参数及 M2 的 AnchorHead。先不叠加全主干 LoRA，以便解释收益来源。冻结参数不会消除穿过主干的反向传播与激活开销，不能给整个主干包上 `no_grad()` 后还期待早层 adapter 学习。

| 阶段 | 数据和训练 | 要得到的证据 |
|---|---|---|
| P0：端点几何检查 | 两张截图，人工／自动对应；不训练视频模型 | 留出点的几何传递正确，错误线能被拒绝 |
| P1：M1 视频接入 | 真实短视频，以两端作条件 | 零分支复现 baseline，非零分支和调度参数有梯度 |
| P2：M2 锚点训练 | 中间帧轨迹标签监督 AnchorHead，再联合训练 | 训练和推理都能用预测锚点完成读取 |
| P3：测试生成 | 未见场景只提供两端；固定种子成组生成 | RGB 结构改善，不能只看内部坐标自洽 |

仅有端点截图时，可以先做到 P0 和 baseline 推理；真正的可学习视频 demo 仍需补充训练片段，或明确引入其他有真实中间帧的数据。对单个场景拟合可以做调试，但必须标为过拟合演示。

### 7.2 训练目标与梯度路径

主目标使用 Wan 的流匹配约定。若写成 `zσ=(1−σ)z0+σε`，目标速度为 `ε−z0`，训练预测速度的均方误差；实现时核对训练器的实际符号、时间采样和权重，不机械套用普通噪声预测代码。

\[
L=L_{\mathrm{FM}}+\lambda_a L_{\mathrm{anchor}}
+\lambda_v L_{\mathrm{visibility}}+\lambda_m L_{\mathrm{match}}.
\]

`L_anchor` 在真实可见标签上使用归一化坐标 Smooth L1；`L_visibility` 监督可见／不可见，不能让网络把置信度全降为零来逃避锚点误差。`L_match` 监督未参与锚点拟合的真实点对应，可在邻近采样 token 上分配软标签，并加入同线错误位置负样本。没有标签的项关闭，不能把公式生成的位置当作独立真值。

训练使用完整真实片段编码的 z0 作为目标，VACE 条件则只由该片段两端构造，避免中间帧泄漏。轨迹标签可以先用清晰标记跟踪加人工修正；世界坐标投影只在相机／渲染变换和遮挡关系已经核实时作为真值。

AnchorHead 可先独立训练，再接入预测锚点联合训练。最终训练 forward 中使用预测锚点；真实中间锚点只计算损失。专门提供真实中间锚点的实验单列为“几何上界”，不能混入主结果。

第一轮不强行增加生成 RGB 上的交比损失，先以真实视频目标和上述监督闭环。若后续加入，必须有经过验证的可微定位器，例如从解码预测干净视频中软定位同名标记，误差反传经过 VAE 解码与主干抵达 adapter。硬线检测、argmax、RANSAC 不能直接提供这条梯度。用 AnchorHead 自己构造的点计算交比损失，只会得到自动满足的约束。

### 7.3 小规模训练配方

先用 1–2 条训练片段做 50–100 次更新的梯度／过拟合检查；再在训练集试 500–2,000 次更新，按验证集选 checkpoint。可从 batch=1、梯度累积 4、AdamW 学习率 `1e−4`、梯度裁剪 1.0 起步；数据很少时优先检查过拟合，而非盲目延长训练。

首轮先只开 `L_FM` 验证分支学习，再分别加入辅助项；辅助权重先按梯度量级调到不压过主目标，再在验证集固定。混合精度、缓存冻结的端点／文本特征和 gradient checkpointing 可用于控制开销。33 帧只用于流程调试；最终比较统一回到同一 81 帧设置，必要时加入对应长度的适配训练。

显卡和训练环境尚未确定，不承诺显存或训练时长。实施第一天应记录一轮推理和一次反向的峰值显存、耗时及实际可训练参数数目，再调整预算。官方推理脚本本身不是现成训练器，P1/P2 需要增加训练入口。

## 8. 怎样判断交比确实有效

首轮至少保留下面的对照，使用同一套两端图、点线、特征编码器、训练划分、采样参数和随机种子。除原始 baseline 外，匹配新增模块容量与训练更新数。

| 编号 | 设置 | 排除的其他解释 |
|---|---|---|
| B0 | 原始 VACE 首尾帧 | 基础生成能力 |
| B1 | 相同分支与点线，但 β=0，仅外观注意力 | 收益只是多了参数、线特征或锚点预测 |
| B2 | 用 AC 线段普通归一化坐标替换 h | 收益只是沿线位置约束 |
| C1 | 交比，固定 β 和固定写回门控 | 几何本身的作用 |
| C2 | 交比，固定手工递增调度 | 递增先验是否已经足够 |
| C3 | 交比，可学习递增调度 | 学习调度是否额外有效 |
| H1 | 三锚点一维射影变换对齐 + 同样注意力 | 交比是否只是等价的几何参数化 |

在 B1–C3 内分别跑 M1 与 M2，先做最有信息量的 B0/B1/C3，再补全归因对照。M2 的所有对照使用相同 AnchorHead 和训练信息。**三对锚点的一维射影变换，与交比坐标传递，在理想条件下等价；H1 不是交比应当必然胜过的弱基线。** 若效果相当，应把结果解释成射影对齐有效，而非发现了更多几何信息。

每个测试端点对至少用 3 个相同种子配对比较，同时保留失败视频。测量分三组：

- **输入几何：** 每对图有效线数、真实同名点数、留出点转移误差、自动前端失败率。人工与自动前端分开报告。
- **输出视频：** 从原始生成 RGB 独立定位同名标记，测交比偏差、直线弯曲、点身份／窗格数量保持、跨帧闪烁、首尾邻域突变；不能拿 adapter 的采样点当测量点。
- **代价和机制：** 峰值显存、训练／推理耗时、额外参数、有效几何覆盖率；记录 β(p)、门控、正确 key 的注意力质量和空候选使用率。β 非零本身不证明有用。

交比误差可采用第 4 节的齐次距离：用生成图中独立定位的 A、B、C 与留出点 D 构造 h，与两端可靠观测比较。同时报告四点共线残差、标记检出率和身份错误率；如果生成器抹掉了难点，缺失应记作失败，不能删掉后只报告剩余点均值。

真实录屏主要用于训练和结构参照。因为两端不唯一决定中间相机路径，主实验不以逐帧 PSNR／LPIPS 作为唯一胜负标准；合理但走另一条路径的视频也可能逐像素差异很大。提供真实轨迹或中间锚点的受控实验要单独报告。

为把 demo 变成可判断的试验，可预先设定内部继续标准：C3 相对 B1 的独立结构误差中位数下降约 10% 以上，标记保留率不下降，改善出现在多数测试对／种子，且无可靠线时可正常退回。10% 是项目决策阈值，必须高于重复标注噪声，不是显著性结论；只赢 B0、只在一个 seed 获胜或只见内部交比误差降低，证据都不足。

## 9. 开发顺序与验收物

| 顺序 | 后续需要实现的内容 | 验收物 |
|---|---|---|
| 1 | 条件视频／mask 构造、baseline runner | 条件帧可视化、原始 baseline 视频、配置与版本记录 |
| 2 | 人工标注读取、候选点线验证、交比坐标 | 两端同名点叠图、留出点转移图、失败样例 |
| 3 | M1 adapter 和去噪调度 | 零分支与 baseline 对齐、参数梯度记录、首轮消融视频 |
| 4 | AnchorHead、M2 稀疏读取／写回、训练入口 | 预测锚点轨迹、真实标签对照、真实与预测锚点差距 |
| 5 | 独立 RGB 结构评测、对照汇总 | 并排视频、指标表、失败率、门控曲线、资源实测 |

建议后续模块名为 `prepare_mc_vace.py`、`line_frontend.py`、`cross_ratio.py`、`cr_line_adapter.py`、`anchor_head.py`、`train_cr_adapter.py`、`evaluate_mc_geometry.py`。这些是开发清单，不是工作区已经存在的脚本。

接入时必须检查：随机射影变换前后 h 等价；退化锚点与全空候选无 NaN；`W_o=0` 时结果退回 baseline；关闭几何时不残留隐藏几何筛选；Q/K/V 与调度最终收到梯度；像素／latent 坐标正确；训练和测试条件不包含真实中间帧。CFG 两条前向使用同一几何条件和噪声调度，几何启用规则保持一致。

如果人工点线下都无改善，先查注意力作用和评测，不急于堆自动分割；如果人工有效、自动无效，下一步重点是对应前端；如果真实中间锚点有效、预测锚点无效，瓶颈就是 AnchorHead。复杂地势没有足够长线时，诚实报告几何覆盖不足，保留 baseline 的生成能力。

本次文档完成的是上述 demo 的设计。下一步最有价值的输入是：**几对带共同长边的 MC 首尾 PNG，以及同路径短录屏**；其中简单房屋优先验证机制，复杂地势检验适用范围。
