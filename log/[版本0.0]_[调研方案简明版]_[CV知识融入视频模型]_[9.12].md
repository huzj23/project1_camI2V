# 扩散视频模型“架构注入”科研方向：入门简明版

> 本文只回答：每个方向到底做什么、输入输出是什么、改模型哪里、改善什么、需要多少计算。  
> 复杂公式、完整查新和文献来源保留在[详细版](总idea.md)中。

## 0. 先直接回答最容易混淆的问题

### 这些方向主要是做什么的？

绝大多数方向都是做**视频生成模型**，特别是“单张图片生成视频”（Image-to-Video，I2V）：

```text
输入：一张起始图片 + 文字描述 + 可选的相机/物体运动轨迹
                         ↓
                 扩散视频生成模型
                         ↓
输出：一段新生成的视频
```

例如，输入一张房间照片，再输入“相机向右移动”，模型生成一段相机向右移动的视频。研究目标不是输出相机参数，而是让生成的视频真的像相机按指定轨迹运动，而且不同帧中的墙、桌子和物体保持一致。

少数方向也可以用于**视频矫正或图像重建**，但为了形成一篇问题清楚的论文，最好为每个方向只选择一个主要任务，不要同时声称“既能生成、又能矫正、又能估计参数”。

### 什么是“架构注入”？

普通做法是把深度图、边缘图等当成额外输入，或者在训练时增加一个损失函数。“架构注入”更进一步：直接修改模型内部的信息传递规则。

以 CamI2V 为例：

- 普通注意力：当前像素可以从另一帧的所有位置读取信息；
- CamI2V：当前像素主要从它对应的极线附近读取信息；
- 结果：模型内部的信息流符合双目几何，而不是只靠数据自己学。

本文提出的方向也是这种思路：把 Hough 投票、Canny 连通、滚动快门成像、骨架、光照方程等知识写成新的 attention、token、记忆单元或投影层。

### 这些方向是在加速模型吗？

**大多不是。** 它们主要改善的是：

- 新视角视频的几何一致性；
- 物体形状和身份在不同帧中的一致性；
- 遮挡、快速运动或错误对应下的稳定性；
- 光照、法向和三维表面之间的物理一致性。

新增模块通常会让推理增加约 5%–30% 的计算，某些多假设方案甚至更慢。如果主要目标是“加速推理、降低显存或减少训练成本”，应该研究蒸馏、缓存、量化或线性注意力；那是另一条论文路线，不是这里这些物理先验方向的主要价值。

### “模型参数”是输入输出吗？

这里有两种不同的“参数”：

1. **模型参数量**：例如模型有 14 亿个可训练权重；这是模型大小。
2. **几何参数**：例如物体位置、旋转、相机位姿、深度、法向；它们可能作为输入，或由模型在内部临时估计。

本文多数方案的最终输出仍然是**视频**。几何参数通常只是内部中间量，不是最终产品。

如果项目仍以 CamI2V 为中心，我建议优先顺序是：

```text
V²-DiT 主线

  └─ 有滚动快门数据/渲染能力 → 转 RSRA，做更窄但物理更强的问题
```

## 2. 第一推荐：V²-DiT 投票—验证扩散模型

### 一句话说明

让不同像素先对“物体可能在哪里、如何运动”进行投票，模型只在得到较多像素支持的运动假设之间传递信息。

### 它在做什么？

它做的是**视频生成**，不是单纯计算相机参数。

目标例子：输入一张汽车图片，要求相机向右移动、汽车向前运动。普通模型可能让车轮变形、车身漂移或背景粘到汽车上。V²-DiT 希望先在内部形成几个“汽车可能移动到这里”的候选，再选择有最多局部证据支持的候选，用它指导后续帧生成。

### 输入和输出

- 输入：一张首帧图片、文字、相机轨迹；可选输入物体中心/关键点的稀疏轨迹。
- 输出：16 帧或更长的视频。
- 内部中间量：若干运动/姿态假设，例如位置、旋转和缩放。
- 不要求把姿态参数作为最终输出；它们主要用来解释和控制视频生成。

### 利用的知识：Hough 投票与 RANSAC

- **Hough 投票**：一条边缘自己不能确定整个物体在哪里，但很多边缘可以分别投票；票数集中的位置更可能是正确答案。
- **RANSAC**：面对大量错误匹配时，先提出多个可能解释，再统计每个解释能得到多少数据支持，拒绝离群点。

通俗地说，不让每个像素“各说各话”，而是让它们先推举几个全局解释，再按支持度做决定。

### 修改模型哪里？

在 CamI2V/DynamiCrafter 的中间特征层加入一组 **hypothesis tokens（假设 token）**：

```text
参考图边缘/局部特征
          ↓ 投票
位置、旋转、尺度等候选假设 token
          ↓ 计算有多少像素支持
保留可信假设，错误信息进入 reject token
          ↓ 反向发送信息
目标帧中的对应区域继续去噪和生成
```

最重要的创新不是让网络额外预测一次姿态，而是让这些假设直接决定模型内部“谁可以和谁交换信息”。

### 主要优化什么？

- 主要：动态物体的形状一致性、轨迹遵循、遮挡鲁棒性、错误对应鲁棒性。
- 次要：扩展成平面或三维运动假设后，可改善新视角的三维一致性。
- 不主要优化：推理速度、训练成本和纯画质。
- 可能代价：推理比原模型慢约 5%–20%。

### 基础模型与预计规模

- 第一阶段基座：CamI2V/DynamiCrafter，约 14 亿参数，256×256、16 帧。
- 原基座冻结，只训练新增模块。
- 预计新增可训练参数：约 2,000 万–1 亿，取决于插入几层以及假设 token 数量。
- 小验证：1–2 张 24GB GPU。
- 论文级训练：4–8 张 24GB 以上 GPU，约 30k–50k step。

以上参数量是设计预算，不是已经实测的结果。实现后必须报告真实参数、显存和速度。

### 最先做什么实验？

先不要训练真实大模型。制作一个简单合成数据集：物体发生平移、旋转、缩放，并随机遮住一半或加入大量错误边缘。比较：

- 普通 attention；
- 同样参数量的普通 latent tokens；
- V² 投票—验证模块。

如果在 50% 遮挡/错误点下仍不能明显更准确，就停止这个方向，不进入大模型训练。

### 我的判断

这是最适合做主线论文的方向。它与 CamI2V 的“限制信息流”思想一致，但解决的不是同一个问题：CamI2V 处理相机导致的极线对应，V² 更侧重动态物体、多解、遮挡和错误匹配。

## 3. 高新颖专项：RSRA 滚动快门射线注意

### 一句话说明

手机相机的一张图并不是所有像素同时拍下的；模型应该为每一行使用略有不同的相机位置和时间。

### 它在做什么？

推荐把它定义成**滚动快门条件下的相机控制视频生成**。也可以做视频矫正，但首篇论文最好不要两个任务一起做。

### 输入和输出

- 输入：一张首帧、文字、连续相机轨迹、传感器从上到下或从下到上的读出方向、整帧读出时间。
- 输出：一段符合指定相机运动的视频。
- 内部使用：每一行的曝光时间以及当时的相机射线。
- 它通常不输出相机轨迹；轨迹是已知条件。

### 利用的知识：滚动快门

很多 CMOS 相机是逐行曝光的。拍摄快速运动物体时，图像顶部与底部对应的时间不同，因此直线可能变弯、快速旋转的物体会倾斜。

CamI2V 默认一整帧共用同一个相机姿态。RSRA 则认为第 10 行和第 500 行应该使用不同时间的相机姿态，所以跨帧对应区域是一条随时间变化的曲线带，而不是固定极线。

### 修改模型哪里？

- 将 CamI2V 的每帧 Plücker ray 改成逐行、连续时间的 ray encoding；
- 将普通极线 attention mask 改成滚动快门曲线 attention mask；
- 用不确定度控制曲线带宽；参数不可靠时允许退回 register token。

### 主要优化什么？

- 主要：真实手机/运动相机下的新视角几何一致性和相机控制准确性。
- 也可扩展：滚动快门矫正和去模糊。
- 不优化：推理速度；预计增加 5%–15% 推理开销。

### 模型和计算

- 基座：CamI2V 最合适，因为可以直接替换其极线模块。
- 新增参数：约 1,000 万–4,000 万；几何 mask 本身主要是计算，不一定有大量参数。
- 数据：最好用 Blender/Unreal 按逐行时间渲染真值，再用真实滚动快门数据做外部验证。
- 计算：小实验 1–2 张 24GB GPU；完整训练 4–8 张 24GB GPU。

### 查新提醒

已有扩散模型做单幅滚动快门矫正，所以不能声称“首次把扩散用于滚动快门”。可守的创新是：**首次或较早把逐行相机位姿变成可控视频生成中的跨帧注意力支持区域**。

### 我的判断

这个方向物理定义最清楚，实验也容易用合成真值验证；缺点是任务比较窄，而且需要图形学渲染或相机知识。

## 4. 最低成本方向：HiCA 迟滞连通注意

### 一句话说明

只允许边缘信息沿着真实连续的轮廓传播，减少视频中物体边界的断裂和闪烁。

### 输入和输出

- 输入：一张图片、文字，可选相机轨迹。
- 输出：视频。
- 内部中间量：强边、弱边、非边缘及“是否与强边连通”的概率图。
- 不输出边缘图；边缘图只是帮助生成视频。

### 利用的知识：Canny 迟滞阈值

Canny 边缘检测把边缘分成强边和弱边。强边可以直接保留；弱边只有在与强边连接时才保留。这样既不丢掉连续的细边，也不会保留大量孤立噪声。

HiCA 把这个规则变成 attention 图：强边是信息传播的种子，与它连接的弱边可以加入，孤立弱边不能参与。

### 修改模型哪里？

- 在高分辨率特征层估计强/弱边；
- 建立像素邻接图和跨帧邻接图；
- 通过几轮连通传播得到 attention mask；
- 扩散早期只使用最强主轮廓，后期再逐渐加入细边。

### 主要优化什么？

- 轮廓连续性；
- 人体肢体、工业零件、线稿和动画中的形状稳定；
- 视频帧之间的边缘闪烁。

它不是三维重建方法，也不是推理加速方法。它主要改善二维/时间结构一致性。

### 模型和计算

- 基座：CamI2V、DynamiCrafter 或较小的视频扩散模型均可。
- 新增参数：约 500 万–3,000 万。
- 训练：1–4 张 24GB GPU 即可完成主要验证；推理开销约 5%–10%。
- 数据：线稿动画、分割视频、合成移动物体，或从普通视频自动提取边缘。

### 查新提醒

已有扩散边缘检测和形态学卷积。这个方向不能只说“把边缘/膨胀腐蚀加入扩散模型”；必须证明真正有效的是 Canny 特有的“强边种子—弱边连通—孤立边拒绝”。

### 我的判断

这是最容易实现和最适合算力有限条件的方向。上限可能不如 V²，但很适合先获得稳定实验结果。

## 5. 强备选：Skeleton–SDF 双流结构模型

### 一句话说明

同时保存物体的“骨架拓扑”和“骨架到表面的距离”，避免只保骨架却丢失外形，或只保表面却弄断结构。

### 输入和输出

- 输入：一张人物、动物、工具或细长结构图片，加文字/动作条件。
- 输出：结构保持的视频；医学任务也可以输出结构图或分割图。
- 内部中间量：骨架图、分叉点、端点和 signed distance field（SDF）。

### 利用的知识：骨架和 SDF

- **骨架**：可以把一个形状想成道路网络；端点和分叉关系描述它是否连通。
- **SDF**：每个位置保存“到物体边界有多远”；它描述局部粗细和表面位置。

骨架负责“结构有没有断、分支关系对不对”，SDF 负责“身体或管道有多粗、表面在哪里”。

### 修改模型哪里？

建立两个并行分支：

- 图分支：处理骨架节点和连接关系；
- 场分支：处理普通二维/三维特征和边界距离；
- 每隔若干层让骨架与表面相互交换信息。

这比把一张骨架图直接送入 ControlNet 更强，因为骨架和表面在模型内部是两种不同 token，并有明确的双向映射。

### 主要优化什么？

- 人体肢体不丢失、不多长；
- 工具、血管、道路等细长结构不断裂；
- 物体粗细和表面更稳定。

它主要优化拓扑和形状，不直接优化相机控制或推理速度。

### 模型和计算

- 新增参数：约 2,000 万–8,000 万。
- 训练：4–8 张 24GB GPU 较稳妥；推理开销约 10%–25%。
- 最好先在二值形状或医学结构生成上验证，再进入自然视频。

### 我的判断

概念容易理解、指标清楚，但骨架条件和 SDF diffusion 都已有论文。新意必须来自“骨架图 token 与距离场 token 的双向架构”，不能只是同时输入两张条件图。

## 6. 三维光照方向：Integrability Projector

### 一句话说明

要求模型预测的表面法向必须真的能够组成一个三维表面，而不是每个像素各自生成一个看似合理的方向。

### 输入和输出

有两种清楚的任务定义：

1. 输入一张物体图片和目标光源，输出重新打光的图像/视频；
2. 输入一张图片和相机轨迹，输出材质、光照与形状在各帧一致的视频。

模型可以额外输出法向、深度、反照率作为训练和解释结果，但最终产品仍是图像或视频。

### 利用的知识：成像分解与可积性

- 像素亮度大致由物体颜色、表面朝向和光源共同决定；
- 法向告诉我们表面朝哪个方向；
- 如果相邻法向相互矛盾，它们就不能组成一个真实连续表面；这称为不可积。

通俗说，普通模型可能画出一张“每个小箭头都像对的法向图”，但把这些箭头拼起来时根本不存在对应的三维物体。投影层会把它们调整到最接近的可实现表面。

### 修改模型哪里？

- 将中间特征分成法向、材质、光照和残差 token；
- 用 Lambertian/球谐成像关系进行显式交互；
- 每隔若干层使用可微 Poisson/Helmholtz 投影，修正不能形成表面的法向；
- 将修正后的几何信息重新送回生成分支。

### 主要优化什么？

- 新视角三维表面一致性；
- 重光照准确性；
- 材质与光照分离；
- 跨帧法向和深度稳定性。

它不是加速方法，通常会增加 10%–30% 计算。

### 模型和计算

- 新增参数：约 2,000 万–1 亿；Poisson 投影主要增加计算而不是大量权重。
- 小实验：Blender 物体、已知法向/深度/光源，1–4 张 GPU。
- 论文级自然视频：4–8 张 48GB GPU 更合适。

### 我的判断

如果团队有三维、渲染、法向或 HDRI 数据经验，这是非常好的方向；否则数据与实现门槛比 V²/HiCA 高。

## 7. 高风险方向：Cross-Ratio Attention

### 一句话说明

让模型使用一种在透视变化下仍保持不变的几何比例，帮助大视角建筑和道路生成。

### 输入和输出

- 输入：一张建筑/室内/道路图片和目标相机轨迹。
- 输出：新视角图像或视频。
- 内部中间量：直线、直线上的四个特征点和它们的交比。

### 利用的知识：交比

相机从不同位置观察一条直线时，点之间的普通距离会改变，但四个共线点形成的某种比例——交比——在理想投影变换下不变。

因此模型可以不用死记像素距离，而是比较两个视角中的四点关系是否一致。

### 修改模型哪里？

- 检测图像中的长直线和线上特征点；
- 为四个共线点计算交比；
- 交比相近的不同视角 token 才获得较高 attention 权重；
- 退化或检测错误的线进入 reject token。

### 主要优化什么？

- 大视角变化下建筑直线与立面结构；
- 强透视中的对应和新视角一致性；
- 可能提高相机外推能力。

它不直接处理动态物体，也不加速推理。

### 模型和计算

- 新增参数：约 1,000 万–5,000 万；主要成本来自直线/四点候选。
- 训练：先用棋盘、建筑立面合成数据，1–2 张 GPU；进入视频后需 4–8 张 GPU。
- 推理开销预计 10%–30%。

### 我的判断

检索空白较大，但前端直线检测、四点排序和数值稳定性都很难。适合追求高新颖性并愿意承担失败风险的项目，不适合作为第一项实现。

## 8. 运动备选：Aperture-Covariance Attention

### 一句话说明

不把光流当成绝对正确的一个点，而是根据图像局部结构给出一个“可能运动区域”。

### 输入和输出

- 输入：一张首帧、文字和可选轨迹。
- 输出：视频。
- 内部中间量：运动方向、二维不确定性椭圆和遮挡置信度。

### 利用的知识：光流孔径问题

只看一小段直线边缘时，我们通常只能确定它垂直于边缘的运动，无法确定沿边缘方向移动了多少；这就是孔径问题。角点能更准确地确定二维运动，平坦区域则几乎无法确定。

因此跨帧 attention 不应永远只看一个预测点：

- 角点附近看一个小圆；
- 直线边缘附近看一个沿边缘方向拉长的椭圆；
- 平坦或遮挡区域放弃硬匹配，改用记忆/生成 token。

### 主要优化什么？

- 低纹理区域和长边缘的时间一致性；
- 光流估计错误时的鲁棒性；
- 遮挡边界附近的错误复制。

它主要改善动态一致性，不是三维建模或加速。

### 模型和计算

- 新增参数：约 1,000 万–4,000 万；推理增加约 5%–15%。
- 1–4 张 24GB GPU 可先验证；完整论文建议 4–8 张。
- 必须与普通 flow warp、固定窗口和 deformable attention 比较。

### 我的判断

这是一个实用且容易解释的备选，可与 V² 组合。但光流指导视频扩散已有很多工作，标题创新必须强调“由孔径问题解析得到的不确定性椭圆”。

## 9. 长视频备选：Particle Memory

### 一句话说明

物体被遮住时，不只记住一个可能位置，而是同时保存多个未来假设，等物体重新出现后再选择。

### 输入和输出

- 输入：起始图片、文字、可选相机/物体轨迹和目标视频长度。
- 输出：较长视频。
- 内部中间量：每个物体的多个位置、深度、速度、可见性和外观“粒子”。

### 利用的知识：粒子滤波

如果球滚到桌子后面，我们不知道它会从左边还是右边出现。Kalman 滤波通常只维护一个平均位置；粒子滤波会保留多个可能位置，每个可能性有自己的权重。看到新证据后，再提高正确分支的权重。

### 修改模型哪里？

- 为每个主要物体保存固定数量的 particle tokens；
- 每帧预测每个粒子的新状态；
- 根据当前生成特征重新计算权重；
- 必要时删除低权重粒子、复制高权重粒子；
- 遮挡解除后由图像证据选择正确分支。

### 主要优化什么？

- 长时间遮挡后的身份和位置恢复；
- 多种合理未来；
- 长视频记忆不随帧数无限增长。

它不加速推理。由于每个物体保留多个分支，可能增加 20%–60% 计算。

### 模型和计算

- 新增参数：约 3,000 万–1.5 亿；参数不一定随粒子数增长，但激活和计算会增长。
- 初始验证可在低分辨率 toy video 上用 1–2 张 GPU；论文级自然长视频建议 8 张 48GB/80GB GPU。

### 查新与判断

粒子滤波已经被用于 diffusion 采样纠错，DiffPF 也把 diffusion 用于粒子状态估计。因此不能声称“首次结合粒子滤波和扩散”。可能的新意只能是：**粒子作为视频生成网络内部长期存在的对象记忆，并直接路由视频内容**。这是高风险、高算力方向，不建议最先做。

## 10. 其他次级方向，用一句话说明

| 方向 | 做什么 | 输入 → 输出 | 主要改善 | 推荐判断 |
|---|---|---|---|---|
| 平面—单应混合路由 | 把场景分成若干平面，每个平面按相机运动单独 warp | 图片+相机轨迹 → 视频 | 室内墙面/地面新视角 3D 一致性 | 好理解，但已有工作较多 |
| 消失点线束注意 | 让建筑线条只沿着指向消失点的方向聚合 | 图片+相机轨迹 → 视频/图像 | 长直线、道路和建筑透视 | 可做，但消失点条件已有先例 |
| 遮挡偏序注意 | 显式表示谁在前、谁在后，前景不能错误读取后景 | 图片+运动 → 视频 | 遮挡与新显露区域 | 适合与平面/粒子方案组合 |
| Delaunay 稀疏图 | 按关键点的几何邻接关系建立 attention 图 | 图片 → 视频/图像 | 不规则结构和局部拓扑 | 新颖但可微实现困难 |

| 焦点扩张/TTC 注意 | 根据前进相机的放射状光流组织信息 | 道路图+相机运动 → 驾驶视频 | 前进运动和碰撞时间一致性 | 任务很窄 |

## 11. 哪些方向现在不建议单独做？

| 不建议方向 | 原因 |
|---|---|
| 再做一个普通极线 attention | Pose-guided Diffusion、CamCo、CamI2V 等已经覆盖。 |
| 单纯输入深度、边缘、骨架或法向图 | ControlNet/adapter 类方案非常多，不足以形成新的架构主张。 |
| 普通 Kalman DiT block | 2026 年 ConfCtrl 已直接提出 Kalman-inspired predict-update 和 Kalman DiT Block。 |
| 普通膨胀/腐蚀形态学卷积 | 2026 年 DEGMC 已将 morphological convolution 放入 diffusion U-Net。 |
| 泛化频域/小波模块 | 小波 diffusion、FAM、FreqFlow、DeCo、Scale Space Diffusion 等已经拥挤。 |
| 只加一个物理损失 | 可以作为辅助实验，但不能证明模型架构真的使用了该物理计算过程。 |

## 12. 不同研究目标应该选哪个方向？

### 如果目标是“改善生成视频的三维一致性”

优先考虑：

1. RSRA：针对真实滚动快门相机；
2. Integrability Projector：针对形状、法向和光照；
3. Cross-Ratio / 平面—单应路由：针对建筑和大视角变化；
4. V² 的后续三维版本：让假设 token 表示平面或 SE(3) 运动。

### 如果目标是“让动态物体在视频里不变形、不漂移”

优先考虑：

1. V²-DiT；
2. HiCA；
3. Skeleton–SDF；
4. Aperture-Covariance Attention。

### 如果目标是“处理遮挡和长视频”

优先考虑：

1. V² 的 reject/multi-hypothesis 版本；
2. 遮挡偏序 attention；
3. Particle Memory。

### 如果目标是“视频矫正”

- 滚动快门矫正：RSRA 的 restoration 版本；
- 边缘闪烁矫正：HiCA 的 video-to-video 版本；
- 运动传播错误矫正：Aperture-Covariance 版本。

这时输入会从“一张图片”改为“已有的错误视频”，输出为“矫正后视频”。论文中要明确它是 restoration，而不是 I2V generation。

### 如果目标是“加速推理或降低训练成本”

以上方向都不是最佳选择。应另外研究：

- attention 稀疏化/线性化；
- KV cache 和跨步特征复用；
- 少步蒸馏；
- 量化；
- 更小视频 VAE 或 token pruning。

物理先验最多可能间接减少搜索空间，但不能预先承诺更快；必须以实测为准。

## 13. 最现实的一篇论文方案

### 方案 A：算力和时间正常，做 V²-DiT

```text
基座：CamI2V/DynamiCrafter
输入：首帧 + 文字 + 相机轨迹 + 可选物体轨迹
输出：16 帧视频
新增：Hough/RANSAC 风格的 hypothesis tokens 和 reject token
主要指标：物体结构、轨迹、遮挡鲁棒性、相机控制、FVD
算力：4–8 张 24GB GPU；论文总预算约 2,000–5,000 GPU 小时
时间：约 4–6 个月
```

### 方案 B：只有少量算力，做 HiCA

```text
基座：小视频扩散模型或冻结 CamI2V
输入：首帧 + 文字
输出：短视频
新增：强/弱边分类、连通传播和稀疏 attention mask
主要指标：边界断裂、连通分量、跨帧边缘误差、FVD
算力：1–4 张 24GB GPU
时间：约 2–4 个月
```

### 方案 C：有渲染/传感器能力，做 RSRA

```text
基座：CamI2V
输入：首帧 + 相机连续轨迹 + 滚动快门读出参数
输出：相机受控视频
新增：逐行射线编码和曲线 attention mask
主要指标：逐行重投影误差、直线弯曲、相机控制、FVD
算力：4–8 张 24GB GPU + Blender/Unreal 数据渲染
时间：约 4–6 个月
```

### 最终建议

如果目前还没有特定数据或三维渲染积累，先做：

1. 用一周复现 CamI2V 的推理和评价；
2. 用一周在简单合成图形上验证 V² 投票—验证层；
3. 同时实现一个非常小的 HiCA 作为保险；
4. V² 小实验明显有效，再投入完整视频训练；
5. 小实验无效，立即转 HiCA，不浪费大模型算力。

这条路线的核心不是“一次实现很多经典视觉算法”，而是选择一个知识点，证明它被写进架构后，确实改变了信息流，并且比同参数普通 attention、额外条件图和辅助损失更有效。
