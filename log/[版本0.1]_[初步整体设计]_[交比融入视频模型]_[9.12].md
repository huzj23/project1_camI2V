# 交比引导的双图视角过渡视频模型：完整设计

## 1. 先确定最终做什么

建议把第一版模型暂称为 **CR-Bridge：交比引导的双图视角过渡模型**。这是一个待实验验证的研究方案，不是已经取得效果的方法。

**输入两张同一静态场景、视角不同且有重叠的照片，输出连接这两个视角的一段视频。重点减少窗框、栏杆、墙面纹理等结构在过渡过程中的错位和变形。**

例如：第一张照片从左侧拍摄一面建筑外墙，第二张从右侧拍摄同一面墙。模型生成一段像摄影者从左侧移动到右侧的短视频，希望相机运动时，窗户仍是原来的窗户，窗沿上的标记不乱跑。

| 项目 | 第一版明确约定 |
|---|---|
| 最终产品 | 一个双图条件视频生成模型；工程上是预训练视频模型加一个可训练的交比分支 |
| 输入 | 同一静态场景的两张 RGB 图片；视频长度；可选文字描述 |
| 相机输入 | 不要求用户提供焦距、相机位置或旋转；这不等于能从交比恢复这些量 |
| 输出 | 短视频；调试时可另存匹配直线、锚点轨迹与置信度 |
| 优化目标 | 已观测直线结构的跨视角对应、细节保持与视频中的投影一致性 |
| 不作为主目标 | 推理加速、相机标定、精确轨迹输出、完整三维建模、已有视频矫正 |
| 初始场景 | 建筑立面、走廊、室内装修等直线丰富的静态环境 |
| 初始运动 | 两个输入视角之间、具有足够共同可见区域的短程平滑过渡 |

这里的“过渡”是模型生成一种合理运动，不是严格执行以米、角度表示的相机轨迹。两个端点不能唯一确定中间相机路径。若要求“向右移动 1 米、绕物体转 30 度”，必须增加相机条件或几何估计；那是另一个明确标注的版本。

第一版不选单图，是因为交比最直接的作用是比较不同图像中的同一组点。只有一张图片时，缺少第二份真实观测，交比不能凭空告诉模型背面是什么。第一版也不选三维重建，因为交比只提供局部投影约束，不能独自完成整场景建模。

## 2. 交比究竟是什么，有什么优势

### 2.1 用一根带标记的栏杆理解

一根真实的直栏杆上有四个固定标记 A、B、C、D。从侧面拍，照片中的标记间距会被透视压缩：近处显得疏，远处显得密。因此，直接比较“两标记相距多少像素”通常不能跨视角使用。

交比是把四点间的距离组成一个特定的“比值之比”。理想透视成像下，观察同一根三维直线上的同四点，虽然像素距离变化，交比保持不变。课程第 18 章讲的正是这种投影不变量。[^1][^2]

把四点在图像直线上的有向一维坐标写成 a、b、c、d，可以采用以下约定：

\[
\operatorname{CR}(a,b;c,d)=\frac{(a-c)(b-d)}{(a-d)(b-c)}.
\]

不同资料可能交换点的次序而采用另一种等价约定。实现时必须固定同一组物理点的身份与排列，不能把不同顺序得到的数字直接比较。

### 2.2 对几个具体问题的回答

| 问题 | 准确答案 |
|---|---|
| 可以不知道相机参数吗？ | **计算交比和验证线上的对应关系，可以不输入相机内外参。** 但仍要找到同一组物理点，并满足成像条件。 |
| 可以使用不同相机拍的照片吗？ | 可以。不同焦距、位置、旋转本身不破坏理想透视下的不变性。两图必须拍到同一真实结构，而非仅仅内容相似。 |
| 可以完全无视镜头问题吗？ | 不可以。明显鱼眼或径向畸变会破坏直线成像，需要校正或专门建模；校正可能仍需估计畸变参数。 |
| 可以直接算出三维坐标或相机轨迹吗？ | 不可以。交比不是深度、尺度或相机位姿的完整解算器。 |
| 比普通注意力多了什么？ | 一个与透视变化相容的“这条线上的位置编号”，使模型不只凭外观判断应读取哪里的信息。 |
| 比完整三维表示更强吗？ | 不更强。它只约束局部直线上的对应，不保证所有像素来自同一个三维场景。 |
| 能加速吗？ | 单个交比很便宜，但检测、匹配和新增注意力都有开销。本方案不承诺加速。 |

它的核心价值可以概括为：**不先把整个场景重建出来，也能获得部分跨视角的几何对应约束。** 使用交比开展未标定图像匹配已有经典先例，不能作为新的发现来写。[^3]

### 2.3 不要把交比理解为“物体身份证”

不同栏杆、不同窗户上的四点，完全可能有相同交比。特别是四个等距点，无论属于哪个物体，都有相同的交比。因此必须同时知道“这是哪一条线”和“锚点分别是谁”。

交比解决的是**已建立共同参照之后，沿线位置如何跨视角对应**，不是仅凭一个数字认出世界中的任意物体。

## 3. 已有多图视频和 FlashWorld 之后，还剩什么研究空间

多图输入本身不是贡献。Generative Inbetweening 已研究两个关键帧之间的视频生成；NoPo3DFusion 已把两张无位姿 RGB 图片、三维高斯重建与视频扩散结合，用于长序列新视角合成。[^4][^5]

FlashWorld 则从单张图片或文字生成显式三维高斯场景，并通过蒸馏提升速度与质量。这种方法能从一个共享三维表示渲染不同视角，具有本方案的局部交比约束所不具备的全局表示优势。[^6]

因此，不应宣称“FlashWorld 不懂几何，而交比能保证真正三维一致”。更合适的研究问题是：

> 在相同的两张输入、相同视频底座和训练预算下，把直线上的投影对应写进注意力，能否比纯外观注意力更可靠地保留参考图中的结构细节，尤其是在透视压缩、不同焦距和部分遮挡下？

这是**待验证的假设**。可能的价值是减少对高质量完整重建的依赖、改善局部信息读取，不是已经证明比 FlashWorld 更快或三维质量更好。拿本方案的两张输入对比 FlashWorld 的一张输入，也不能把差异全部归功于交比。

还有一个更直接的架构相关工作：PRoPE 把完整相机内外参关系编码到注意力中。我们的区别应是以观测到的共同直线与锚点作为局部参照，而不是使用已知相机矩阵；区别不等于优越性。[^7]

### 一个必须提前承认的数学事实

**三对锚点确定一条线上的一维射影变换；用交比传递其他点，与用这个一维变换传递点，在理想条件下是等价的。**

因此，“把交比换个名字做位置编码”可能不足以构成强论文。必须比较“一维单应变换对齐 + 普通注意力”。若二者效果相同，就不能声称交比带来了额外几何信息。潜在贡献应在可靠匹配、噪声条件下的几何读取、遮挡处理与生成任务的组合设计上，并由消融实验确认。

## 4. 四个三维共线点，实际怎么找

### 4.1 一张图里看着共线，并不够

照片压扁了深度。几个不同深度的点可能碰巧落在同一条图像直线上；遮挡形成的轮廓，也不一定是固定的三维直线。

所以不能执行“检测四个共线像素 → 当作真实三维直线 → 强制全视频满足交比”这样的流程。线检测器只给出候选，不提供三维真实性证明。

### 4.2 第一版前端：先匹配，再验证，再采样

**第一步：检测候选点和线。** 在两张输入图片中找窗沿、栏杆横梁、墙面接缝等候选直线，同时提取角点、纹理特征和线之间的连接关系。可使用 GlueStick 这样的点线联合匹配方法构建初始候选；它不是三维共线性的保证器。[^8]

**第二步：建立同一物理点的候选对应。** 对每条候选线寻找多个可重复识别的标记，例如一条横梁上的螺钉、同一平面窗沿上的真实接点、清晰纹理斑点。仅有“这两条线匹配了”还不够，必须进一步确定线上的点怎样对应。

特别注意：检测出的线段端点常常只是裁剪边界、遮挡处或检测器的截断位置，不一定是同一物理点。两条线在图像中的交叉，也可能只是前后遮挡形成的假交点，不能自动当作锚点。

**第三步：用三个对应锚点提出假设，用额外点检验。** 选三对分布较开、置信度较高的点 A↔A′、B↔B′、C↔C′，拟合沿线的一维射影关系；再看没有参与拟合的 D、E 等点能否被准确预测。多试少量候选组合，保留能解释更多独立对应点的假设。

三个锚点只够拟合，没有验证余量。第四个点给出第一条额外约束。工程上优先使用具有至少 5–6 个可靠匹配点的候选线，但这是筛选设置，不是数学要求所有直线都必须有六点。

**第四步：联合判断置信度。** 结合外观匹配、留出点误差、直线拟合误差、遮挡、锚点间距和附近真实连接关系。保留多个相近假设或直接放弃低置信度线，不为了凑数量强行匹配。

**第五步：确认对应关系后，才在同一条线的可见部分采样特征。** 由已拟合的投影关系，把源图采样位置传递到另一张图。这里采样的是已知对应关系上的位置，不是独立猜测四个点。

### 4.3 两张图验证通过，也不是绝对证明

在相机有有效平移、两个反投影平面不重合、点对应正确的一般情形下，同一组点在两张图中都落在对应直线上，为真实三维共线提供很强的证据。直观上，两张图各自限定一个空间平面，两个不同平面的交线就是候选三维直线。

但纯旋转、低视差、相关极平面重合，以及错误对应，会破坏这种判断。甚至可以构造“两图都共线、交比也相同，三维点却不共线”的退化例子。因此无相机参数前端应输出**可信度**，不能输出“已经数学证明真实共线”。

如果允许更多训练信息，建议离线使用三视图以上、估计相机和三角化来生成较可靠的三维线标签，再检查重投影误差与三维点到直线距离。LIMAP 是可参考的三维线建图系统。若测试时也依赖它，就应把该版本明确标为“几何估计辅助版”，不能再声称推理过程完全没有三维估计。[^9]

即使没有已知标定，也可以尝试射影重建并检验共线性，因为射影变换保留共线关系；但这仍然是在做几何估计，不是仅凭交比免费获得三维结构。

### 4.4 最可能卡住的地方

现实中“检测到很多线”和“每条线上有足够多可靠的同名点”是两回事。光滑桌沿可能只有两个能识别的端点，第三个锚点都找不到。重复窗格又可能让外观匹配产生多个同样合理的解。

所以应先审核真实数据中可用直线的覆盖率，而不是先训练视频大模型。找不到三对锚点时，交比分支应关闭或退回普通线特征注意力。若引入已验证平面上的虚拟线补充覆盖，必须同时比较平面单应变换；不能任意在非平面图像上画线就当作真实三维直线。

## 5. 无限多个四点组合，怎样避免枚举

核心办法是：**固定三个真实对应锚点，其他每个点作为第四点。**

假设同一条物理线上的三个标记 A、B、C 已在两张图中对应。对于线上任意点 P，定义一个由交比构成的位置坐标：

\[
u(P;A,B,C)=\frac{(s-a)(b-c)}{(s-c)(b-a)}.
\]

这里 s、a、b、c 是点在图像直线上的一维有向坐标，可由二维像素点投影到拟合直线方向得到。

这个约定把 A 编号为 0、B 编号为 1、C 编号为无穷。对于另一张图中的同一物理点 P′，使用对应的 A′、B′、C′，会得到同一个 u。于是 u 成为**这条线内部、这套锚点参照下的跨视角位置编号**。

```text
真实物体：    A ── P ─── B ───── C
图片一：     A₁ ─ P₁ ── B₁ ─── C₁
图片二：     A₂ ─── P₂ ─── B₂ ─ C₂

像素间距可以不同；同名点 P₁、P₂ 的交比坐标相同。
前提：两张图使用的是同名 A、B、C，而不是各自任意选三个点。
```

若一条线采样 32 个位置，只需为这些位置分别计算坐标，不必枚举所有四点组合。第一版可设最多 64 条线、每线 32 点、每线最多 3 套锚点假设；这些是起步超参数，后续由覆盖率和显存实验调整。

**不能在两张图中各自均匀采样，再把第 k 个点当作对应点。** 透视变换不保持等间距。更危险的是，两边独立等距采样得到的四点交比仍然相同，因而只检查交比会得到毫无意义的“成功”。

也不能跨不同直线或不同锚点系统，直接比较 u：每条线有自己的参照。若更换锚点，必须同时更换两端的同名锚点，并重新计算坐标。

## 6. 具体怎样写进模型架构

### 6.1 先理解注意力

注意力可以理解为“当前生成位置应该从哪些参考位置读取信息”。普通注意力主要根据特征相似度分配权重：当前正在生成的窗户，看起来与哪块参考图更像，就多读取那里。

问题是，建筑上许多窗户外观相似，很容易读错另一个窗户。交比分支在外观之外增加条件：**先确认同一条物理线，再优先读取线上相同投影位置的特征。**

### 6.2 整体结构

```text
两张输入图片
   ├─ 原视频底座的关键帧条件 ───────────────────────────┐
   │                                                    │
   └─ 点线匹配与留出点验证                               │
          ↓                                             │
      共同直线、同名锚点、可见性、置信度                  │
          ↓                                             │
      交比坐标 + 沿线图像特征                            │
          ↓                                             │
      跨参考图对齐与融合 → 直线特征记忆库                 │
                                  ↓                     ↓
参考图全局特征 → 中间帧锚点预测器 → 交比引导读取 → 视频生成主干
                                  ↑                     │
                        当前视频隐特征，按需更新          ↓
                                                     输出视频
```

这里“隐特征”是模型内部压缩后的图像表示，不是三维坐标。“记忆库”是参考图特征的集合，不是数据库产品。

### 6.3 模块 A：建立直线特征记忆库

对每条验证后的共同直线，保存线身份、同名锚点、采样位置、交比坐标、可见性与置信度。从两张干净参考图提取沿线特征，得到带几何编号的 token。

先在**同一条线的不同参考图之间**做交叉注意力，把交比位置一致的特征融合。第一版只实现这一步也有意义：它不需要知道尚未生成的视频里直线在哪，是风险较低的最小模型。

在这个最小版本中，将融合后的线特征作为额外 Key/Value，交给目标视频 token 做普通交叉注意力，同时保留源图位置与线身份信息。此时只有源图之间的对齐使用交比；目标到源的读取仍由外观学习，不能称为已经实现了目标帧的几何约束。

线附近可以采窄条带提供纹理上下文，但精确交比约束只作用于线中心位置。不能声称整个条带里的像素都属于同一条三维直线。

### 6.4 模块 B：中间帧的锚点位置从哪里来

这是架构必须补齐的环节：输入图中有 A、B、C，不代表我们已经知道第 10 帧中的 A、B、C。**不能直接拿未知目标帧的交比坐标计算注意力。**

建议增加一个小型锚点预测器：输入两张参考图的全局与线特征、视频帧位置，以及与生成过程共享的隐特征；输出每条线在各中间帧的三个锚点位置和可见性。两端锚点绑定观测值，中间锚点由训练学得。

可把每帧的 A、C 作为两个二维点预测，再用线上位置系数表示 B，保证三个预测点共线。在线段始终有限且 B 位于 A、C 之间的有效区间内可限制该系数为 0 到 1；不满足条件、发生遮挡或投影退化时，应退出该表示或关闭分支，而不是硬夹到画面内。

锚点预测器不是交比公式推导出的“真实相机轨迹”。它只是一个受端点、训练监督和视频内容约束的局部运动预测模块。多条线通过共享全局特征和真实连接点约束相互协调，但仍不保证它们来自同一个物理相机运动。

训练和推理中都必须让它接触模型预测的不准确中间状态。不能训练时一直给真实目标锚点、测试时突然要求它从噪声中自行找到锚点。

### 6.5 模块 C：交比引导的目标到参考注意力

得到某个目标帧的线和三个锚点后，可以把同一交比编号映射到这帧的图像位置，在那里读取生成隐特征作为 Query；参考记忆库提供 Key 和 Value。

先按“同一物理线”筛选，再按交比坐标检索少量候选，最后结合外观相似度决定读多少。这是稀疏的额外注意力分支，不是把原模型所有注意力都替换掉。

直观打分规则为：

\[
\text{注意力得分}
=\text{外观相似度}
-\text{交比位置不一致惩罚}
+\text{参考特征可信度奖励}.
\]

几何负责限制“去哪里找”，外观负责判断“找到的东西是否真的相同”。加入空候选，允许模型选择不读取任何几何特征，避免被错误匹配强制带偏。

读出的信息通过小型输出投影和门控，以残差方式写回视频隐特征。门控初始为零或很小，使新增分支在训练开始时不会破坏原底座。

### 6.6 区分视频时间和去噪时间

视频第几帧记为 τ；扩散或流匹配采样进行到哪一步记为 t。这两个时间不同。

生成刚开始、噪声很强时，不能可靠地检测目标图中的线。此时可使用干净参考图之间的融合，但应降低依赖目标锚点的分支权重。随着中间结果变清晰，再根据锚点置信度逐步加强几何读取。

如使用生成结果来修正锚点，使用上一轮去噪的预测或前一层已经存在的隐特征，再用于下一步；不能在同一步中要求“先有正确交比才能生成图，又先有生成图才能定义交比”，却不给初始化方案。

## 7. 数学与实现细节

### 7.1 不直接使用可能爆炸的交比数值

当 P 接近锚点 C 时，u 趋向无穷。直接把 u、log(u) 或 1/u 送入网络容易出现数值问题。建议使用齐次二元表示：

\[
n=(s-a)(b-c),\quad d=(s-c)(b-a),\qquad
h=\frac{(n,d)}{\sqrt{n^2+d^2}}.
\]

h 与 −h 表示同一个射影坐标。使用不依赖符号的距离：

\[
D_{ij}=(h_{i,1}h_{j,2}-h_{i,2}h_{j,1})^2
=1-(h_i^\top h_j)^2.
\]

第一种写法避免了浮点误差造成第二种写法略为负数的问题。输入坐标先按图像尺度归一化；锚点重复或过近时先剔除，不能仅靠加一个很小的分母掩盖几何退化。

这个距离只有在同一条线、同名锚点系统内才可比较。它能平稳表示无穷坐标，但不意味着锚点定位噪声已经消失；仍需传播坐标不确定性或用多套锚点检验稳定性。

### 7.2 一个可实现的注意力公式

对已经通过线身份和可见性筛选的候选集合，使用：

\[
S_{ij}=\frac{q_i^\top k_j}{\sqrt{d_f}}
-\lambda\frac{D_{ij}}{\sigma_i^2+\sigma_j^2+\varepsilon}
+\eta\log(c_j+\varepsilon),\qquad
Y_i=\sum_j\operatorname{softmax}_j(S_{ij})v_j.
\]

d_f 是特征维数；c 是置信度；σ 表示在该几何距离下的不确定性，不能直接混用像素单位。可通过对锚点坐标施加符合检测误差的微小扰动，估计交比坐标的变化。λ、η 控制几何与置信度的影响。

高不确定性只意味着放宽几何匹配，不意味着这个候选值得信任。因此还要降低残差门控，并保留空候选。第一版可以用经过验证的置信度分档代替复杂的不确定性学习，先验证基本效用。

目标线上某个编号的二维位置，可通过逆变换获得。已知齐次坐标 (n,d) 和目标帧锚点的一维坐标 a、b、c：

\[
s=\frac{n(b-a)c-d(b-c)a}{n(b-a)-d(b-c)}.
\]

分母接近零意味着该位置趋于无穷，应屏蔽；落在图像外或不可见区域也应屏蔽，不应将坐标强行截到边界。注意：用公式构造出的点自动满足交比，这只能说明坐标系统自洽，不能证明最终生成的图像细节正确。

### 7.3 计算量来自哪里

记共同直线数为 M，每线采样点数为 n，参考图数为 R，视频帧数为 T，每次读取的邻居数为 k，锚点假设数为 G。

交比坐标计算大致随 GMRn 线性增加。源到源按线分别做注意力，可避免所有线之间无差别比较。以一套锚点、两图单向比较为例，64 条线各 32 点，需要 64×32²＝65,536 次点对比较；把所有 2,048 个源点与所有目标点比较则是 4,194,304 次。

目标到参考只读取同一线上的 k 个邻居时，比较数量约为 GTMnRk，而不是枚举像素四元组。排序、匹配前端、特征提取、写回操作和原视频主干另计。这个局部分支的稀疏性，不能被拿来宣称整个视频模型获得了同等比例的加速。

### 7.4 基础数值检查

配套的 [cross_ratio_sanity.py](tmp/cross_ratio_sanity.py) 使用标准库检查了四组性质：1,000 组非退化随机一维射影变换下的交比与位置传递；无穷交比坐标的齐次表示；独立等距采样产生的错误对应；两相机共同极平面中的假共线反例。四组测试均通过。

第三组特别说明：两个各自等距的四点组，交比相同，并不说明其物理对应正确。第四组采用两个不同相机，构造不共线的三维点，使它们在两图中都共线且交比相同，验证退化情形确实存在。这些只是公式和边界检查，不是对前端准确率、训练收敛或生成质量的实验验证。

## 8. 底座、训练数据与损失

### 8.1 底座选择

建议第一版以 **Wan2.1-VACE-1.3B** 为候选底座，而不是从头训练视频模型。其官方实现提供参考图、视频和掩码条件；可用“首尾帧保留、中间帧待生成”的掩码构建双端点任务。这个选择是为了已有条件接口和较小底座，不是声称它已经为本方案做好了几何训练。[^10]

先复现一个无交比分支、能稳定完成同场景双端点过渡的基线。短片原型可试 17 或 33 帧，但必须验证底座的时空压缩、预处理和短序列行为；官方常见配置为更长片段，不能假定任意缩短都不影响质量。

原始 Wan2.1 的 1.3B 文生视频模型与 VACE-1.3B 不是同一个任务配置，不能把前者直接称为现成单图或双图模型。项目目录名含 CamI2V，也不意味着本方案可以不改条件接口就直接套用原来的单图流程。

### 8.2 数据分为两层

**合成几何数据负责验证机制。** 渲染带窗格、接缝、栏杆和可辨标记的三维静态场景，保存真实相机、深度、三维点线身份、各帧投影和可见性。随机改变焦距、裁剪、视角、遮挡、纹理和光照。输入只给两端 RGB，真实三维与相机仅用于训练标签或评测。

**真实静态场景视频负责验证可用性。** 从建筑、室内等视频中取两端作为输入，中间帧作为训练目标；几何教师离线产生候选点线轨迹和置信度。RealEstate10K 可作为候选来源，其真实数据获取、许可和有效片段数量需要实际核查；不能把整套视频都视为可靠几何标签。相关双图新视角工作也使用该数据源。[^5]

训练、验证、测试必须按场景切分，不能让同一房间相邻片段跨集合。真实多相机照片与同一视频裁剪得到的双图，应分开报告；后者不能充分证明跨设备泛化。

### 8.3 分阶段训练

1. **匹配与对齐小实验。** 暂不接视频底座，测交比坐标能否在真实直线上正确读取对应特征。先与外观匹配、一维射影变换基线对比。
2. **源图融合版。** 冻结底座大部分权重，只训练线特征投影、源图融合、输出适配层及必要的小范围微调。目标帧仍由普通视频主干处理。
3. **目标读取版。** 增加锚点预测器和稀疏几何读取。先在可监督合成数据中训练，再加入真实伪标签；逐步减少对真实目标锚点的依赖，并在训练中使用预测锚点与匹配噪声。
4. **完整压力测试。** 加入错配、缺线、遮挡、畸变和视角变化，确认分支可以退出，不会在几何不适用时破坏底座。

训练小模块通常减少需要更新的权重和优化器状态，但视频主干的前向、激活保存及必要反向计算仍然昂贵。没有实测前，不给出“几 GB 显存即可”“只训练几小时”或固定加速百分比。

### 8.4 训练约束

主损失沿用所选底座原来的去噪或流匹配目标。辅助监督分别负责锚点位置与可见性、参考图特征对应，以及生成画面中的线结构和细节保持。

可写成：

\[
L=L_{\text{base}}+\alpha L_{\text{anchor}}+\beta L_{\text{match}}+\gamma L_{\text{image-geometry}}.
\]

权重由验证集选择，不预先宣称某个固定值最优。L_anchor 在可见帧上监督真实或高置信度伪标签；L_match 要使用独立对应点及错误位置负样本，不能把按交比自动对齐的位置全部当成真实标签。

L_image-geometry 必须作用于生成内容中可独立定位的结构，例如由冻结局部特征与真实模板得到的软匹配位置、已知合成标记的位置，而不是只比较锚点预测器自己的输出。传统硬线检测和 RANSAC 可用于离线评测，但不能不作可微处理就声称其误差可以直接端到端反传。

对真实数据，宁可先不加容易自证的交比图像损失，只保留底座损失、可靠锚点监督和架构消融。随后再验证可微测量器是否真的识别生成内容，而不是受到伪纹理欺骗。

## 9. 怎么证明交比真的有用

### 9.1 最重要的对照不是另一篇大模型，而是同底座消融

| 对照 | 它排除什么解释 |
|---|---|
| 双端点底座，无新增分支 | 基础参照 |
| 相同点线特征、相近参数量，只用外观注意力 | 排除“只是加了线检测器或更多参数” |
| 用普通线段归一化坐标代替交比 | 检验透视不变坐标是否优于沿线等比例位置 |
| 一维射影变换对齐 + 相同注意力 | 检验交比实现是否只是等价重参数化；这是必须做的强对照 |
| 只加交比相关训练损失，不改注意力 | 检验架构注入是否比仅增加监督更有用 |
| 只做源图融合 / 再加目标锚点读取 | 分离收益来自哪个模块 |
| 真实锚点 / 自动预测锚点 | 测量几何前端与目标预测器损失了多少理想收益 |
| 去掉置信度、噪声门控或空候选 | 检验错误几何下的稳健性 |

对于平面区域，再加入二维单应变换对齐基线。对于允许相机或三维估计的设置，加入极线/相机位置编码或重建再渲染方法；其额外输入、预处理时间和估计器必须单列，不混成同一个“无需几何输入”的比较。

外部方法可选择 Generative Inbetweening、NoPo3DFusion 等任务相关基线。FlashWorld 可以展示“显式三维场景”和“直接视频生成”的取舍，但输入数量与输出形态不同，不能成为唯一主基线。[^4][^5][^6]

### 9.2 测什么，不能只看交比误差

首先测前端：有效共同直线数、每线真实对应点数量、留出点转移误差、错误匹配率，以及这些线覆盖了多少图像区域。结果按场景类别和视角变化分组，不能只展示成功的建筑立面。

再测生成内容：同一标记有没有错位、窗格数量和连接关系有没有改变、直线有没有弯折、局部纹理有没有跳动、两端附近是否突然变形。交比误差只是其中一项，并且必须来自生成 RGB 中独立识别出的同名物理点。

生成器把难点全部抹掉，可能令检测器只剩几个容易匹配的点，交比均值反而变好。因此必须同时报告标记保留率、匹配覆盖率和检测失败率；缺失点不能被悄悄删掉。身份明显错误时也应记失败，而非替换成另一个交比相似的点。

由于本任务不输入精确中间相机路径，生成的合理过渡可能与真实视频采用另一条路径。不能把逐帧 PSNR/LPIPS 作为唯一结论。主评测应关注端点条件满足、结构保持、跨帧一致性和盲评；如要做严格逐帧新视角重建评测，应另设提供目标相机或真实目标锚点的受控诊断组，并与实际无相机版本分开。

测试时真正提供真实目标锚点，只能标为上界实验，不能混入主结果。强制复制输入作为首尾帧，也不能用首尾帧的高分夸大中间生成质量。

### 9.3 应该在哪些条件下拉开差距

根据机制推断，最值得测试的是：真实直线丰富、锚点清楚、视角产生明显透视压缩、两个相机焦距不同、局部遮挡但仍有共同可见锚点的场景。它不应被宣传为对人物、树林、烟雾、柔性布料同样有效。

设置普通坐标、真实交比、打乱交比三组，但打乱组只能是辅助证据。给模型错误信息导致性能下降，不足以证明正确交比优于强基线。

最关键的判断是：在**相同输入、点线前端、参数预算和训练数据**下，完整方案是否优于外观与一维射影对齐基线，且不会在无可靠直线时明显退化。

## 10. 执行顺序、停止条件与风险

以下是工作顺序，不是对完成日期或训练成本的承诺。显卡、数据准备程度和底座训练代码尚未确定，不宜给出固定 GPU 小时数。

| 阶段 | 交付物 | 进入下一阶段的依据 |
|---|---|---|
| 0：数学检查 | 不变性、逆变换和失败案例的单元测试 | 公式正确，并理解测试不能证明视频效果 |
| 1：数据可用性审核 | 一小批真实双图的点线覆盖率、误匹配率报告 | 自动方法能稳定找到足够多有用对应，而非只在人工标记图上成功 |
| 2：独立匹配原型 | 外观、普通坐标、交比、一维射影对齐的比较 | 明确收益来源与噪声敏感度 |
| 3：源图融合视频原型 | 同底座、同预算的生成消融 | 生成内容的结构保持有稳定改善 |
| 4：目标几何读取 | 自动锚点预测与置信度门控 | 相比只融合源图，新增复杂度带来可测收益 |
| 5：完整研究结果 | 压力测试、效率测量、失败案例、可复现实验 | 结论在多个随机种子和独立场景成立 |

首轮可审核约 100–200 对图片，覆盖几类计划研究的场景。预先约定最低可用线数量、对应精度和场景覆盖目标，再根据应用需求决定是否继续；不能看完结果才挑出少量成功样例作为总体证据。

三个明确的停止或收缩条件：

1. **只有人工锚点有效。** 说明主要瓶颈是对应获取。先研究点线匹配，或将应用诚实收窄到有标记的工业/建筑场景，不立即训练完整视频模型。
2. **真实目标锚点有效，自动锚点无效。** 说明目标几何预测吃掉了交比收益。保留源图融合版，或另立相机/几何辅助版本，不能把上界结果当最终能力。
3. **与一维射影对齐无区别。** 说明当前方法主要是等价实现。仍可有工程价值，但不足以声称新的几何机制；应停止“交比天然更强”的论文叙事。

主要风险不是四点计算量，而是足够可靠的物理对应、未生成帧的锚点位置、局部约束与全局场景的一致性，以及新颖性是否能超过经典射影对齐。

### 如果仍要保留单图或精确相机控制

可以在单图加指定相机轨迹的生成模型中，将交比作为线结构的辅助先验。但这时目标投影位置仍需深度、三维线假设或预测器，交比不能替代它们。该版本更接近原 CamI2V 项目的任务，却失去了“两张真实图直接验证沿线对应”的优势。

若最终想生成可编辑三维场景，则可以研究把交比记忆融入三维重建/生成网络，但应承认这改变了最终产品，也会直接面对 FlashWorld 等显式三维方法。建议先证明局部匹配与视频模块有用，再考虑这个扩展。

## 11. 入门知识：按这个顺序查

| 顺序 | 知识 | 一句话理解 | 在本方案中做什么 |
|---|---|---|---|
| 1 | 透视投影、针孔相机 | 三维物体经过相机中心投到二维图上，远近会改变大小和间距 | 理解为什么像素距离不可靠，以及交比的适用边界 |
| 2 | 射影变换、一维单应变换 | 一条线换视角后，其位置关系可写成分式形式，而不是简单缩放 | 理解三个锚点为什么够定义沿线映射 |
| 3 | 交比、射影坐标 | 用三个锚点给其余点编号，这种编号不随理想透视变化 | 为沿线特征建立跨视角位置参照 |
| 4 | 点线检测与特征匹配 | 找出两张图片里“同一处物体分别在哪里” | 解决公式使用前必须知道的对应关系 |
| 5 | RANSAC、留出验证 | 用少量点提出几何假设，再用其他点验证，排除错配 | 不让三个错误锚点强行解释整条线 |
| 6 | 三角化、重投影、三维直线拟合 | 从多张图片估计空间位置，再看它投回图片是否吻合 | 制作训练标签，分析二维假共线 |
| 7 | Attention 的 Q/K/V | 当前位置提出查询，参考位置提供索引与内容 | 明白交比惩罚加在信息读取的哪里 |
| 8 | 视频扩散、流匹配、DiT | 大模型把噪声逐步转成视频，Transformer 负责特征交互 | 提供视频生成底座 |
| 9 | Adapter、残差门控、LoRA | 不从头训练大模型，而是添加或微调少量模块 | 控制实验规模，保持原有生成能力 |
| 10 | 可见性、不确定性、消融实验 | 不确定时允许不用几何，并拆开模块检验效果来源 | 防止错误约束和错误结论 |

课程入口优先看第 18 章的交比部分，再补点线匹配和注意力。不必先学完整三维重建系统才开始第 1 阶段的数据审核。[^1]

## 12. 最终判断

这个方向有合理的物理动机，但价值应表述为：**让视频生成模型更可靠地读取已观测直线上的跨视角信息。** 它不是“不知道相机也能万能重建”的捷径。

最推荐的研究路径是：**双图静态场景过渡 → 可靠点线对应 → 三锚点交比坐标 → 源图特征融合 → 有证据后再加入目标帧几何读取。**

在真实数据覆盖率、强基线消融和目标锚点预测通过验证之前，不能承诺三维一致性、优于 FlashWorld、推理加速或论文新颖性。前述方案中的具体模块和预期收益均为设计建议；文献已证明的性质与已有任务不能作为本方案的新贡献。
