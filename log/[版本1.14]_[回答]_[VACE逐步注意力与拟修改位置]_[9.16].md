# 版本 1.14｜VACE 每次去噪时的注意力到底看什么

日期：2026-09-16。本文件区分 Wan2.1-VACE 原版已经存在的计算，和本项目**希望新增**的“运动票引导参考 Token”计算；没有修改模型或运行扩散实验。以实际发布的 [1.3B 配置](https://huggingface.co/Wan-AI/Wan2.1-VACE-1.3B/blob/main/config.json) 与 [14B 配置](https://huggingface.co/Wan-AI/Wan2.1-VACE-14B/blob/main/config.json) 为准。

## 1. 原版确实有全局视频自注意力吗

有。每个 DiT 主干块都含一轮视频 Token 自注意力，原版 `window_size=(-1,-1)` 且 `causal=False`。一条视频的有效 `[F_z,H_p,W_p]` Token 展为 `L=F_z·H_p·W_p`，每个查询 Token 的 Q 与**同一次模型前向里的所有有效视频 Token** 的 K 计算注意力分数，再对它们的 V 加权求和。位置通过 3D RoPE 进入 Q/K，Q/K 还做 RMSNorm。概念式为每头 `A_ij=softmax_j((RoPE(Q_i)·RoPE(K_j))/√d)`、`o_i=Σ_j A_ij V_j`，再经输出投影与残差门控。FlashAttention 是省内存的执行方式，没把全局关系改成“只看一个候选”。浮点下极小权重可近似零，但原版结构允许所有有效 K。[Wan Q/K/V 与 RoPE](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/model.py)、[FlashAttention 默认非因果、全局窗口](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/attention.py)

这轮自注意力看的**不是已经存在的干净首帧原 RGB 像素**，而是当前去噪状态 `x` 投影后的**整段待生成视频 latent Token**：当前时间、其它空间位置、近邻、视频第一个/最后一个潜时间位置，甚至时间上“未来”帧都在同一批查询/键/值里。它不会按时间只看过去帧。第一个/最后一个 `x` 时间位置在原版 VACE 初始步也从噪声生成；干净的条件首帧/尾帧走另一条 VACE 条件分支。对一个 `768×432×121` 的无额外参考例子，视频自注意力序列是 40176 个 Token；它不是“每个 Token 只看首帧 1296 个 Token”。[VACE 主干 patch 与展平](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vace_model.py)、[原版 pure-noise latent 与条件视频](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)

## 2. 参考帧、文本、过往扩散步分别在哪条路径

原版 VACE 将已知视频/首尾帧按 mask 编码进条件视频 latent：可见/遮挡图像 VAE 编码与 mask 通道拼接为 96 通道，经过独立的 VACE patch embedding 得到与视频时空格点对齐的条件 Token `c`。VACE 控制块先在 `c` 上运行自己的全局自注意力、文本交叉注意力和 FFN；第 0 个控制块还将当前生成 `x` 混入 `c`，控制块输出经 projection 变成 hint，**加到**主干实际配置指定的块输出。若另给 reference images，原版将其 VAE latent 前置到条件时间轴，对应生成时间位置也前置，但视频最后解码裁掉这些位置。条件图像对主干的作用是经这些 hint **间接传递**，不是主干视频自注意力自动从一个“干净参考首帧 K/V 库”读取。[VACE 条件/控制块实现](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vace_model.py)、[条件图像/mask 编码](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)

每个主干块另有视频 Token 到 **UMT5 文本 Token** 的交叉注意力；Q 来自视频 hidden，K/V 来自文本 embedding。这个文本交叉注意力也不是逐像素首帧检索。VACE 原版源码的 `clip_fea` 图像交叉拼接段落在 VACE forward 里被注释；不能把其他 Wan I2V/FLF2V 的 CLIP 图像交叉注意力当作此 VACE 模型的标准路径。[Wan 主干自注意力/文本交叉注意力](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/model.py)、[VACE forward](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vace_model.py)

前一个扩散步的 hidden/Q/K/V **没有在原版模型中作为独立 KV 缓存送进下一步**。采样器把上一步的 latent `x_{s+1}` 更新成当前步 `x_s`，模型每步重新 patchify 并重新计算主干/控制块注意力。因此当前 Token 带有之前去噪造成的信息，是通过更新后的 latent 状态，而不是逐层直接“看前一步 Attention 矩阵”。[原版采样循环](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)

## 3. 每个采样步内部按什么顺序、注意力发生几次

原版推理的默认采样步数为 50，可调；每步以当前完整 latent、当步 timestep、冻结的条件视频/mask/参考图像 latent、文本条件执行模型前向，得到 16 通道 latent 的流/噪声预测，采样器据此更新完整 latent。使用常见 `guide_scale>1` 时，同一采样步还执行一次正提示条件前向和一次负提示/无条件文本前向，预测按 CFG 加权；两次都要跑相应注意力。**VACE 视频条件并未因为负提示文本前向而消失**，两次仍传同一 `vace_context`。[原版 VACE 采样循环](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)

一次模型前向的顺序为：

1. 当前待生成 `[16,F_z,H_z,W_z]` latent 经视频 Conv3D patch embedding、展平；条件 `[96,F_z,H_z,W_z]` 经另一 Conv3D、展平；timestep 与文本各自投影。
2. **先**运行 VACE 控制块：1.3B 实际 15 块，14B 实际 8 块；每块都有 `c` 序列的自注意力+文本交叉注意力+FFN，产出一个 hint。控制第 0 块把 `x` 加入 `c` 的起点。[1.3B 控制索引](https://huggingface.co/Wan-AI/Wan2.1-VACE-1.3B/blob/main/config.json)、[14B 控制索引](https://huggingface.co/Wan-AI/Wan2.1-VACE-14B/blob/main/config.json)
3. **再**运行主干块：1.3B 30 块，14B 40 块。每块是当步扩散 timestep 调制的**视频全局自注意力 → 文本交叉注意力 → FFN**；当块索引属于实际 `vace_layers` 时，在该块**之后**加对应 VACE hint。比如 1.3B 在 0,2,…,28 注入；14B 在 0,5,…,35 注入。[VACE blocks/forward](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vace_model.py)
4. head 预测每个 patch 的 64 个 latent 输出数值，unpatchify；CFG 合并两次预测（若启用），scheduler 更新 latent。仅全部采样完成才通过 VAE decode 得到像素视频。[原版模型和采样代码](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vace_model.py)、[原版 scheduler 循环](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)

所以一个采样步、一次前向：1.3B 有 **30 轮主干视频自注意力 + 15 轮 VACE 条件自注意力**，另各有相应文本交叉注意力；14B 为 **40 + 8**。若 CFG 两次前向，这些次数翻倍。注意力头数分别 12/40，每“轮”内部每头各算自己的 Q/K/V；不能把“注意力头数”“块数”“采样步数”相乘后称为不同视频帧。

## 4. 我们具体想改哪里，原版有什么必须继续看

我们的目标是给**当前时空 Token 的某些注意力边**增加运动票支持，使它更偏重首帧（可选首+尾帧）相应的条件图像 Token；尤其可研究较后去噪步与主干较后层。这里必须先确定参考 K/V 的来源：

- 如果直接在**主干视频自注意力**的首帧时间位置加 mask/bias，数学上限制的是 `x` 中第一个**待生成/noisy**时间位置，**并不等于读取干净首帧像素**；高噪声阶段更明显。可测的主干方案是利用已注入 VACE hint 之后的特定主干层 hidden，或另建立来自条件 `c` 的**干净参考 K/V 路由**，对选中的参考位置加 logits bias/稀疏 Value 路由。
- 如果在 **VACE 控制块的自注意力**改 `c` 的时空注意力，条件图像位置已在 `c` 时间轴；但 `c` 又含与生成 `x` 相互作用、mask 和其它条件，候选需追溯真实控制层/头与参考时间索引，不能把颜色网格候选原封不动当它的 attention mask。
- 可以先在某个明确的主干层/控制层、明确的时间步只改“**到参考条件位置**”这一类边；其它边仍允许当前时刻自身、当前帧其它位置、时空近邻、整段视频中必要的全局依赖和文本条件。若把整个 self-attention 的 K/V 硬限制成首帧 Top-8，就会失去同帧结构、相邻帧连续性、新出现/遮挡物体和全局布局所需的信息。Top-8 是参考边的上限候选，不是全部注意力的唯一 K/V。

后两项是**拟实验设计**，不是 VACE 原版已在做的运动投票。现有网页仅存 Top-8/16 候选及布尔 mask，没有使用这些 mask 重算任何一层 Wan2.1-VACE attention 或 Value。要选择哪层、哪头、哪步以及 bias/mask 强度，还需要从真实 checkpoint 提取对应 Q/K/V、做 no-noise真实帧的局部测试和正常生成对照；这与“Demo0 当前不必模拟噪声”并不矛盾，Demo0 可以先只解决 Token 与像素/参考索引对应。[当前 mask 计算](../data/demo0_v11/core.py)、[当前网页读取](../data/demo0_v11/backend/server.py)
