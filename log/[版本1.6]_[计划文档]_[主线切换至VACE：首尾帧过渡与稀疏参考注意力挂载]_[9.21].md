## 2. 依据：VACE 的代码级挂载点分析（本文的实现基础）

来源：`Wan-Video/Wan2.1` 的 `wan/modules/vace_model.py`（本次实测抓取）。**这是 [版本1.6] 相对 [版本1.14] 的实质进展。**

### 2.1 插槽 A — `hints`：VACE 自带的插件接口

```python
class BaseWanAttentionBlock(WanAttentionBlock):
    def forward(self, x, hints, context_scale=1.0, **kwargs):
        x = super().forward(x, **kwargs)
        if self.block_id is not None:
            x = x + hints[self.block_id] * context_scale     # ← 外部注入点
        return x
```

- `hints` 是长度 15 的 list（`vace_layers = [0,2,4,...,28]`），主干 block 按 `block_id` 各取一个
- `context_scale` 即官方 `vace_context_scale`，是**外部标量**

### 2.2 插槽 B — 文本 cross-attn 残差（**推荐**）

`WanAttentionBlock.forward` 由三条残差串联：

```python
x = x + self.self_attn(norm1(x))            # ① 全序列自注意力（32760 token）
x = x + self.cross_attn(norm3(x), context)  # ② 文本交叉注意力  Q←主干, KV←文本
x = x + self.ffn(norm2(x))                  # ③ FFN
```

**② 的形态是"Q 来自主干、K/V 来自外部序列"，与 V² 参考注意力完全同构。** 因此新增第三条残差：

```python
x = x + self.self_attn(...)          # 已有，不动
x = x + self.cross_attn(...)         # 已有，不动
x = x + v2_ref_attn(                 # ← 新增
        q=self.norm_v2(x),           #   Q ← 主干当前 token
        ref_k, ref_v,                #   KV ← 条件支路的干净参考 token
        mask=voted_mask,             #   [L, M] 投票掩码
      ) * gate                       #   reject 时 gate=0；输出投影零初始化
x = x + self.ffn(...)                # 已有，不动
```

**不需要改自注意力，不需要空间/时间分离，不需要可命名的类。** 这是"具体挂在哪一层"的答案。

### 2.3 干净参考 K/V 天然存在

```python
def forward_vace(self, x, vace_context, seq_len, kwargs):
    c = [self.vace_patch_embedding(u.unsqueeze(0)) for u in vace_context]
    c = [u.flatten(2).transpose(1, 2) for u in c]
    c = torch.cat([...pad to seq_len...])
    hints = []
    for block in self.vace_blocks:
        c, c_skip = block(c, **new_kwargs)
        hints.append(c_skip)
    return hints
```

| 事实 | 含义 |
|---|---|
| `c` 来自 `vace_context`（96 通道首尾帧条件+mask 编码） | **不是 noisy latent**，天然干净 |
| `c` 与主干 `x` 共用同一套 `vace_patch_embedding` 网格 | token 位置一一对应，首/尾帧 token 索引可定位 |
| `c` 在每个 vace block 内逐层演化 | 每个深度都有对应深度的干净参考 |

**这解决了 [版本1.4] 在 CamI2V 上纠结的"参考只能是 noisy"难题。VACE 的插入故事比 CamI2V 更好。**

### 2.4 旁路均为零初始化

```python
if block_id == 0:
    self.before_proj = nn.Linear(dim, dim); nn.init.zeros_(...)
self.after_proj = nn.Linear(dim, dim);     nn.init.zeros_(...)
```

**VACE 官方自己就是按"零初始化旁路"范式做的**，与 [版本1.5] 的模块设计一致。

### 2.5 稀疏发生在哪一层

```text
不是把 32760² 的全局自注意力变稀疏 —— 那个完全不动
而是新增一条 L×M 的稀疏交叉注意力：

  以 480×832 / 81 帧为例
    latent        [16, 21, 60, 104]
    patch (1,2,2) → [21, 30, 52]
    L = 21×30×52 = 32760                主干 token
    首帧 = 1×30×52 = 1560 ；尾帧 = 1560
    M = 3120                            参考 token
    稠密 L×M = 102M 次相似度（fp16 约 200 MB，需分块）
    Top-K 后  = L×16 = 524K（gather 索引，极轻）
```

### 2.6 修正 [版本1.14] 的结论

[版本1.14] 的观察"每个主干块一轮全局自注意力、无空间/时间分离"**正确**，但由此推出的"无从下手"**不成立**——它只看了自注意力内部，未注意到：
1. `BaseWanAttentionBlock` 的 `hints` / `context_scale` 是现成的外部注入点
2. cross-attn 残差槽与 V² 参考注意力同构
3. 条件支路 `c` 提供干净参考

**此修正必须记入，不得静默改写 [版本1.14]。**

## 3. 相机轨迹接口的处理（决策 3）

已核查到的事实：

- VACE 官方**没有**数值相机位姿（K/RT）输入接口
- 但 VACE 的 `vace_in_dim=96` 是一个**通用控制信号接口**：`96 = 16(控制 latent) + 16(反应 latent) + 64(mask)`，官方用它支持深度图、姿态骨架、光流等多种控制模态

因此：

```text
若把 Plücker 射线渲染成"控制视频"再走 96 通道 → 属于"使用官方通用接口"
但 Plücker 渲染器 + 投影层仍需我们自己实现 → 按决策 3，判定为"需要手搓"
结论：本版本不安排相机轨迹编码器。VACE 路线默认无位姿条件。
```

**这一条对 V² 反而是好事**：没有位姿 → 极线不可用 → **只能用纯运动投票**（[版本1.5] 的臂 (c)），方法内核被完整保留。

**待办**：在服务器上核实官方是否已发布相机控制相关的 VACE 变体或接口（本机 HF 不可达，需在服务器上查）。若发现官方接口，再启动 [版本1.7] 讨论是否引入。
