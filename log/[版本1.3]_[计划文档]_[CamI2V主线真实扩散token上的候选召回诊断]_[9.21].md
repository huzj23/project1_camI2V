## 0. 本次决策

**放弃在 Demo0 的外部网格描述子上继续加码，直接把评测对象换成 CamI2V 的真实扩散 token。**

理由：

1. Demo0 v1.1 的审计结论已经明确——它的 1296 个 token 是工程自建的 RootSIFT+颜色网格，**不是任何扩散模型的内部 token**（`vace_checkpoint_used=false`）；稀疏掩码从未接入任何 Value 信息流。在它上面继续调参，无法回答本项目最核心的问题。
2. CamI2V 已在服务器 strict load 全键匹配并跑通 2/25 步推理，**是一个真实、可运行、带相机几何的扩散主干**，且它的极线注意力分支正是 V² 模块的天然插入位（见 §2）。
3. 1.16 综述指出，"把对应关系注入扩散注意力"已被 CorrAdapter、CAMEO 等覆盖；本项目可能的独特点只在"多运动假设投票 + 显式拒绝 + 验证后的稀疏参考路由"。这个独特点必须在**真实 token** 上先证明有 headroom，才值得投入。

## 2. CamI2V 主干的三个可用接口

这一节是后续全部实验的坐标系，全部已在本地克隆中逐行核对。

### 2.1 极线注意力模块（16 个）

```text
类        CameraControl.CamI2V.epipolar.Epipolar
                                                     C=320   320   640   640  1280  1280  1280
input_blocks.1,2 .2.transformer_blocks.0.epipolar
input_blocks.4,5 .2.transformer_blocks.0.epipolar    → 640
input_blocks.7,8 .2.transformer_blocks.0.epipolar    → 1280
middle_block.2  .transformer_blocks.0.epipolar       → 1280
output_blocks.3-5  .2.transformer_blocks.0.epipolar  → 1280
output_blocks.6-8  .2.transformer_blocks.0.epipolar  → 640
output_blocks.9-11 .2.transformer_blocks.0.epipolar  → 320
共 16 个，配置 attention_resolution=[8,4,2,1] → 32×32/16×16/8×8/4×4
```

`Epipolar.forward(features, sample_locs_dict, cond_frame_index, **kwargs)`：

```text
features: [B, T1, C, H, W]
attn_mask = sample_locs_dict[origin_h // H]      # 键为下采样倍率
x = rearrange(features, "B T1 C H W -> B (T1 H W) C")
context = x                                       # 全帧自注意力（only_on_cond_frame=False）
out = epipolar_attn(x, context, attn_mask)
return rearrange(out, "B (T1 H W) C -> (B H W) T1 C")
```

`EpipolarCrossAttention.forward(x, context, attn_mask)`：

```text
q = to_q(x);  context = [register_tokens(4), context]
k = to_k(context);  v = to_v(context)
attn_mask 为 bool 时用 F.pad(..., (4,0), value=True)  → register 恒可见
attn_mask 为 float 时 pad value=-0.0
out = scaled_dot_product_attention(q, k, v, attn_mask)
```

### 2.2 原始时序自注意力 `attn1`

注入点上溯一层，`new__forward_for_BasicTransformerBlock_of_TemporalTransformer`：

```python
normed_x = self.norm1(x)
if camera_condition is not None and isinstance(camera_condition, dict):
    zero_init_x = torch.zeros_like(normed_x)
    if pluker_embedding_features is not None:
        zero_init_x += self.pluker_projection(normed_x + pluker_embedding_features)
    if hasattr(self, 'epipolar'):
        zero_init_x += self.epipolar(rearrange(normed_x + pluker, '(b h w) f c -> b f c h w', ...), **camera_condition)
    if camera_condition['add_type'] == "add_to_main_branch":
        x = zero_init_x + self.attn1(normed_x, ...) + x      # ← 并行相加
x = self.attn2(self.norm2(x), context=context) + x
x = self.ff(self.norm3(x)) + x
```

**这就是 V² 模块未来要并列插入的位置**：与 `pluker_projection`、`epipolar` 同级的第四条零初始化分支。

### 2.3 相机几何侧

```text
sample_locs_dict：{下采样倍率 -> [B, T·H·W, T·H·W] bool/float mask}
由 K、相对位姿 R,t 算 F，对每个 query 点求极线，距离阈值 = downsample·√2/2
pose_encoder：Plucker [B,6,16,256,256] → PixelUnshuffle(8)=384ch → 多尺度 [320,640,1280,1280]
```

## 3. 核心待答问题

Demo0 想问但答不了的问题，原样搬到真实 token 上：

| 编号 | 问题 | 对应 Demo0 的问题 |
|---|---|---|
| Q1 | CamI2V 内部 token 的 Q/K，在低噪声去噪步能否找回正确参考 token？ | "正确候选是否进入 Top-L" |
| Q2 | 真实 QK 的 Top-K 里，正确参考的排名与权重分布如何？有无 headroom？ | "投票是否有用" |
| Q3 | 极线 mask 之外，模型自身的时序 attn1 把注意力放在哪里？ | 新增：真实模型的基线行为 |
| Q4 | 这些结论在层/尺度/去噪步/注意力头上是否一致？ | 1.16 要求的 early/middle/late 扫描 |
| Q5 | 真实稀疏 Value 路由改动的信息流，能否被量化？ | "稀疏掩码是否可用" |

**关键区别**：Demo0 问的是外部描述子；这里问的是 CamI2V 每步前向里真实算出来的 Q/K/V。

## 4. 为什么不能直接照搬 Demo0

| 维度 | Demo0 | CamI2V 真实 token |
|---|---|---|
| 时间索引 | 每原始帧 1 个描述子层 | 16 帧 latent，逐帧对应，无时间压缩（2D VAE） |
| 空间索引 | 48×27 @768×432，stride 16 | 32×32 / 16×16 / 8×8 / 4×4 多尺度 |
| 特征 | RootSIFT + 颜色，手工 | U-Net 内部 hidden，随层/步变化 |
| 相似度 | 余弦 | 真实 Q·K/√d，多头 |
| 当前帧来源 | **真实视频帧** | **当轮生成的 noisy latent** |
| 时间先验 | 真实相邻帧 DIS 流 | 生成时不存在，必须改为从生成 latent 推断 |
| 几何 | 无（相机轨迹只用于选窗） | 有真实 K/RT，可算极线与重投影 |

**最本质的变化**：生成时"当前帧真实画面"不存在。Demo0 里那个"端点自匹配权重=1"的免费锚点，在 CamI2V 里没有对应物。**这是从验证性实验进入真实注入的最大接口断裂**，必须在 S1 就正视。

## 5. 诊断阶梯

三个阶段，逐级加真值强度。每级独立报告，通过门槛才进入下一级。

### S1 — 探针与结构验证（无真值，纯只读）

**目的**：在真实 25 步推理中把 16 个 epipolar 模块与 16 个时序 attn1 的输入/输出接出来，确认抓取链路可用，并记录真实形状、dtype、显存代价与耗时分部。

**方法**：

```text
新增 /data/raw/huzijian/project1_camI2V/code/CamI2V/codex_probe_attn.py   ← R5：不改上游
  1. 复用 codex_smoke_infer.py 的 build_batch / load_model
  2. 用 forward hook 给 16 个 Epipolar 与 16 个 attn1 注册探针
  3. 可选地在指定去噪步（默认 {0, 5, 12, 20, 24}）记录：
       - epipolar: 输入 normed_x(+pluker)、q/k/v、attn_mask、输出
       - attn1   : 输入 normed_x、q/k/v、输出
  4. 只落盘统计量与小样本，不落盘完整 [B, L, L] 矩阵
       - 每模块：shape / dtype / 极线 mask 每行可见数分布（min/median/max）
       - 选定 token 的 Top-16 index+score
  5. 产物写入 /data/raw/huzijian/project1_camI2V/tmp_local/s1_probe/<run_id>/
```

**产物**：`s1_probe/` 下的 `shapes.json`、`mask_stats.json`、`topk_sample.npz`、`timing.json`、`probe.log`

**完成条件**：能对任一 epipolar 模块的任一 query token，给出它在同一尺度上的 Top-16 K 索引与分数，并说明该 token 的 2D 网格坐标。

**不做**：不训练、不改上游、不改推理参数、不落盘完整注意力矩阵。

### S2 — 几何真值对照（弱真值：极线带）

**目的**：在没有深度的条件下，用已知 K/RT 给出"正确参考必须落在哪条极线附近"，检验真实 QK Top-K 是否落在几何允许带内，以及**带内的精细排序**与几何距离是否相关。

**方法**：

- 用 `sample_locs_dict` 已有的极线 mask 作为"带宽"定义，但**不**把它当成正确答案，只当成约束边界。
- 对每个 query token 的 Top-K，计算它到该 query 极线的像素距离，统计分布。
- 定义并报告：
  - `in_band_rate`：Top-K 中落在极线带内的比例（这是 mask 强制的结果，预期接近 1，作为链路自检）
  - `band_occupancy`：极线带内被 Top-K 覆盖的比例
  - `rank_entropy`：Top-K 分数熵，判断是否退化为均匀
- 对**无 mask** 的 attn1 做同样统计，观察原始时序注意力是否自发靠近极线（这才是真正有信息量的对照）。

**注意**：S2 **不能**回答"是否正确对应"，只能回答"是否在几何允许范围内、以及带内是否给出有区分度的排序"。必须按 R7 标注为 `provisional`。

### S3 — 强真值对照（MC 重导出深度图）

**目的**：拿到逐像素真值对应，做真正的 PCK@K / Hit@K。

**前置（需人类执行）**：在 MC 客户端用 Flashback 重新导出至少一段短片，**打开 Depth Map**，规格：

```text
PNG Sequence，1280×720，60fps，Projection=Perspective，SSAA 关闭，No GUI 开
Depth Map: 开启
轨迹 CSV 与帧一一对应（validate_mc_capture.ps1 校验）
```

**方法**：

```text
camera K/RT + depth  →  对 frame 0 的每个像素求它在 frame t 的重投影位置
→ 得到几何真值对应（含遮挡判定：重投影后深度不连续则标为不可见）
→ 与 CamI2V 真实 QK Top-K 比对，报告 Hit@1/8/16、MRR，按可见/遮挡/低纹理/重复纹理分层
```

**通过门槛（建议，执行前冻结）**：

1. 首帧可见且纹理可辨的人工/几何查询中，主设置 Hit@8 ≥ 0.80；
2. 低噪声后期步的 MRR 显著高于高噪声早期步（证明"后期注入"假设成立）；
3. 极线带内排序 MRR 明显优于随机（证明模型确实在做带内区分，而非依赖 mask 兜底）；
4. 遮挡区域可被识别（拒绝机制有依据）。

**任一门槛不通过即停止注入路线**，回到 1.0 计划的停止条件判断，不得用更长视频或更大模型掩盖。

## 9. 已知不确定与风险

| 风险 | 说明 |
|---|---|
| CamI2V 的时间建模 | 2D VAE 逐帧编码，无时间压缩，16 帧 latent 与 16 原始帧一一对应；但 25 步 DDIM 中每步 latent 都是 noisy 的，早期步的 Q/K 可能完全不可用 |
| 极线 mask 的作用 | mask 已把注意力限制在极线带内，QK 的"排序能力"可能被 mask 掩盖；S2 必须在 **attn1（无 mask）** 上做对照才有信息量 |
| 显存 | 16 尺度 × 5 步 × 全量 QKV 会爆显存；S1 只落盘统计量与小样本 |
| GPU 共享 | gpu0/1/3 有他人作业，只能等或只用 gpu2 |
| 真值缺失 | 无深度时 S2 只是弱真值；真正的结论必须等 S3 |
| 端点锚点消失 | Demo0 的"首帧自匹配=1"在生成时不存在，S1–S3 必须改用几何真值而非端点自匹配 |
