## 1. 本次修订的核心结论

版本 1.0 的现有实现不能用于判断运动投票思想是否有效。它实际使用 ImageNet ResNet-18 特征、固定首帧长距离匹配、DIS 弱光流监督和每帧独立的四槽二维位移聚类；这些条件与计划验证的“在 VACE 扩散步骤中，用运动投票限制当前 token 对首帧或首尾帧 token 的关注范围”并不等价。

版本 1.1 不改变总任务，重新把 Demo0 收缩为一个明确的验证性实验：

1. 先确认当前时刻 token 的正确参考位置能否进入首帧或首尾帧候选列表；
2. 再确认运动投票能否在候选列表内部提高正确候选的排名和权重；
3. 最后确认投票结果能否形成稳定、稀疏、可用于扩散模型注意力的参考 token 掩码；
4. 只有上述结论成立，才进入完整视频生成模型的集成实验。

## 2. 总任务边界

### 2.1 主任务 A：首帧条件视频生成

输入：

- 一张视频首帧；
- 常规视频生成条件；
- 后续可选的相机轨迹条件。

输出：

- 由首帧生成的后续视频。

V² 模块在每个扩散去噪步骤内部工作。对当前视频 token，只允许它读取首帧中经运动投票和验证后保留的少量参考 token。模块重点在低噪声、靠后的去噪步骤发挥作用，因为此时当前 token 已包含较稳定的结构和外观信息。

主任务 A 仍是当前首要目标，不因 Demo0 引入尾帧而自动改变。

### 2.2 可选任务 B：首尾帧条件过渡视频生成

输入：

- 视频首帧；
- 视频尾帧；
- 常规视频生成条件；
- 后续可选的相机轨迹条件。

输出：

- 首尾帧之间的过渡视频。

在任务 B 中，参考 token 库由首帧和尾帧共同组成。当前 token 可以从两个端点中选择少量候选，以覆盖首帧不可见但尾帧可见的区域。

任务 B 是一个独立、合法的最终任务设定，不作为任务 A 的隐式额外输入。是否转向或同时保留任务 B，要由 Demo0 的首帧模式与首尾模式对照结果决定。

## 3. Demo0 的准确定位

Demo0 不负责生成最终视频，也不负责证明完整 VACE 的生成质量。它只验证以下链路：

```text
真实视频当前帧 / 单个受控扩散步骤中的当前 token
    → 从首帧或首尾帧 token 中检索 Top-L 候选
    → 候选对应关系提出运动意见
    → 对共享运动状态进行投票和验证
    → 得到每个当前 token 的稀疏参考 token 掩码
    → 交互查询和全视频运动集合可视化
```

Demo0 必须回答四个相互独立的问题：

1. **候选是否存在**：正确参考区域是否进入 Top-L；
2. **投票是否有用**：正确候选是否在投票后得到更高排名或权重；
3. **时间上是否稳定**：运动集合能否在连续帧中保持一致，而非逐帧随机换色；
4. **稀疏掩码是否可用**：在保留正确参考信息的同时，能否显著减少当前 token 可读取的参考 token 数量。

颜色 overlay 只是检查这些问题的手段，不是算法目标本身。

## 4. 对版本 1.0 现有结果的审计

### 4.1 实际使用的不是 VACE token

现有实现使用冻结的 ImageNet ResNet-18 `layer3` 特征，输入为 512×288，得到 32×18 个 stride-16 token，并将 256 维特征随机投影为 64 维。

这套特征可以作为外部基线，但不能回答以下问题：

- VACE 内部 token 是否具有可用的跨帧对应关系；
- VACE 某个扩散步骤的 Q/K 是否能找回正确参考 token；
- 稀疏候选掩码能否真正限制 VACE 的 Value 信息流。

### 4.2 名义 token 方框与真实感受野严重不一致

界面显示的 token 方框为 16×16，但 ResNet-18 `layer3` 单个位置的理论感受野约为 211×211。用户看似选中了窗户或墙面的一小块，实际匹配特征可能同时包含窗户、墙、屋顶和天空。

因此，版本 1.0 的小方框热力图不能被解释为精确的 token—像素对应。

### 4.3 Top-8 候选生成已经失败

现有流程先用全局余弦相似度产生 Top-8，再由运动投票在这八个候选内部重新加权。正确候选一旦不在 Top-8 中，投票无法恢复它。

“简单平动透视关系”的现有弱代理结果中：

- Top-8 Recall 为 0.5317；
- B5 的 PCK@1 为 0.3171；
- B5 的代理总分为 0.3845，低于等参数 B4 的 0.4648。

所以该视频的失败首先发生在候选生成阶段，而不能单独归因于运动聚类。

### 4.4 DIS 长距离弱监督基本失效

现有训练直接计算当前帧到整段视频第 0 帧的 DIS 双向光流。在“简单平动透视关系”的测试集中，7488 个 token 只有 205 个被弱代理判定为有效，有效比例约为 2.7%；B5 最终只接受约 7.7% 的 token。

这导致当前结果主要表现为大面积拒绝、灰暗和碎片化，而不是精细的遮挡判断。现有 DIS 指标不得继续作为 Demo0 的主要训练标签或结论依据。

### 4.5 当前运动视频没有追踪具体 token 或物体

版本 1.0 每帧独立对全局候选位移做 K=4 的 soft k-means，再按相邻帧槽中心距离匹配颜色。所谓时间信息只约束四个全局槽中心，没有维护：

- 单个 token 的跨帧轨迹；
- 某个运动集合的成员连续性；
- 集合的出现、消失、分裂与合并；
- 遮挡前后的身份恢复。

因此现有 overlay 表示“每帧重新得到的四类位移”，不能表示“同一物体或表面被持续跟踪”。

### 4.6 四个全局恒定位移不足以解释透视缩放

视频没有显著旋转或环绕，也没有多个独立物体造成的显著光流差异；主要困难是透视缩放、深度差异和遮挡。

在这种条件下，同一物体不同位置的二维位移仍可能因透视缩放而不同。强制整幅图像服从四个恒定 `(dx,dy)`，会把一个物体切成多个颜色，也会把不同但位移接近的区域放入同一槽。

这说明需要修订“运动状态”的参数化，但不意味着改做深度估计，也不改变运动投票目标。

### 4.7 数据与可视化进一步放大了失败

- “简单平动透视关系”长 720 帧、12 秒，却始终只与第 0 帧匹配；后半段包含大量出画、新出现和遮挡区域。
- “非对称建筑平动”长 882 帧、14.7 秒，路径包含出去后返回；首尾视角接近，使结尾匹配指标虚高，不能证明中段追踪有效。
- 简单视频存在大面积近似纯青色天空。纯色区域不可定位，却在现有算法中以与其他 token 相同的权重参与全局投票。
- 当前热力图按每个查询单独归一化，即使所有候选都很差，也必然出现红色“高响应”。
- 候选框没有清楚编码真实权重；被拒绝和低置信区域在全视频 overlay 中大量变灰、变暗。

### 4.8 版本 1.0 的有效结论

当前只能得出以下结论：

> 版本 1.0 实现失败，尚未真正检验 VACE token 上的运动投票稀疏注意力。

不能据此断言运动投票思想有效，也不能据此断言它承担不了目标任务。

## 5. 版本 1.1 的总体实验结构

版本 1.1 分成两条逐步衔接、但结果独立报告的验证路径。

### 5.1 D0-Real：真实视频直接验证

目的：先消除视频生成误差，验证在真实当前帧存在的情况下，候选匹配、运动投票、时间一致性和可视化是否能工作。

输入当前帧是真实视频帧。它在最终生成任务中不可用，但在 Demo0 中可作为受控实验输入，以隔离“生成失败”和“投票失败”。

D0-Real 不声称已经模拟完整扩散过程。

### 5.2 D0-Step：冻结 VACE 的单步验证

目的：在不训练完整生成模型的条件下，模拟一个真实的 VACE 去噪步骤。

流程：

1. 用 VACE VAE 编码真实短视频，得到干净视频 latent；
2. 按 VACE 实际 scheduler 向 latent 加入指定噪声；
3. 运行冻结 VACE 的一次去噪网络前向；
4. 在选定层记录当前视频 token 与首帧/尾帧参考 token 的 hidden、Q、K、V；
5. 用真实 QK 或明确记录的轻量投影产生候选；
6. 用运动投票产生稀疏掩码，检查哪些参考 Value token 被允许进入当前 token。

扩散步骤按实际噪声强度记录，避免“第几步”因 scheduler 方向不同产生歧义。主要观察低噪声、靠后的去噪步骤，同时保留中噪声和高噪声作为对照。

## 6. 数据修订方案

### 6.1 先复用现有录屏，不立即重录全部数据

从现有视频截取多个短窗口。初始候选为 1–3 秒窗口，但最终不以固定秒数决定，而以视觉可见重叠为准。

每个窗口满足：

- 相机方向基本固定；
- 相机平移连续、无突然跳变；
- 首帧仍覆盖窗口内大部分主要建筑区域；
- 同时保留一定透视缩放、深度差异和遮挡，不能短到几乎零运动；
- 非对称建筑视频的去程和回程必须拆开，不能跨越运动反向点。

短窗口只用于验证局部对应机制，不等价于已经解决长视频生成。长时程能力在 Demo0 成立后另行验证。

### 6.2 首帧与首尾帧模式

每个短窗口固定运行两种模式：

- `F`：仅使用窗口首帧作为参考；
- `FL`：使用窗口首帧和尾帧作为联合参考库。

两种模式使用相同的当前帧、token 提取方式和评价点，分别保存结果，不能混合指标。

### 6.3 天空与低纹理区域

- 不再把天空替换为更纯、更统一的颜色；
- 保留原始视频画面，保证可视化真实；
- 天空、纯色和其他低纹理 token 默认不作为运动假设的投票者；
- 它们仍可作为查询 token，但允许输出低置信度或“无可靠对应”；
- 后续如有语义/深度/渲染掩码，只作为更强评价或辅助条件，不作为版本 1.1 首轮实验的前置依赖。

### 6.4 相机轨迹的使用边界

版本 1.1 首轮暂不通过相机轨迹反算真实物体运动，也不将几何重投影直接加入投票得分。

相机轨迹先只用于：

- 检查帧与轨迹同步；
- 定位路径转折和异常；
- 辅助选择短窗口；
- 记录实验数据，供后续真值阶段复用。

## 7. Token 与候选生成

### 7.1 主实验必须使用真实 VACE token

至少记录以下候选表示：

1. VACE VAE latent token；
2. VACE DiT 若干早期、中期和后期层的 hidden token；
3. 对应注意力层的实际 Q/K；
4. 被稀疏路由的实际参考 V。

每个结果必须保存：

- VACE 模型版本与权重标识；
- VAE 和 patch embedding 的空间、时间下采样比例；
- token 网格尺寸；
- 层号和注意力头；
- scheduler、噪声强度和去噪步骤；
- token 名义像素范围及其解释限制。

ResNet-18 结果只保留为 `external_baseline`，不得再作为 Demo0 主结果。

### 7.2 候选参考库

设视频时间为 `τ`，扩散步骤为 `s`，当前 token 为 `X[s,τ,j]`。

首帧模式参考库：

```text
R_F = {首帧所有参考 token}
```

首尾模式参考库：

```text
R_FL = {首帧所有参考 token} ∪ {尾帧所有参考 token}
```

原始候选分数：

```text
S[s,τ,j,i] = Q(X[s,τ,j]) · K(R_i) / sqrt(d)
```

每个当前 token 在整个参考库上统一保留 Top-L。首尾模式中的 `L=8` 表示首帧和尾帧合计八个候选，不强制分成 4+4；同时保留 `L=16` 作为候选召回对照。

候选记录必须包含：

- 参考端点来源：首帧或尾帧；
- 参考 token id 和二维网格位置；
- 原始 QK 分数；
- 候选间距、排名、margin 和熵；
- 投票前权重；
- 运动假设归属；
- 投票验证后权重；
- 是否被拒绝。

### 7.3 候选质量先于投票训练

在候选 Hit@L 达到预先设定的最低门槛之前，不训练复杂验证器，不通过增加槽数掩盖候选缺失。

如果正确候选不在 Top-L 中，应优先检查：

- VACE 层和注意力头是否合适；
- 低噪声与无噪声 token 是否仍不可定位；
- token 网格是否过粗；
- Q/K 是否需要轻量、受控的匹配投影；
- 是否存在尺度变化或重复纹理导致的候选混淆。

## 8. 运动投票算法

### 8.1 不改变运动投票的核心含义

每个当前—参考候选对仍然提出一个运动意见。投票结果用于判断哪些参考 token 与当前 token 具有相容的运动状态，并形成稀疏注意力掩码。

“相同运动状态”表示较强的邻近深度或同一刚性表面线索，因此可能对应同一物体，但它不是语义实例标签。两个不同物体可能具有相似运动，同一物体也可能因透视而具有略有不同的二维位移。

该限制不妨碍其作为注意力先验使用，但禁止把运动槽颜色直接宣称为物体分割真值。

### 8.2 两类运动假设

版本 1.1 固定比较：

#### H0：二维恒定位移基线

```text
p_current ≈ p_reference + (dx, dy)
```

该模型保留版本 1.0 的基本假设，用作最简对照。

#### H1：无旋转的局部平移—尺度假设

```text
p_current ≈ scale × p_reference + (dx, dy)
```

H1 允许同一运动集合中出现由透视缩放带来的位置相关位移，但不引入旋转、相机几何反算或显式深度槽。它仍然属于候选运动投票，只是运动状态的参数化更符合当前数据。

### 8.3 投票权重

候选投票至少考虑：

- 原始 QK 相似度；
- 候选分数 margin 和熵；
- 与运动假设的残差；
- 当前 token 邻域的边缘感知空间支持；
- 相邻帧轨迹与槽归属连续性；
- 低纹理、天空和重复纹理的不确定性；
- 首帧/尾帧可用性和拒绝概率。

低纹理 token 可以被查询，但默认不以高权重影响全局运动假设。

### 8.4 真正的跨帧一致性

版本 1.1 不再只通过相邻帧槽中心的 Hungarian 匹配稳定颜色。必须显式维护：

- token 或局部区域的相邻帧匹配；
- 运动槽参数随视频时间的平滑变化；
- token 对运动槽的归属连续性；
- 遮挡时的消失和重新出现；
- 槽的新增、终止、分裂和合并记录。

可以使用相邻帧小位移跟踪作为时间验证信号，但它只用于验证连续性，不替代首帧/尾帧参考候选，也不得作为 V² 的隐藏输入而不披露。

### 8.5 输出稀疏注意力掩码

对扩散步骤 `s`、视频时刻 `τ`、当前 token `j` 和参考 token `i`，输出：

```text
M[s,τ,j,i] ∈ [0,1]
```

只有 Top-L 且通过运动验证的候选具有非零值。扩散模型中的参考注意力写为：

```text
A[s,τ,j,:] = softmax(QK / sqrt(d) + log(M + ε))
Y[s,τ,j]   = Σ_i A[s,τ,j,i] · V(R_i)
```

非候选位置等价于被掩蔽，不允许搬运参考 Value 信息。

后期门控 `g_s` 可以更强，但 Demo0 必须先分别记录掩码本身和路由结果，不能只展示最终颜色。

## 9. 可视化系统

### 9.1 交互页面布局

主视觉区固定为：

```text
左：窗口首帧       中：当前帧，可点击 token       右：窗口尾帧
```

首帧模式下，右侧尾帧仍可显示，但明确标记为“不参与候选”；首尾模式下，两端共同参与候选。

控制项至少包括：

- 视频与短窗口；
- F / FL 模式；
- 视频时间进度条；
- 当前 token 点击选择和 token id；
- VACE 层与注意力头；
- 扩散噪声强度/步骤；
- Top-L 数量；
- 原始 QK / 投票后权重切换；
- H0 / H1 运动假设切换；
- 候选框、热力图、运动槽、置信度和拒绝图层开关。

### 9.2 当前 token 与候选显示

点击当前帧 token 后：

- 当前 token 用高对比边框和半透明填充高亮；
- 首尾两张图合计标出 Top-L 候选；
- 候选编号从 1 到 L 全局排序；
- 首帧和尾帧候选使用不同形状或边框样式；
- 框的粗细、透明度或外圈直接编码候选权重；
- 显示当前 token 与每个候选的局部放大图；
- 明确显示原始分数、投票后分数、所属运动槽和拒绝原因。

### 9.3 热力图标定

禁止只按单个查询的最小值和最大值或百分位进行无说明归一化。热力图应提供：

- 默认关闭的 dense 热力图开关；
- 同一模型层和噪声等级下固定的标尺；
- 原始 QK 与投票后掩码两张独立热力图；
- 数字候选框始终可见，不被彩色 overlay 淹没；
- 当最高分本身也很低时，明确显示“整体低置信度”，不能仍绘制成强红色。

### 9.4 全视频运动 overlay

至少提供四种可切换 overlay：

1. 运动槽颜色；
2. 参考端点来源：首帧、尾帧或拒绝；
3. 置信度；
4. 预测二维运动箭头或轨迹。

运动槽颜色在连续帧中必须绑定到持续运动集合，而不是仅按每帧槽中心重新排序。低置信度与拒绝区域使用网纹、边框或单独图层表达，避免整幅画面被统一压暗。

## 10. 人工核验与辅助参考

### 10.1 首轮人工核验集

在每个短窗口中选择若干代表帧和查询 token，覆盖：

- 唯一纹理区域；
- 重复墙面或重复方块；
- 屋檐、窗框和建筑角点；
- 不同深度的结构；
- 遮挡边缘；
- 首帧不可见、尾帧可见区域；
- 两端都不可见区域；
- 天空和其他低纹理区域。

人工标注不要求像素级光流，但至少记录：

- 正确物理区域在首帧是否可见；
- 在尾帧是否可见；
- Top-L 中哪些候选属于正确物理区域；
- 查询是否应被拒绝；
- 运动槽在连续帧中是否保持合理一致。

### 10.2 相邻帧跟踪参考

可以另外计算相邻帧小位移的光流或点跟踪，并逐帧链到首帧/尾帧，作为人工检查的辅助参考。它必须满足：

- 不直接进入主候选分数；
- 不作为未披露的投票输入；
- 单独标记为 `auxiliary_track_reference`；
- 只帮助判断候选是否大致落在同一物理区域。

版本 1.1 不再使用“当前帧直接到长距离首帧的 DIS 光流”训练主验证器。

## 11. 实验矩阵

### 11.1 Token 表示对照

| 编号 | 表示 | 用途 |
|---|---|---|
| E0 | 版本 1.0 ResNet-18 layer3 | 失败基线，仅供回顾 |
| E1 | VACE VAE 干净 latent token | 检查编码空间中的基础可匹配性 |
| E2 | 冻结 VACE、无噪声真实视频 hidden/QK | 检查网络内部 token 对应 |

| E4 | 冻结 VACE、中噪声步骤 | 噪声退化对照 |
| E5 | 冻结 VACE、高噪声步骤 | 能力边界对照 |

### 11.2 候选与投票对照

| 编号 | 方法 | 验证问题 |
|---|---|---|
| P0 | 原始 VACE QK Top-L | 正确候选是否存在 |
| P1 | P0 + H0 恒定位移投票 | 最简运动投票是否有效 |
| P2 | P0 + H1 平移—尺度投票 | 透视缩放参数化是否必要 |
| P3 | P2 + 边缘感知空间支持 | 空间一致性是否提高正确候选权重 |
| P4 | P3 + 真正的多帧时间一致性 | 是否减少槽闪烁和错误切换 |
| P5 | P4 + 拒绝槽 + 稀疏 Value 掩码 | 完整 Demo0 方法 |

所有 P0–P5 均在 F 和 FL 两种参考模式下运行。`L=8` 为主设置，`L=16` 用于判断失败是否来自候选容量不足。

## 12. 评价指标

版本 1.1 在人工或可靠辅助标签建立之前，不再计算误导性的单一综合总分。先分别报告原始指标。

### 12.1 候选阶段

- `Hit@1 / Hit@8 / Hit@16`：正确物理区域是否进入候选；
- MRR：第一个正确候选的倒数排名；
- 候选 margin 与熵；
- F 模式中按“首帧可见/不可见”分组的召回；
- FL 模式中按“仅首帧可见/仅尾帧可见/两端可见/两端不可见”分组的召回。

### 12.2 投票阶段

- 正确候选投票前后的排名变化；
- 正确候选获得的总权重变化；
- 错误重复纹理候选的权重下降；
- 拒绝 Precision / Recall；
- 平均每个当前 token 保留的参考 token 数量；
- 稀疏率与候选覆盖率。

### 12.3 时间与可视化阶段

- 相邻帧槽标签闪烁率；
- 人工选定物体/表面的运动集合持续率；
- 遮挡前后槽身份恢复情况；
- 错误跨边界合并率；
- F 与 FL 的可见区域覆盖差异。

### 12.4 初始建议门槛

正式运行前冻结以下首轮建议门槛：

1. 在首帧可见且具有可辨识纹理的人工查询 token 中，主设置 Hit@8 不低于 80%；
2. 投票后 MRR 或正确候选权重相对 P0 有稳定提升，而不是只减少覆盖率；
3. P5 必须优于 P3，证明时间一致性与拒绝机制不是纯粹的事后上色；
4. FL 必须在“首帧不可见、尾帧可见”子集明显提高候选覆盖，同时不能明显损害“两端都可见”子集；
5. 全视频 overlay 中，同一建筑表面或局部结构不能出现持续高频随机换色；
6. 稀疏 Value 路由结果必须和只做事后热力图的结果拉开差异。

门槛可在首轮人工标注量确定后调整一次，但调整原因必须写入新版本记录，不能根据最终结果反复修改。

## 13. 诊断决策树

```text
正确候选不在 Top-L
    → 检查 VACE 层/头、噪声、token 尺度和候选表示

正确候选在 Top-L，但投票后被压低
    → 投票假设、空间支持或验证器有问题

单帧候选正确，但全视频颜色乱跳
    → 跨帧轨迹和槽身份维护有问题

F 失败、FL 明显成功
    → 首帧覆盖不足；任务 B 值得进入后续生成验证

F 与 FL 都失败
    → 尾帧不能解决问题，应先修复 token 候选和投票

候选与投票均有效，但稀疏 Value 路由没有收益
    → 运动先验成立，但注入位置、门控或信息流设计有问题
```

## 15. 实施顺序

### D0.1 冻结并归档版本 1.0

- 保留当前结果作为失败基线；
- 不覆盖现有 run；
- 在查看器中明确标为 `ResNet/DIS provisional legacy`；
- 删除任何可能被误解为 VACE 扩散步结论的描述。

完成条件：版本 1.0 结果可以复查，但不会与版本 1.1 主结果混淆。

### D0.2 建立短窗口数据层

- 从现有两段录屏中划分 1–3 秒候选窗口；
- 拆分非对称视频的去程和回程；
- 保存每个窗口的首帧、尾帧、帧范围和轨迹摘要；
- 人工确认主要物体在窗口中的可见覆盖。

完成条件：至少得到一个简单窗口、一个多深度窗口和一个含遮挡窗口。

### D0.3 先重做三栏交互查看器

- 左首帧、中当前帧、右尾帧；
- 支持 F / FL 切换；
- 支持统一 Top-8 候选；
- 修正热力图标尺和候选权重显示；
- 增加候选局部放大与人工标注入口。

完成条件：即使不运行投票，也能清楚判断任一查询 token 的正确候选是否进入 Top-8。

### D0.4 接入冻结 VACE token

- 跑通 VAE 干净 latent；
- 跑通冻结 VACE 无噪声前向；
- 记录指定层/头的 Q/K/V；
- 验证 token 网格到视频像素区域的映射；
- 输出 E1–E3 的候选对照。

完成条件：查看器展示的候选来自真实 VACE token，并可追溯到具体层、头和噪声强度。

### D0.5 建立人工核验集

- 在三类短窗口中标注代表查询；
- 记录首/尾可见性和正确候选区域；
- 冻结第一版核验集；
- 计算 P0 候选指标。

完成条件：可以明确区分“候选缺失”和“投票筛错”。

### D0.6 实现并比较 H0/H1 投票

- 实现恒定位移投票；
- 实现无旋转的平移—尺度投票；
- 加入低纹理投票抑制；
- 加入边缘感知空间支持；
- 输出 P1–P3 对照。

完成条件：能够回答透视缩放是否是当前聚类破碎的主要原因。

### D0.7 实现多帧一致性和稀疏掩码

- 建立相邻帧 token/局部区域轨迹；
- 维护槽参数和成员的跨帧连续性；
- 处理遮挡、消失和重新出现；
- 生成 P4/P5 与完整等长 overlay；
- 保存实际稀疏参考掩码。

完成条件：运动视频可以观察同一表面或局部结构的连续运动全过程，而不是逐帧独立上色。

### D0.8 扩散噪声与注入前验证

- 运行低、中、高噪声单步实验；
- 重点检查低噪声后期步骤；
- 对比原始 QK、投票后掩码和实际 Value 路由；
- 检查后期门控增强是否有依据。

完成条件：明确哪些 VACE 层和噪声范围适合注入 V²。

### D0.9 决策主任务走向

根据 F 与 FL 的独立结果决定：

- F 成立：继续首帧 I2V 主任务；
- F 有限而 FL 显著成立：保留首帧任务，同时把双端点过渡列为正式候选任务；
- 两者都不成立：停止集成扩散模型，继续修复候选或重新评估运动投票假设；
- 两者都成立：后续分别实现首帧生成与首尾过渡，不混合其输入条件和指标。

## 16. 版本 1.1 暂不开展的工作

- 不用相机轨迹反算物体真实运动；
- 不把深度槽替代运动投票；
- 不训练完整 VACE 视频生成模型；
- 不将尾帧偷偷加入首帧任务；
- 不用长距离 DIS 光流训练主验证器；
- 不把运动槽颜色解释成语义物体分割；
- 不通过更长视频、更大模型或更多槽掩盖候选失败；
- 不在候选质量尚未成立时追求单一综合总分。

## 17. 版本变更摘要

相对版本 1.0，版本 1.1 的主要变化为：

1. 重新锁定首帧 I2V 主任务，并将首尾帧过渡定义为独立可选任务；
2. 将 Demo0 明确拆成真实视频验证和冻结 VACE 单步验证；
3. 主特征由 ResNet 改为真实 VACE VAE/DiT/QKV token；
4. 长视频固定首帧匹配改为短窗口 F/FL 对照；
5. 停用长距离 DIS 作为主训练标签；
6. 先验证 Top-L 候选，再验证运动投票；
7. 在恒定位移之外增加无旋转的平移—尺度运动假设；
8. 将时间一致性从“槽中心换色”升级为 token/区域轨迹与成员连续性；
9. 三栏展示首帧、当前帧和尾帧，并统一显示首尾合计 Top-L；
10. 将最终输出明确为可注入扩散注意力的稀疏参考 token 掩码。
