# 版本 1.11｜VACE 与当前 Demo0 Token 编码逐项核对

日期：2026-09-16。本文的“VACE”特指 **Wan2.1-VACE 原版**；将官方 1.3B 配置作为尺寸计算的主例，并同时给出 14B 的差异。当前 Demo0 根本没有加载任一 VACE checkpoint，因此当前运行**没有选定 1.3B 或 14B**。这里使用的参数来自 [1.3B 实际发布配置](https://huggingface.co/Wan-AI/Wan2.1-VACE-1.3B/blob/main/config.json)、[14B 实际发布配置](https://huggingface.co/Wan-AI/Wan2.1-VACE-14B/blob/main/config.json)，不是根据名称猜测。

## 1. 标准、输入与完整路径

| 项目 | VACE-1.3B | VACE-14B | 当前 Demo0 |
|---|---:|---:|---:|
| 名义模型规模 | 1.3B | 14B | 没有模型参数 |
| DiT 隐藏维 | 1536 | 5120 | 265 维手工描述子 |
| DiT 主干块数/注意力头数 | 30 / 12 | 40 / 40 | 无 DiT |
| VACE 控制块实际 checkpoint 配置 | 15，索引 0,2,…,28 | 8，索引 0,5,…,35 | 无控制块 |
| VAE 输出通道 | 16 | 16 | 未运行 VAE |
| 额外 VACE 条件输入通道 | 96 | 96 | 无 |

RGB 视频进入 VAE 时的逻辑形状是 `[B,3,F,H,W]`，官方原版按 `[-1,1]` 归一化，通道为 RGB，不处理音频。文本提示另由 UMT5 编码；它不是混在 3 通道视频里。VACE 可接条件视频、mask、参考图像与文本；不同条件如何进入网络见第 5 节。入口并不是把 RGB 小块直接展平：第一层是 VAE 的 `CausalConv3d(3,96,kernel=3)`，之后经过残差卷积、三次空间下采样、两次时间下采样、VAE 中间的同帧空间自注意力、输出卷积，取并标准化 16 通道 VAE 均值 latent。[官方 VAE 源码](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vae.py)、[1.3B VAE stride 配置](https://github.com/Wan-Video/Wan2.1/blob/main/wan/configs/wan_t2v_1_3B.py)

VAE 后，待生成视频的 latent 是 `[B,16,F_z,H/8,W/8]`。Wan2.1 原版视频帧数要求 `F=4n+1`（默认 81 帧），因此 `F_z=(F-1)/4+1`；高度、宽度应为 16 的倍数，才能在 VAE 的 `/8` 后再由 `(1,2,2)` patch 整齐划分。官方原版任务尺寸为：1.3B 主要 `832×480`；14B 支持 `832×480` 与 `1280×720`，不是固定只能输入这些尺寸的数学结构，但原版预处理和可用配置按这些尺寸实施。[官方任务配置](https://github.com/Wan-Video/Wan2.1/blob/main/wan/configs/__init__.py)、[官方 VACE 推理接口](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)

进入 DiT 的第一层是 `Conv3d(16,D,kernel=stride=(1,2,2))`：每个输出位置线性投影一个**同一 latent 时刻的 2×2×16=64 个 latent 数值**，不是 16×16×3 个原始 RGB 数值。`D=1536` 或 `5120`。patch 输出逻辑形状 `[B,D,F_z,H/16,W/16]`，随后按时间优先、行优先展平为 `[B,L,D]`，`L=F_z·H/16·W/16`。后续每一主干块执行时间调制、视频自注意力、文本交叉注意力与 FFN；VACE 控制分支的特征在指定块中相加；最后线性 head 输出每 patch 的 64 个 latent 预测数值，unpatchify 为 `[B,16,F_z,H/8,W/8]`，采样器更新 latent，最终 VAE 解码回 RGB。默认推理采样步数 50，采样步数不是“编码器层数”。[VACE 模型源码](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vace_model.py)、[Wan 基础模型源码](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/model.py)

没有音频输入路径：这里的“视频时维”指图像帧，不是音频帧。以后若另接音频模型，需独立定义条件与 Token 映射；不能把 Wan2.1-VACE 本身说成音视频联合编码器。

## 2. 具体张量尺寸与 Token ID

以当前网页处理分辨率 `W=768,H=432`、一个 `F=121` 短窗口为例，若**仅按 VACE 网络几何**且不加额外参考图像，形状是：

```
RGB                         [B, 3, 121, 432, 768]
VAE 均值 latent              [B, 16, 31, 54, 96]
DiT patch embedding 1.3B     [B, 1536, 31, 27, 48]
展平的 DiT Token 1.3B        [B, 40176, 1536]
DiT patch embedding 14B      [B, 5120, 31, 27, 48]
VACE 条件 latent（有视频/mask） [B, 96, 31, 54, 96]
```

`768×432` 可以按网络几何整齐下采样，但**不是上文官方 480P/720P 标准任务尺寸**，因此这组形状不能冒称为官方该尺寸的实跑结果。标准 1.3B 的 `832×480×81` 得到 `[B,21·30·52,1536]=[B,32760,1536]`；标准 14B 的 `1280×720×81` 得到 `[B,21·45·80,5120]=[B,75600,5120]`。如附加 `R` 张参考图像，原版 VACE 将其 VAE latent 前置到条件时间轴，生成 latent 时间长度也会增加 `R`，并在解码输出时裁掉参考图像位置；以上无参考图像数字不适用。[原版参考图像前置与 noise 形状](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)

视频 patch 序列下标 `k`（从 0 起）对应：`x=k mod W_p`、`y=floor(k/W_p) mod H_p`、`t=floor(k/(W_p·H_p))`，其中 `W_p=W/16,H_p=H/16`。坐标原点为**图像左上角**；`x` 向右、`y` 向下、`t` 向后。这是模型展平顺序与网页坐标需要约定的同一个序列坐标系，不能用左下角原点。[Wan 3D RoPE 展平代码](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/model.py)

例如该 768×432 例的 VACE `k=126` 是 `(t=0,y=2,x=30)`；几何上对应左上角像素 `x=480…495,y=32…47` 的 16×16 网格单元，以及 VAE latent 网格的 `x=60,61;y=4,5` 四个位置。后者并非只由这 256 个 RGB 像素决定：VAE 有大量重叠卷积与中间同帧空间注意力，时间卷积也是因果的。故“几何对应 16×16”**不是**“这个 Token 只包含这 256 个像素”，无法列出一组封闭、精确且固定的原图贡献像素；想量化实际像素贡献应测 checkpoint 的梯度/Jacobian 或输入扰动，而不是画一个方框便宣称包含关系。时间上 `t=0` 对应原视频首帧；`t≥1` 的名义新帧批次为原视频 `4t-3…4t`，并可能因因果卷积依赖更早帧。[VAE 1+4+4 编码与注意力实现](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vae.py)

## 3. Token 到底含有什么、如何融合位置

初始 DiT Token 是四个 VAE latent 位置的 64 数值经过**可学习 3D 卷积线性投影**所得，不是颜色均值，也不是可逆的像素堆叠。四个 latent 的各通道已含 VAE 学到的颜色、边缘、纹理、形状及周边与过去帧上下文；不应把 16 个 latent 通道逐一命名为固定语义。进入后续层后，Token 还聚合其他时空 Token、文本和 VACE 条件特征。

视频空间/时间位置**没有直接作为 `(x,y,t)` 数值拼接在初始特征向量后面**。自注意力的 Q/K 使用 3D RoPE 对帧、行、列位置编码，位置影响注意力分数；后续 hidden 因注意力与残差计算间接带位置信息。另有扩散 timestep 的正弦嵌入，经调制参数加/乘到每层状态；这个 timestep 是“第几次去噪”，不是视频第几帧。[RoPE、Q/K/V 官方实现](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/model.py)

不同融合位置不能混称一种操作：VACE 条件视频的可见/遮挡部分各自 VAE 编码后与 mask **按通道拼接为 96 通道**，再由独立 Conv3D 投影；VACE 控制分支先经过注意力/FFN，再将投影的 hint **加到**主干指定块输出；视频自注意力则用 `softmax(QKᵀ/√d)·V` 做**加权和**；文本经交叉注意力进入。原版 VACE 的条件图像没有直接作为“干净首帧 K/V”拼进主干视频自注意力。14B 的控制注入索引以实际 checkpoint `[0,5,…,35]` 为准，不以源码默认每 2 层推断。[条件通道构造](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)、[实际 checkpoint 配置](https://huggingface.co/Wan-AI/Wan2.1-VACE-14B/blob/main/config.json)

## 4. 噪声的范围：只为理解将来接入，不是 Demo0 要做的事

加噪发生在待生成视频的 **16 通道 VAE latent 的每个数值**，因此一个 patch 对应的 64 个输入 latent 数值原则上都参与加噪；不是只噪某几个 RGB 通道，也不是对投影后的 1536/5120 hidden 逐特征独立加噪。流匹配常见写法为 `z_σ=(1-σ)z_clean+σ ε`，`ε~N(0,I)`；实际 σ/时间表和预测量以所用 scheduler/checkpoint 配置为准。[Diffusers FlowMatch scheduler 的加噪实现](https://github.com/huggingface/diffusers/blob/main/src/diffusers/schedulers/scheduling_flow_match_euler_discrete.py)

**Wan2.1-VACE 原版推理的第一步待生成 latent `x` 是按完整 `[16,F_z,H_z,W_z]` 采样的高斯噪声**，即使条件里有首帧/参考图像；条件图像经 VAE 形成另一条**干净的 VACE 控制输入**，同时还有文本、mask、位置与 timestep 信息。故“第一步生成 latent 全是噪声”可说；“模型此时没有任何噪声以外的信息”不能说。某些其他 I2V/编辑管线会覆写或混合部分 latent，不可据此否定本原版 VACE 路径。[原版 noise 创建与条件输入](https://github.com/Wan-Video/Wan2.1/blob/main/wan/vace.py)

## 5. 刚运行的 Token 与差距

现有 3 个窗口和新增 14 个窗口都使用 `dense_multiscale_rootsift_rgb_v1`，未加载 VACE。实际处理的原 RGB 帧为 `768×432`，**每一原视频帧独立**产生 48×27=1296 个描述子；`F=121` 时保存形状 `[121,1296,265]`，而不是 VACE 的 `[31,1296,1536]`。265 维精确构成为：两个固定采样的 128 维 SIFT，经 RootSIFT 归一化，关键点名义尺寸分别 24 与 40 像素；再拼 9 维颜色摘要（局部 RGB 均值 3、RGB 标准差 3、Lab 均值 3），颜色分量乘 0.70，最后整个向量 L2 归一化。纹理分数另存，不在 265 维中；没有显式 `(x,y)` 拼接，也没有深度、相机轨迹、VAE latent、DiT Q/K/V。[本地实现](../data/demo0_v11/core.py)、[本地配置](../data/demo0_v11/config.json)、[运行记录](../data/demo0_v11/runs/demo0_v11_d0real/model_and_scheduler.json)

当前描述子的**绿色 1×1 网格单元**是 ID 所在的名义 16×16 像素单元；它的特征读取周围名义 24/40 像素 SIFT 支持与 25×25 颜色滤波范围，所以不是把 16×16×3 原像素展平。当前与 VACE 的**空间 ID 几何恰好一致**（都为 16 像素 stride、左上原点、行优先），但 Token 的来源、特征内容、时间压缩和后续条件融合差异很大。仅凭 48×27 一致不能说已经模拟 VACE Token。新运行 14/14 已完成，逐窗口均有 `window_manifest.json`、FL/P5 权重数组与运动槽 overlay 视频；不过这 14 个也同样是 D0-Real 手工特征。短窗口中 `82、51、31、120` 帧等不满足原版 `4n+1`，未来接原版 VACE 还需明确裁剪/补帧策略，不能照搬已有逐帧数组。[新增窗口进度](../data/demo0_v11/runs/demo0_v11_fullcoverage_d0real/coverage_progress.json)

本文没有登录远端服务器或读取未指定路径的 checkpoint；官方发布配置已经给出两种标准的确切数值，而当前运行记录足以确定“未选择任何 VACE 模型”。如项目将来指定一个不同的 checkpoint/改版，需从该文件的 `config.json` 和权重键重新核对，以上数字不自动适用。
