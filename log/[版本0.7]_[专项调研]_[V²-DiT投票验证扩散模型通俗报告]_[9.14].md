# V²-DiT“投票—验证扩散模型”通俗报告

> 调研日期：2026-09-14  
> 研究目标：给定同一场景的两个不同视角，生成中间的平滑过渡视频  
> 说明：这里的 **V²-DiT 不是已经发表并可下载的模型名称**，而是 0.0 版报告提出的研究设想。下面会严格区分“别人已经做成的部分”和“我们尚未验证的部分”。

## 先说结论

| 问题 | 直接答案 |
|---|---|
| 它成熟了吗？ | **没有。** Hough 投票、RANSAC 验证、可微版本都很成熟；把“投票→验证→把信息送回生成 token”反复放进视频扩散模型，目前没有查到成熟通用方案。 |
| 它准备做什么 demo？ | 0.0 版原方案是“首图 + 相机轨迹 → 视频”。为了符合本项目，应改成“首图 + 尾图 → 中间视频”，先在静态 Minecraft 建筑上验证。 |
| Minecraft 数据可以吗？ | **可以，而且很适合第一阶段。** 但应由程序控制相机并保存真值，不要人工手持录屏。需要 RGB、相机位置姿态、深度和可见性等自动标签。 |
| 能用 VACE 吗？ | **能。** 最稳的做法是用 Wan2.1-VACE-1.3B，把新模块接在 VACE 的控制支路上，先冻结原模型，只训练新增模块。 |
| VACE 能当 baseline 吗？ | 对“两端图片补中间帧”，**可以**。若输入还包括明确的相机轨迹，原始 VACE 不自带相机位姿接口，需要给所有对照方法增加相同的相机条件，或改用 CamI2V 作主 baseline。 |
| 值得做吗？ | **值得做一个小实验来证伪，但现在不能直接押成主论文。** 2025–2026 年已经出现几篇很接近的对应关系/注意力工作，创新空间比 0.0 版报告判断的更窄。 |

## 一、它到底想干什么

先把扩散模型想成一个正在补画动画的画师。

- 画师拿到第一张图和最后一张图。
- 中间十几张图一开始全是“雪花噪声”。
- 画师一遍遍擦掉噪声，逐渐画出中间帧。
- 难点是：第一张图里的窗户，到中间帧应该跑到哪里？最后一张图里的那扇窗，和第一张图里的是不是同一个？树枝、阴影、遮挡物又可能提供错误线索。

普通注意力像“所有人都能互相说话”。一个局部区域可能听错人：左边第三扇窗会把右边第三扇窗当成自己，于是建筑结构漂移。

V²-DiT 增加一个“小型评审会”：

1. **投票。** 每个局部图块根据自己看到的纹理、边缘、位置和两端图像，提出“我认为这一块沿着这种运动方式移动”的意见。
2. **凑成几种完整说法。** 模型不立刻相信某一个图块，而是把相近意见汇总成少量“运动/几何假设”。例如：近处墙面按方案 A 移动，远处墙面按方案 B 移动。
3. **验证。** 检查每种说法能不能同时解释许多图块，能不能连接首图和尾图，是否符合连续、平滑的相机运动。
4. **拒绝坏证词。** 树叶、反光、遮挡边缘、重复纹理等不能支持任何一致说法时，进入“拒绝桶”，不强迫它们参与。
5. **把可信信息送回画师。** 通过验证的假设告诉中间帧的局部 token：“你应该主要参考两端图中的这些区域。”然后扩散模型继续去噪。

这里传递的是模型内部的**特征向量**，不是直接把首图的像素剪下来粘过去。VACE 先用 VAE 压缩视频，再把压缩后的时空小块展平成 token；一个 token 通常代表一小块时空区域，不等于一个原图像素。V² 模块处理这些 token，并在模型每次去噪、经过被改造的 Transformer 层时执行投票和验证。[Wan2.1 的官方代码](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/model.py)展示了视频潜变量经 3D patch embedding 后展平为 token，再进入自注意力、文本交叉注意力和前馈层。

### 输入和输出

本项目适合采用下面的定义：

**推理输入**

- 同一场景的首视角图片；
- 同一场景的尾视角图片；
- 可选文字，例如“镜头平滑向右绕行，场景静止”；
- 可选首尾相机位姿。第一阶段 Minecraft 实验应提供位姿，先减少歧义。

**输出**

- 一段短视频，第一帧等于首图，最后一帧等于尾图，中间帧表现平滑的视角变化。

**训练时额外拥有、推理时可不提供的信息**

- 完整真值视频；
- 每帧相机内外参；
- 深度、可见性和遮挡；
- 哪些局部区域在不同帧中来自同一块表面。

这些额外信息像老师手里的答案，用来教会“谁的票可信”。训练完成后，普通用户不需要手工标点或画线。

## 二、它是否已经被别人研究成熟

### 结论：零件成熟，整机不成熟

| 已有方向 | 已经解决了什么 | 和 V²-DiT 的差别 |
|---|---|---|
| Hough / 广义 Hough | 让许多局部边缘对直线、圆或物体姿态投票。 | 经典视觉算法，不负责生成视频。 |
| CHM，CVPR 2021 | 把 Hough 式几何投票做成可训练网络层，用于两张图的语义对应。[论文](https://openaccess.thecvf.com/content/CVPR2021/html/Min_Convolutional_Hough_Matching_Networks_CVPR_2021_paper.html) | 有“可微投票”，没有扩散去噪，也没有把验证后的信息送回视频生成 token。 |
| DSAC，CVPR 2017 | 把 RANSAC 的选假设过程做成可训练模块，用于相机定位。[论文](https://openaccess.thecvf.com/content_cvpr_2017/html/Brachmann_DSAC_-_Differentiable_CVPR_2017_paper.html) | 有“提出并选择假设”，但输出相机位姿，不生成视频。 |
| NG-RANSAC，ICCV 2019；CONSAC，CVPR 2020 | 学会从更可信的数据点采样；CONSAC 还能找多个平面、多个消失点或多个运动。[NG-RANSAC](https://openaccess.thecvf.com/content_ICCV_2019/html/Brachmann_Neural-Guided_RANSAC_Learning_Where_to_Sample_Model_Hypotheses_ICCV_2019_paper.html)、[CONSAC](https://openaccess.thecvf.com/content_CVPR_2020/html/Kluger_CONSAC_Robust_Multi-Model_Fitting_by_Conditional_Sample_Consensus_CVPR_2020_paper.html) | 非常接近 V² 的“多说法 + 离群点”思想，但仍属于几何估计。 |
| Track4Gen，CVPR 2025 | 用点跟踪监督扩散模型内部特征，减少视频中的物体外观漂移。[论文](https://www.openaccess.thecvf.com/content/CVPR2025/html/Jeong_Track4Gen_Teaching_Video_Diffusion_Models_to_Track_Points_Improves_Video_CVPR_2025_paper.html) | 已证明“监督扩散内部特征”有用，但没有显式的多假设投票与拒绝。 |
| FCVG，CVPR 2025 | 直接研究“两张关键帧补中间视频”，先匹配两端的线，再为每一帧制造条件。[论文](https://openaccess.thecvf.com/content/CVPR2025/html/Zhu_Generative_Inbetweening_through_Frame-wise_Conditions-Driven_Video_Generation_CVPR_2025_paper.html) | 任务和本项目高度一致，是必须比较的强 baseline；它把对应关系作为逐帧条件，而不是投票—验证路由。 |
| CAMEO，CVPR 2026 | 用真实几何对应直接监督多视角扩散模型的一层注意力，报告了更快收敛和更好几何一致性。[论文](https://openaccess.thecvf.com/content/CVPR2026/html/Kwon_Correspondence-Attention_Alignment_for_Multi-View_Diffusion_Models_CVPR_2026_paper.html) | 已经覆盖“对应关系监督注意力”这个宽泛主张，V² 不能再只声称这一点。 |
| CorrAdapter，CVPR 2026 | 在扩散 Transformer 旁加支路，从中间特征找对应区域，只在匹配区域之间传信息；还能用于动态视频。[论文](https://openaccess.thecvf.com/content/CVPR2026/html/Zhang_Align_Images_Before_You_Generate_CVPR_2026_paper.html) | 这是目前最接近的架构对手。V² 必须证明“多个明确假设 + 一致性验证 + reject”比普通对应聚合更有用。 |

截至本次查新，没有检索到名为 “V²-DiT”“Vote, Verify, Then Denoise”，或完整采用“局部投票→多个几何假设→一致性验证→反向路由→在去噪层中重复”的视频扩散论文、公开代码或 checkpoint。因此：

- **不能说它已经成熟。** 目前连我们自己的最小实验结果也没有。
- **也不能轻易说它绝对首创。** CorrAdapter、CAMEO、Track4Gen 已占据了周围很大一块空间。
- 仍可能成立的新意只有一个很窄的版本：**用可解释的多个运动/平面假设来组织扩散信息，并显式拒绝离群区域。**

我会把 0.0 版中“查新风险低—中”修正为：**查新风险中—高，机制风险高。**

## 三、期待的 demo 到底是什么

### 0.0 版原方案的 demo

原文定义的是：

> 一张首图 + 一条相机轨迹 + 可选物体轨迹 → 一段受控视频。

这属于**相机控制的图生视频**。例如给一张 Minecraft 小屋正面图，再要求镜头平滑向右绕行，模型生成小屋侧面逐渐出现的视频。CamI2V 已证明了“首图 + 相机轨迹”的任务和极线注意力方案。[CamI2V](https://arxiv.org/abs/2410.15957)报告其方法用极线约束跨帧注意力，在 RealEstate10K 上改善相机可控性。

### 本项目应该做的 demo

为了不再偏离“已知两个视角生成过渡视频”，建议把 demo 改成：

> **输入：** 同一座 Minecraft 建筑的首视角图和尾视角图。  
> **输出：** 17 帧视频；第 1 帧和第 17 帧固定，中间 15 帧是平滑绕行。  
> **场景：** 先保持建筑和光照静止，只让相机运动。

生成过程可以直接理解为：

```text
首图 ─┐
      ├─→ VACE 把中间帧从噪声逐步画出来 ─→ 过渡视频
尾图 ─┘          ↑
             V² 小模块反复做：
             局部投票 → 检查多数意见 → 丢掉坏票 → 传回可信特征
```

第一阶段最好同时给模型首尾相机位姿，并把中间位姿用平滑曲线插出来。这样实验只问一个问题：**投票—验证能否让建筑结构比普通 VACE 更稳定？**

如果第一阶段就只给两张图片、完全不给相机位姿，模型还要同时猜：相机向哪边走、走多远、焦距有没有变、中间有没有绕过物体。多种答案都可能合理，实验很难判断“模型错了”还是“它选了另一条也合理的路”。这个难度应放到第二阶段。

### V² 在双端点版本中具体投什么票

最容易落地的 V0 不是让模型凭空发明无限种运动，而是准备少量候选解释：

- 假设 1：这一片属于近处正面墙；
- 假设 2：这一片属于远处侧墙；
- 假设 3：这一片属于屋顶斜面；
- 拒绝：它是遮挡、树叶、阴影或暂时无法确认的区域。

每个假设内部保存一个能把首图位置投到各个中间帧的位置变化规则。相机位姿和候选深度/平面确定后，这条规则可以计算。局部 token 根据特征相似度和重投影误差投票；大量相邻 token 一起支持的假设留下，孤立坏票被拒绝。留下的假设负责从首图和尾图取出相关特征，送给中间帧相应区域。

这正是它比“所有位置自由注意”多出的限制。

## 四、验证阶段需要什么数据，Minecraft 可以吗

### 可以，但必须是程序采集

Minecraft 的优势很适合检验 V²：

- 建筑有多个平面和深度层；
- 方块纹理经常重复，容易造成错误对应；
- 门洞、屋檐、树木能制造遮挡；
- 世界和相机由程序控制，可以自动得到真值。

[MineDojo 官方文档](https://docs.minedojo.org/minedojo/minedojo.sim.html)提供可设定的起始位置和朝向，并支持深度观察；其[入门文档](https://docs.minedojo.org/sections/getting_started/sim.html)还列出了 RGB、位置、yaw 和 pitch。也可以使用能输出 RGB 与深度的 [Project Malmo 接口](https://microsoft.github.io/malmo/0.30.0/Documentation/classmalmo_1_1_mission_spec.html)。

不要让人用鼠标手动移动再录屏。相机轨迹应由程序给出，例如一条圆弧或三次样条，然后按固定帧率渲染。这样得到的运动本身就是平滑的。

### 每条训练样本需要保存什么

| 文件/标签 | 用途 | 是否要人工标 |
|---|---|---|
| 17 帧 RGB 视频 | 扩散模型要学习的正确答案 | 否，游戏直接渲染 |
| 第 1、17 帧 | 推理时的两张输入图 | 否 |
| 每帧相机位置、朝向、视场角 | 计算平滑轨迹和几何投影 | 否，程序记录 |
| 每帧深度图 | 判断一个位置在三维中有多远 | 否，可由模拟器输出 |
| 方块/物体 ID 或分割图 | 区分墙、屋顶、树和遮挡物 | 最好自动输出；没有也能先做 |
| 可见性/遮挡标签 | 教 reject 分支何时不要相信局部证据 | 由深度和相机矩阵自动计算 |
| 跨帧对应点或光流 | 监督局部 token 应该支持哪个假设 | 用深度和相机矩阵自动计算，无需手点 |

因此答案是：**你不需要手工标点、线、面。** 静态场景中，一个像素的深度加上相机矩阵，就能算出它在下一帧应该落到哪里；若那里被别的东西挡住，也能用深度判断。

### 推荐的数据难度顺序

1. **最小调试集：** 单栋静态小屋、纯相机绕行、少量纹理。
2. **机制验证集：** 多层墙面、屋檐、柱子、重复窗户、树木遮挡、不同距离。
3. **压力测试集：** 首尾重叠很小、强重复纹理、前景遮挡、大角度视差。
4. **第二阶段：** 加会动的门、活塞或生物，区分相机运动与物体运动。

训练集和测试集必须按“建筑/世界”分开，不能把同一栋楼换一个镜头后同时放入训练和测试。小实验可先做约 500 条调试 clip，再做 5,000–20,000 条受控 clip；具体数量由分辨率和显存决定，数据的几何覆盖比机械堆数量更重要。

### Minecraft 能证明什么，不能证明什么

- 能证明：投票是否形成正确峰值、能否拒绝错误纹理、能否在遮挡下保持结构。
- 不能单独证明：方法能泛化到真实楼房、曲面物体、透明反光和非刚体人物。

所以 MC 是很好的**机制考场**，不是最终应用结论。MC 通过后，至少再加一套真实或更写实的双视角数据。

## 五、模型到底改哪里

### 推荐修改 VACE 的控制支路

Wan2.1-VACE 由一个原始 Wan 视频 DiT 和一条 VACE 控制支路组成。官方 1.3B 配置有 30 个主 Transformer block；VACE 在偶数层设置 15 个控制 block，把控制信息处理成 hint，再加回主干。[官方配置](https://huggingface.co/Wan-AI/Wan2.1-VACE-1.3B/blob/main/config.json)给出了 `num_layers=30` 和 15 个 `vace_layers`；[官方实现](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vace_model.py)展示了控制 block 和零初始化投影如何把 hint 加入主 block。

最稳的改法是：

1. 保留 VAE、文本编码器和 Wan 主干不动。
2. 首图、尾图和已知/未知位置的 mask 仍走 VACE 原有输入。
3. 在 15 个 VACE 控制 block 中先选 3 个中间层，插入 V² 小模块。
4. 小模块含四样东西：`vote head`、少量 `hypothesis tokens`、`verify/reject head`、把可信特征送回控制支路的 `zero gate`。
5. 新输出再沿 VACE 原有 hint 通道进入主干。

这样改的好处是：如果新模块一开始什么都没学会，zero gate 输出为零，模型行为仍接近原始 VACE；调试失败时也容易定位。

### 先训练什么

第一轮不需要全量训练 1.3B checkpoint。

- 冻结 VAE、文本编码器、Wan 主干和原 VACE 参数；
- 只训练新增的投票头、假设 token、验证头和输出门；
- 损失一部分来自正常视频扩散训练，要求最终视频接近真值；
- Minecraft 有真值时，再教模块“正确平面/运动应得高票，遮挡和错误对应应进入 reject”；
- 若小模块确实有效，再给少量 VACE 层加 LoRA 或解冻控制支路。

这能回答一个干净的问题：效果来自投票—验证结构，还是只是因为重新训练了整个大模型。

### 能否直接用 VACE 生成两端之间的视频

可以把首、尾图放入一段“只有两端已知、中间为空”的控制视频，并用 mask 告诉 VACE 保留两端、生成中间。VACE 官方接口本身接收 `src_video`、`src_mask` 和参考图，[官方仓库](https://github.com/ali-vilab/VACE)说明了这些统一输入；Wan 官方还另有专门的 [FLF2V 权重和推理实现](https://github.com/Wan-Video/Wan2.1)。

不过要区分两件事：

- **只做首尾帧补间：** 原始 VACE 可以作为 baseline。
- **还要求严格跟随数值相机轨迹：** 原始 VACE 没有 CamI2V 那样现成的相机位姿条件。此时应该用 `VACE + 同一个相机编码器` 对比 `VACE + 相机编码器 + V²`，或者直接以 CamI2V 为主 baseline。

## 六、baseline 应该怎么设，才知道 V² 是否真有用

所有方法必须使用相同的首尾图、训练数据、随机种子、视频长度和采样步数。

| 对照 | 它回答什么问题 |
|---|---|
| 原始 VACE-1.3B | 什么新结构都不加时能做到多好？ |
| VACE + 普通同参数 adapter | 提升是否只是因为多了参数？ |
| VACE + 对应/重投影损失，但不加 V² | 提升是否只来自额外标签和 loss？ |
| VACE + 单一假设，无 reject | 多假设和拒绝机制是否有必要？ |
| VACE + V² | 完整方法。 |
| FCVG | 和已经发表的双关键帧补间方法相比是否有价值？ |
| CorrAdapter | 和更简单的“先找对应区域再聚合”相比是否有价值？ |
| 使用真值几何的 oracle | 如果几何全对，理论上限有多高？ |

至少观察四类结果：

- 中间帧是否接近 MC 渲染真值；
- 建筑边缘、窗户、屋顶是否漂移或变形；
- 对应点能否跨帧稳定跟踪；
- 模块的票是否真的集中到正确假设，遮挡处是否真的进入 reject。

如果完整 V² 只比原始 VACE 好，却不比“普通同参数 adapter”或“只加对应损失”好，就不能说明投票—验证思想有效。

## 七、我对这个方向的最终判断

它不是胡思乱想：Hough、RANSAC、可微投票、多模型拟合都有可靠基础；MC 又能提供非常干净的自动真值。它也不是一个已经被证明的方案：到目前为止，最重要的“验证后的假设反过来改善扩散生成”仍是待实验的假设。

建议把第一阶段压成一个两周内可判生死的小问题：

> 在静态 MC 建筑、已知相机位姿、首尾帧固定的条件下，V² 是否比等参数 adapter 更能抵抗重复纹理和遮挡？

**继续条件：** 随着遮挡率和错误对应率上升，V² 的结构误差明显小于等参数 adapter；投票图和 reject 也与真值一致。  
**停止条件：** 只在干净简单场景有效；一加遮挡就乱；或者普通 adapter 同样好。

这个 Gate 通过后，再谈真实建筑、未知相机位姿和动态物体。没有通过前，不建议在 14B 模型上投入大算力。
