# 版本 1.13｜天空查询、网页候选与大小白框

日期：2026-09-16。只读核查现有结果及网页代码，没有调整天空阈值或重跑。用户指出“很多天空点击的前 1–8 个位置看着大致正确”是有价值的观察；我此前用“天空一致、都分辨不出来、置信度低”概括整片天空，**说得过满，描述有错**。需要分清“不同位置的特征有差别”“候选框落在看着合理的位置”“识别出该像素的唯一真实物理对应”这三个要求。

## 1. 当前能否区分不同天空位置

当前 265 维特征不只看绿色 16×16 网格单元的纯蓝颜色：它在单元中心采两个名义 24/40 像素大小的 RootSIFT 特征，并采 25×25 局部 RGB 均值/方差和 Lab 均值；纹理评分也使用局部标准差及梯度。天空若有色彩渐变、云层、视频压缩/像素微差，或 40 像素支持碰到树/建筑边缘，不同位置可能得到不同分数。即使中心绿色小块全蓝，白框覆盖范围里的非天空结构也可能参与描述子；所以“这个 Token 里只有一片蓝”不是代码实际输入。[描述子代码](../data/demo0_v11/core.py)

对**严格均匀、无边界且所有候选都同色同纹理**的天空，局部外观不能给出唯一物理像素对应；多个位置的余弦分数会几乎相同。Top-8 仍一定会返回一些位置，因为检索代码无条件取 Top-16。当前 P5 在外观之后又使用候选位移的运动槽、周边颜色槽平均及从真实相邻帧计算的光流时间先验，这些可把模糊候选往一个局部位置排列；它们提供几何/时间偏好，不让纯蓝色本身变成唯一标识。特别是对静止远景，“看着在原处附近”可能与真正同一片天空的物理对应无法区分。[外观 Top-16](../data/demo0_v11/core.py)、[候选运动/空间/时间打分](../data/demo0_v11/core.py)、[真实相邻帧光流](../data/demo0_v11/pipeline.py)

VACE 的 VAE 特征可能利用周边结构与全帧上下文，自注意力 Q/K 还有 3D RoPE 的位置编码，因而**有条件**地区分有云、梯度、地平线或相机轨迹约束的天空区域。但如果输入确实全同色且无任何几何/时间辨识线索，VACE 也不能从同一 RGB 视频里创造出“这个蓝色像素属于哪个物理天空点”的可观测信息。RoPE 可偏好图像坐标，却不是物体身份/真实运动的测量。是否重导数据取决于任务：若要测唯一物理像素跟踪，应导出有纹理/明确边界、且带可核对对应的天空；若要测算法何时应承认歧义，纯色天空恰是必要负例。本文没有决定删天空、替换背景或把所有天空强制拒绝。[VACE VAE 注意力](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/vae.py)、[Wan 3D RoPE](https://github.com/Wan-Video/Wan2.1/blob/main/wan/modules/model.py)

## 2. 对一个纯天空查询逐字段复核

现有窗口 `simple_multidepth_0180_0300` 的局部帧 60、Token ID 126，对应当前帧网格 `(x=30,y=2)`。直接读保存数组得到：纹理分数 `0.0000`；Top1/Top2 余弦差距约 `0.0000946`；Top-16 归一熵 `0.8110`；P5 组合置信度 `0.1117`；P5 已拒绝，`selected_reference_endpoint=2`，Top-8 稀疏允许数为 **0**。与此同时，Top-8 数组确有首/尾帧候选，例如首帧 `(29,2)`、尾帧 `(31,2)`、尾帧 `(31,3)` 等，框在当前 `(30,2)` 附近；最高余弦相似度约 `0.9995`，但第一、第二几乎并列。这正是“框看着大致对”与“无法确认唯一匹配”可以同时出现的一条真实记录。[该窗口候选数组](../data/demo0_v11/runs/demo0_v11_d0real/simple_multidepth_0180_0300/modes/FL/raw_topl_index.npy)、[P5 数组目录](../data/demo0_v11/runs/demo0_v11_d0real/simple_multidepth_0180_0300/modes/FL/P5)

不能把这一个例子外推为“所有天空都低置信度”。当前帧顶部还有有纹理/边界的 Token，可能被接受；不同窗口、不同帧和 P1–P4（没有拒绝门）也会有不同状态。现在没有用户那几次点击的 `run/window/frame/token/mode/P方法`，因此无法逐个判定所见“对”的候选究竟来自轻微天空变化、边界 40 像素支持、空间/时间运动先验、端点自匹配，还是纯视觉巧合。若提供这些五项信息，下一轮可只读逐条比对原视频像素、描述子、数组和网页响应；无需先改阈值。

## 3. 网页的候选/热力图从哪里来，有无面向前端加工

点击查询时，前端请求 `/api/query`，没有在浏览器里凭点击坐标虚构首尾位置。后端按帧/ID从 `raw_topl_index/score`、`reference_endpoint/local_id`、`verified_topl_weight`、`sparse_reference_mask`、`token_slot_probability` 等 `.npy` 数组逐项读取候选与投票结果。**原始全库热力图**由后端读取保存的 `descriptor.npy`，重新计算查询向量与首帧、尾帧全部 1296 描述子的内积；**验证权重热力图**只把已计算 Top-16 权重放到相应网格，其他位置填 0。前端把这两种数值映射为颜色并叠在原图上。不能把颜色深浅直接读作“正确物理对应概率”或 VACE 注意力。[后端查询代码](../data/demo0_v11/backend/server.py)、[前端绘制代码](../data/demo0_v11/frontend/app.js)

现有面向人眼的处理需要逐项说明，免得视觉印象被当原始输出：

| 网页/视频效果 | 实际处理 | 会怎样影响观感 |
|---|---|---|
| 原始热力图颜色 | 余弦值按固定 `0.45…1.0` 裁剪归一，再套五色调色板，透明度 `0.42` | 相近高分可看起来都“很热”；颜色不是校准置信度 |
| 验证热力图颜色 | Top-16 权重放网格、外面填零，透明度 `0.58`；P5 拒绝时默认不画验证热图 | 它是截断候选图，不是全图重新计算的运动概率 |
| 首/尾候选框 | 无论是否拒绝，前 8/16 候选仍画框；拒绝时改成灰色虚线，`sparse_allowed=false` | 拒绝查询仍会出现“位置很对”的诊断框；这些不是允许关注的 Token |
| 当前帧选中组浅色 | 前端按选中槽与其他 Token 的概率向量相似度、以及置信度计算透明度阈值 | 可把概率相近区域连成视觉块，不是硬的物体像素分割 |
| 单槽白边界 | 前端取每 Token 的槽 `argmax`，排除拒绝 Token，只描画相邻格单元之间的边 | 白边界是后验的硬视图，不是单独训练的实例 mask |
| MP4 运动槽覆盖层 | 由数组生成；槽概率升到 `2.4` 次幂后混色，颜色透明度随置信度变化，拒绝处画斜线 | 加强颜色与连续性感；不能据视频色块认定真实物体被追踪 |
| 运动箭头视频 | 每 8 个 Token 才画 1 个，且仅较高置信度、非拒绝者；箭头末端被裁到画面内，顶部避开标题栏 | 视频箭头不是全部原始候选，也不代表全区域无误 |
| 端点自匹配 | 在首帧与 FL 尾帧，计算端强制该帧同 ID 匹配且置信度 1 | 拖到端点看到完美重合是代码边界条件，不能当中途跟踪能力 |

这些处理的具体代码在 [前端 app.js](../data/demo0_v11/frontend/app.js)、[后端 server.py](../data/demo0_v11/backend/server.py)、[MP4 渲染 pipeline.py](../data/demo0_v11/pipeline.py)、[端点处理 core.py](../data/demo0_v11/core.py)。网页可以信赖为**现有 265 维描述子与投票数组的可视化读取器**；它没有使用真实 VACE 模型，色彩/框选/裁剪也不是逐像素真值。尤其要同时看表格中的 `raw_score`、`verified_weight`、`confidence`、`sparse_allowed`、`endpoint=拒绝`，单看热图颜色和 1–8 框会误读。

## 4. 绿色 1×1 与白色“3×3”是什么

当前 48×27 网格的 **一个 Token ID 只有一个绿色 16×16 单元**，右上角 `ID++` 按 `id=y·48+x` 遍历这些 1296 单元。点击后白色虚线外框由前端读 `descriptor_support_pixels=[24,40]` 并取最大 **40×40 像素**，以绿色 16×16 单元中心为中心画出。因此看起来约覆盖 2.5×2.5 个小格，视觉上近似 3×3；它**不是 9 个 Token 合成一个 Token**，也不是 VACE 的 3×3 感受野。这是对手工 SIFT 较大名义采样尺度的观察提示。SIFT 内部有旋转/高斯/插值，40×40 白框不是精确的每像素权重支撑边界；另外局部颜色滤波取 25×25。绿色框指出 Token 坐标/ID，白框提示周边图像会影响当前手工特征。[前端两框代码](../data/demo0_v11/frontend/app.js)、[后端尺寸字段](../data/demo0_v11/backend/server.py)、[SIFT 与颜色代码](../data/demo0_v11/core.py)
