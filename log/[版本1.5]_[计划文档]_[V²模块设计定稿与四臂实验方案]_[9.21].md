## 1. 对前序版本的修正（必须显式记录，不得静默覆盖）

| 修正项 | 原表述 | 修正后 |
|---|---|---|
| 主干类型 | 项目名 V²-**DiT** 暗示主干是 DiT | 当前主线主干是 **3D U-Net**（`lvdm...openaimodel3d.UNetModel`）。V²-DiT 只保留为**方法名**，不是主干描述 |
| 投票对象 | [版本1.4]："投票投的是深度层，不是运动" | **废弃**。投票是**候选对的一致性共识 + 拒绝**。深度只是"静态场景 + 已知位姿"这一特例下位移场的等效解释，不是方法的定义 |

## 2. CamI2V 的 "plug-and-play" 机制（代码级事实）

论文只声明 *"in a plug-and-play manner"*，机制在 `CameraControl/CamI2V/cami2v.py`，三步：

### 2.1 按类名字符串定位插入点

```python
for _name, _module in self.model.diffusion_model.named_modules():
    if _module.__class__.__name__ == 'TemporalTransformer':
        setattr(_module, 'forward', new_forward_for_TemporalTransformer.__get__(...))
    elif _module.__class__.__name__ == 'TimestepEmbedSequential':
        ...
    elif _module.__class__.__name__ == 'BasicTransformerBlock':
        if _module.context_dim is None and _module.attn1.to_k.in_features != init_attn_out_channels:
            setattr(_module, '_forward', new__forward_for_BasicTransformerBlock...)
```

### 2.2 运行时动态挂载零初始化子模块

```python
pluker_projection = nn.Linear(C, C)
nn.init.zeros_(list(pluker_projection.parameters())[0])
nn.init.zeros_(list(pluker_projection.parameters())[1])
_module.add_module('pluker_projection', pluker_projection)

epipolar = Epipolar(query_dim=C, context_dim=C, heads=..., **epipolar_config)
_module.add_module('epipolar', epipolar)     # Epipolar.__init__ 内对 to_out 零初始化
```

### 2.3 条件以 dict 逐层透传

```python
return_kwargs["camera_condition"] = {
    "pluker_embedding_features": ...,   # 多尺度相机特征
    "sample_locs_dict": ...,            # 极线 mask，键为下采样倍率 {8,4,2,1}
    "cond_frame_index": ...,
    "add_type": "add_to_main_branch",
}
```

### 2.4 结论

**"plug-and-play" 的真实含义**：不改权重、不改原文件，运行时按类名找到插入点、挂上零初始化分支。
**它不是 backbone 无关的**——`__class__.__name__ == 'TemporalTransformer'` 这一行决定了它只对拥有该类名的骨架有效。

## 3. 为什么 VACE 难插（保留此记录，作为 E 项决策的依据）

| 维度 | DynamiCrafter / CamI2V（U-Net） | VACE（Wan2.1 DiT） |
|---|---|---|
| 可命名插入单元 | ✅ 有 `TemporalTransformer` 类 | ❌ 只有 30 个同构 DiT block |
| 注意力粒度 | 三种可分开：spatial / temporal / epipolar | ❌ 单一全局自注意力，32760 token |
| 条件通道 | ✅ `camera_condition` dict 透传 | ❌ 96 通道独立支路，第 0 块混入 |
| 位置编码 | 无 | ❌ 3D RoPE，Q/K 被位置旋转 |
| 可加残差 | ✅ `attn1`、`pluker_projection` 均可加 | ❌ 每块只有一个 attention 残差 |

**「内部特征耦合、无从下手」这一判断成立，且有代码级依据。** 但见 §4——V² 的形态与 CamI2V 不同，因此仍然有机会。

## 4. 核心设计：V² 是与 CamI2V 不同形态的轻量模块

### 4.1 形态对比

```text
CamI2V 极线分支（重）:
    q ∈ [L, C]  attend to  k,v ∈ [L, C]     mask [L, L]
    L = T·H·W，32×32 尺度下 L = 16384  →  必须物化 mask

V² 参考分支（轻）:
    q ∈ [L, C]  attend to  k,v ∈ [M, C]     mask [L, M]
    M = 每个 query 被投票选中的少量参考 token，K ≈ 8–64  →  gather 取索引
```

### 4.2 由此得到的四条性质

1. 注意力矩阵是 `[L, M]`，**不需要物化 `[L, L]`**
2. 用 `gather`/`index_select` 取 K/V，计算与显存均为 `O(L·M)`
3. **不需要空间/时间分离**，因此**不需要** `TemporalTransformer` 这类可命名单元
4. 天然稀疏，适配 FlashAttention / 分块

**结论：V² 可以是 backbone 无关的。** 它是"在当前 attention 旁边挂一条对少量参考 token 的稀疏注意力残差"，任何含 attention 的扩散主干均可挂载——U-Net、VACE、CogVideoX 皆可。

### 4.3 模块接口（定稿）

```python
class V2RefAttn(nn.Module):
    """
    backbone 无关的稀疏参考注意力残差。
    零初始化输出投影 ⇒ 接入初期输出恒为 0，模型严格等价于原主干。

    输入:
        q       : [B, L, C]           当前 token 的 query 特征
        ref_k   : [B, M, C]           参考 token 的 key（M ≪ L，来自首帧/尾帧）
        ref_v   : [B, M, C]           参考 token 的 value
        mask    : [B, L, M]           投票掩码。bool=硬允许；float=logit bias
        gate    : scalar | [B, 1, 1]  扩散步门控；reject 时置 0
    输出:
        delta   : [B, L, C]           加回主干的残差
    """
```

**接口约束（必须遵守，否则失去 backbone 无关性）**：
- 不得出现任何相机/位姿/极线相关参数
- 参考 token 以**索引 + 张量**传入，不得依赖主干的类结构
- 掩码既支持 bool 也支持 float（便于后续做 soft bias 消融）

### 4.4 在 CamI2V 上的挂载点

```python
# new__forward_for_BasicTransformerBlock_of_TemporalTransformer 内
normed_x = self.norm1(x)
zero_init_x  = torch.zeros_like(normed_x)
zero_init_x += self.pluker_projection(normed_x + pluker_feat)              # 已有
zero_init_x += self.epipolar(normed_x + pluker_feat, epipolar_mask)        # 已有
zero_init_x += self.v2_ref_attn(                                           # 新增
    q      = normed_x,
    ref_k  = self.v2_ref_k,
    ref_v  = self.v2_ref_v,
    mask   = self.v2_mask,
    gate   = self.v2_gate,
)
x = zero_init_x + self.attn1(normed_x) + x
```

**注意零初始化带来的一个干净性质**：接入初期第 (a) 臂与第 (b)(c)(d) 臂**严格等价**，因此对比不含任何初始化噪声。

## 5. 候选生成：可插拔的 `CandidateProvider`

### 5.1 接口

```python
class CandidateProvider(Protocol):
    def __call__(self, ctx: ProviderContext) -> CandidateSet:
        """
        ProviderContext: 当前 token 特征、参考池特征、token 网格元数据、
                         （可选）相机内参/位姿、扩散步 t
        CandidateSet:   每个当前 token 的
                          - 候选参考索引  [L, K]
                          - 候选权重      [L, K]
                          - 拒绝标记      [L]
        """
```

### 5.2 三个实现

| 实现 | 用于 | 先验 |
|---|---|---|
| `EpipolarVoteProvider` | 臂 (b)，CamI2V 原生 | 极线带把搜索降到 1-D，带内做运动投票排序 |
| `PureVoteProvider` | **臂 (c)，VACE 可迁移** | **不使用任何相机信息**，在全参考池上做一致性投票 + 拒绝 |
| `OracleProvider` | 臂 (d)，诊断上限 | 用真值对应关系直接构造掩码 |

### 5.3 运动投票的定义（回到 [版本1.0] §3.3，并修正）

```text
投票者    当前 token j 与参考 token i 构成的候选对
投票内容  该候选对隐含的位移 d_ji（在 token 网格坐标上）
被投对象  少量共享运动假设 {μ_k}（软 EM 求归属，保留拒绝槽）
验证      外观相似度 + 位移残差 + 空间邻域支持 + 时间一致性 + 可见性/遮挡
输出      稀疏掩码 M[j, i] ∈ [0,1]，只有通过验证的候选非零
```

**关键**：纯投票路线 (c) **完全不需要相机**。位移在 token 网格坐标上定义，因此自然适用于没有位姿条件的主干。这正是它与"深度估计"的分野——深度估计需要一个带位姿的成像模型，而投票只需要"多个候选对是否互相一致"。

## 6. 四臂实验（第一条实验路线）

### 6.1 臂定义

```text
同一 seed / 同一首帧 / 同一相机轨迹 / 同一 CamI2V 权重：

(a) 原版 CamI2V                                ← 零初始化 ⇒ (b)(c)(d) 在初始点等价于 (a)
(b) + V²，EpipolarVoteProvider   （CamI2V 原生路线）
(c) + V²，PureVoteProvider       （VACE 可迁移路线）★ 重点
(d) + V²，OracleProvider         （架构 headroom 上限）
```

### 6.2 每个对比回答什么

| 对比 | 回答的问题 | 若为负的结论 |
|---|---|---|
| (d) vs (a) | 稀疏参考注意力这个**架构**本身有没有 headroom | 架构无效，不必往下走 |
| (c) vs (d) | **纯投票**离真值上限有多远 | 投票质量不足，回到候选生成 |
| (b) vs (c) | **几何先验**到底值多少 | 差别小 ⇒ (c) 即可作为通用模块 |
| (c) vs (a) | **可迁移版本单独有没有收益** | 决定能否迁移到 VACE |

### 6.3 评价指标

**主指标（生成质量，最终结论只认这个）**：

```text
视觉质量   FVD（对比真实 MC 视频），以及 PSNR / SSIM / LPIPS
相机可控性 RotErr / TransErr / CamMC（对生成视频跑 GLOMAP 反解轨迹，与给定轨迹比）
```

**辅助指标（诊断用，不作为结论）**：

```text
候选阶段   Hit@1/8/16、MRR、候选熵
路由阶段   每 token 平均保留参考数、拒绝率、掩码稀疏率
```

**必须记录的限制**：CamI2V 在 RealEstate10K 上训练，**零样本跑 Minecraft 是分布外**。绝对值不能与论文比较；四臂同样 OOD，**相对比较有效**。

### 6.4 前置的可行性检查（半天，先做）

> **CamI2V 零样本跑 Minecraft 能否生成像样的视频？**

用 `简单平动透视关系含天空版.mp4` 的首帧 + 真实相机轨迹，25 步生成，人眼看。
若完全崩坏，整条 MC 生成实验线不成立，必须改到 RealEstate10K。**此检查不通过则不进入四臂实验。**

## 7. 与 VACE 的关系（决策 E：先不碰）

本文档**不安排**任何 VACE 工作。保留的接口兼容性要求只有一条：

> `V2RefAttn` 的签名与实现中不得出现相机相关假设。

满足这一条，将来迁到 VACE 时理论上只需换 `CandidateProvider`。但**迁移的真实可行性未经验证**，仍需一次独立探针（挂载点、RoPE 影响、干净参考 K/V 的取得方式）。不在此版本承诺。

## 9. 待解决的技术问题（实现前需确认）

| 编号 | 问题 | 影响 |
|---|---|---|
| T1 | 参考 K/V 从哪来：当前特征的时间位置 0（noisy）/ 新增 reference encoder（干净） | 决定是否需要新增参数与额外前向 |

| T3 | 投票掩码用 bool 硬掩码还是 float logit bias | 影响可回退性与消融设计 |

| T6 | 参考池是仅首帧，还是首帧 + 尾帧 | 与 [版本1.0] 任务 A/B 的划分一致 |
