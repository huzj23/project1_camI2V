# Demo0 v1.1 投票算法、三窗口诊断与下一版提案

范围：冻结的 `demo0_v11_d0real` 三窗口 D0-Real。目标不是分割色块本身，而是为每个当前 Token 提供首帧（可选尾帧）中**有限、尽可能同运动状态的参考 Token**，日后用于扩散步注意力引导。当前数组已做到“每 Token 的参考建议”，**尚未接入 VACE Attention**。对应代码为 [core.py](core.py)、[pipeline.py](pipeline.py) 和冻结 [config.json](config.json)。

## 当前算法确切做了什么

1. 每帧先缩放到 768×432，按 16 像素步长建立 48×27、共 1,296 个显式网格查询位置；Token ID=`y×48+x`。中心位置提取固定尺度 24/40 像素 SIFT 梯度、RootSIFT 归一化及附近 RGB/Lab 均值/方差，拼接、L2 归一。故“16×16 框”只是索引格，表示支持域可达 40 像素。
2. P0 不投票：对每个当前查询，与首帧（F）或首尾帧并集（FL）的同一表示做余弦点积，保留 Top16，首 8 个是主候选。对比 P1–P5 的公平起点是**同描述子、同网格、同参考池、同 Top16**。旧 ResNet/DIS 结果是历史失败方案，不能充当因果对照。
3. 候选 `r` 的端点坐标与当前查询 `q` 产生位移票。若来自首帧，`v=(q-r)/α`；尾帧则 `v=(r-q)/(1-α)`，其中 `α=t/(T-1)` 且靠端点时设最小时间差与几何可靠性门。H0 假设 `v=(vx,vy)`；H1 假设 `v=scale_rate×position+(vx,vy)`，允许随透视位置变化的尺度趋势，**没有真实深度、旋转或 3D 反投影**。
4. 初始票权约为 `softmax(raw_score/0.012)×纹理可靠性×候选清晰度×几何可靠性`。在每帧用鲁棒、加权 EM（6 槽、10 轮、残差温度 0.75）拟合运动假设，得到各候选到各槽的软分配。P3 起加入 RGB 边缘感知邻域支持；P4 起用相邻帧 DIS 缓存**只传递运动槽时间先验**、Hungarian 槽号对齐和参数平滑。DIS 合成到首/尾的远程轨迹另用于辅助代理指标，不能视为真值，也不是 P0 候选来源。
5. 对同一个 Top16 池重排，概念上 `logit_i = raw_i/0.012 + g_i×[0.90 log(motion_fit_i)+0.55 log(spatial_i)+0.20 log(temporal_i)+0.10 log(slot_prior_i)]`，关闭的消融项权重设零，`g_i` 是端点几何可靠性。对 logit softmax 得到验证后权重；权重加权候选槽概率，再经两次保守的边缘感知邻域平滑，获得每个查询的六槽后验。
6. P5 置信度为启发式加权和：`0.24×权重峰值+0.20×清晰度+0.20×拟合+0.16×空间支持+0.20×原始强度`，再乘 `0.25+0.75×纹理分数`。拒绝显示值=`1−置信度`，**不是校准概率**。置信度 <0.18 拒绝；否则只允许原始 Top8 中验证后权重 ≥0.035 的候选，若无则强留 Top8 中最高者。拒绝时允许列表清空。P1–P4 不拒绝，也没有 P5 稀疏掩码（均保留 Top16）。

这条链条既不是“仅把色块聚类”，也不是“已在 VACE 内部 Token 上投票”：候选、槽、拒绝和稀疏掩码都真实地索引到当前工程的网格 Token 数组；颜色只是这些数组的绘图。该 Token **不是** VACE VAE/DiT 编码所得 Token，稀疏掩码也尚未真正改变任何 Attention Value 信息流。

描述子本身**没有加入绝对 `x,y` 位置向量**，但它包含两个 24/40 像素 SIFT 邻域和约 25 像素颜色邻域；名义天空格靠屋顶时可能吸入建筑。弱蓝天压缩纹理在 RootSIFT 中也会被归一化成可比的方向，原始相似度可接近 1，哪怕纹理可靠性已判为 0。查询 `simple_multidepth` 帧 60、Token 126 的 Top1/Top2 原始分数约 0.9995、margin≈0.000095、候选熵≈0.811，就是**多位置并列而非唯一像素定位**。坐标和视频时间在候选提出后才进入运动票/空间时间先验，不能把最终候选靠近点击点误说成“描述子内编码了真实位置”。该天空查询 P5 实际拒绝（置信度≈0.112，允许参考 0）；旧网页仍绘制蓝/橙诊断框，造成虚假的成功观感，展示层已经显式修正。

## baseline、比较对象和指标

主要可复验基线是 P0 原始描述子 Top16。比较 P0 vs P1/2/3/4/5 在**同一候选池中**的正确参考名次、权重、拒绝行为与运动槽时间稳定性。Hit@8 问“至少一个正确候选在前八名吗”，Hit@1 问第一个是否正确；MRR 是首个正确参考名次的倒数均值；正确候选总权重衡量注意力方向概率质量。拒绝准确率只检查人工可判定样本上的接收/拒绝；槽 flicker 衡量相邻帧槽身份变化，**不是**物体追踪精度。未来需要补充“有限参考质量 + VACE 全图 Attention / P0 TopK / 投票 TopK 的视频一致性”三方生成对照，以及可见性、遮挡边界、跨帧身份、纹理重复分组的人工真值。

冻结的 24 个**手选 FL 查询**每窗口 8 个，其中 19 个被人工标为有正确匹配候选，5 个被标为应拒绝。19 个条件样本 P0 Hit@1=15/19=78.9%、Hit@8=19/19、MRR=0.853；P5 Hit@1=16/19=84.2%、Hit@8=19/19、MRR=0.912。这个“100% Hit@8”**有选择偏差**：遮挡窗口另外两个可在端点看见的树干查询 token 541、492 实际没有正确树干进入 Top8，却被列入“应拒绝”并且 P5 错误接受房屋候选。若仅为透明度将它们归入“物理上可见、待匹配”的 21 个查询，P0 的直观 Top8 找回为 19/21≈90.5%；两例的具体候选可见性仍需重新冻结统一评估规则，不能把 90.5% 当正式指标。24 条样本数量太小、手选且仅 FL，不能外推所有 Token 或 F 单首帧生成。

全网格代理指标由相邻光流长期合成得到，人工审查已发现其首/尾可见性标签频繁错误，所以只用作**趋势报警**。在三窗口六个 F/FL 条件中，代理 P5/P4 的 MRR 均低于 P0；例如遮挡 FL：P0 0.717、P5 0.610。另一方面 P3→P4 的槽 flicker 明显下降，例如多深度 FL 0.498→0.244、遮挡 FL 0.573→0.306。P5 仅保留约 2.3–2.8 个候选/被接受 Token，但没有证明这种稀疏 Value 路由已提高视频生成。旧“未通过”的准确意思是**未通过预设的注入前严格门槛，特别是遮挡错误接受与 P5 不稳定优于 P3**，不意味着你在网页看见的大多数局部对应是假的。

门槛本身也需审计：当前 P5 只在 P4 的验证权重之后追加拒绝/稀疏掩码，P4 与 P5 的候选排名和 MRR **按实现完全相同**。若把“P5 优于 P3”狭义解释为 MRR，实际上无法测量 P5 的核心作用，可能将可视对应质量误判为失败。v1.1 既有门槛不能事后偷偷改；下一版应事先改为“正确候选进入实际稀疏允许集的比例、错误参考允许率、拒绝—覆盖权衡和真实 V 路由/生成对照”，另行报告排名 MRR。这样既承认目前的网页正面信号，也保留树干错误接受和未接入 VACE 的真实风险。

## 三段样本里具体失败在哪里

| 窗口 | 正面信号 | 主要失效与原因 |
|---|---|---|
| `asymmetric_outbound_0060_0120` | 手选可匹配 7 条中 P0/P5 Hit@8 均为 7/7，P5 未带来 MRR 增益；FL 代理 P0 Hit@8≈0.908 | 重复建材/纹理和透视变化产生相似但非同一物体的高分候选；H1 单一仿射式尺度率不足以区分不同深度、不同局部平面。六槽近似运动规律，容易把跨物体的相似速度并到一起；P5 稀疏只删低权，不补漏召回 |
| `simple_multidepth_0180_0300` | 手选 7 条 P0/P5 Hit@8=7/7，P5 MRR 0.886→0.905；P4 降低 flicker | 透视缩放在多深度物体上的速度场不同，同一物体边缘和内部描述子也不同；H1 的一个尺度率+平移、六槽及 RGB 局部平滑可能把相邻但不同深度混合，或把同物体不同纹理碎裂。代理 FL P0 MRR 0.849、P5 0.787，并非一致排序收益 |
| `simple_occlusion_0360_0480` | 手选条件 5 条 P5 MRR 0.700→0.900；P4 flicker 减少 | token 541、492 是树干/遮挡边界：视觉上树干在端点仍可见，但 Top8 没找回树干，P5 用房屋局部作高置信替代、**没有拒绝**。先是检索漏召回，后是拒绝/跨边界负证据不足；硬 Top8 稀疏进一步封死正确参考。天空低纹理区域拒绝较容易，但不能代表遮挡边界能力。代理 FL P0 Hit@8 0.846、P5 0.782 |

这些失败不能归为“必须换天空背景”或“视频缺光流差异”。两段录屏含透视尺度、深度差异和遮挡，正是当前假设应该接受的考验；天空低纹理确实难以唯一匹配，但关键反例是**可见树干被错投房屋**。旧版灰暗、碎裂的可视化还叠加了长程候选召回缺失、不可信 DIS 可见性及逐帧独立常速度槽绘图等工程问题。当前短窗方法改进了可读性与局部命中，但尚未修好前景/背景边界。

## 不改变总目标的下一版算法

1. **先修召回，再谈投票**：按端点分别维护候选、多尺度/局部几何备选，Top8 无正确候选时允许受控扩至 Top16/32 或邻近参考区；度量“正确参考入池率”，不让投票承担凭空找回池外 Token 的任务。保留 P0 TopK 作为强基线。
2. **显式可见性与拒绝**：首/尾分别估计可见、遮挡、出界和低纹理状态；首尾证据不能用一端错误候选相互借置信度。对树干→房屋等边界引入前后向局部一致性、深度次序/遮挡线索和跨边界负票。用按类别冻结的人工标签校准拒绝分数，避免直接把 `1−启发式置信度` 称概率。
3. **局部多假设运动场**：H1 平移+尺度作为起点，允许每个槽分片透视/局部仿射及深度层；运动槽不是固定的语义物体数，需动态槽数、合并/拆分与边界约束。避免依赖并不存在的大旋转或环绕设定。
4. **遮挡期间保持身份、但不要硬平滑错误排名**：保留 P4 时间对齐收益，加入软记忆与重现检测；把时间先验只用于被局部几何确认的区域，候选排名权重受温度/可靠性控制，防止 flicker 下降掩盖身份错配。
5. **首帧与首尾两种任务分开评估**：F 是给定首帧生成，FL 是给定首尾帧生成过渡视频；短窗尽量提高首帧覆盖，仍不可见的区域才考虑尾帧。后续在真实 VACE Token/QKV 上设计“参考 Attention 稀疏引导”，不应无条件阻断文本或必要的全局视频上下文。

建议新增可操作门槛：按窗口与类别冻结独立 F/FL 人工样本（尤其端点可见的前景边界、仅尾可见、两端不可见），报告查询覆盖率、端点可见条件下 Hit@8/16、错误接受率、同物体随帧保持率和跨深度误并率；做 P0 原始 TopK、P3/P4/P5 同候选的配对对照与置信区间。只有候选质量/拒绝质量过关后，再测真实 VACE 同 seed 生成的一致性提升；局部可视化良好是“可实验”的证据，**不是提升已经成立的证据**。
