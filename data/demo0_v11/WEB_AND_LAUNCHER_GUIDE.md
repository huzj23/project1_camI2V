# Demo0 v1.1 网页与一键启动说明

版本：1.1；会议展示基准：`demo0_v11_d0real`。本页展示真实视频帧上的显式网格 Token 对应、运动投票和稀疏参考候选。它**没有使用 VACE 编码器或扩散模型**；不要把候选可视化当成生成一致性实验。

## 一键启动

在 Windows 文件管理器双击 [start_demo0.cmd](start_demo0.cmd)。脚本调用本机 `hajicar` Python 环境运行 [launch_viewer.py](launch_viewer.py)，检查或启动只监听 `127.0.0.1:8767` 的本地服务，然后打开默认浏览器。网页地址为 <http://127.0.0.1:8767/>。若此前已启动，它复用现有服务，不会重复占用端口。启动失败时看 `runtime/viewer_8767.log`。这不是互联网网站；演示电脑须保留仓库、运行产物和 Python 环境。

若你仍开着原来的 <http://127.0.0.1:8766/>，该服务也读取同一份更新后的网页文件；刷新一次可看到黄色“已拒绝”提示和“全部短窗”入口。两端口的 API 均已检查可读，新增窗口由页面按完成状态过滤，不会把仅“已准备”的窗口误列为可推理结果。

命令行等价操作：`C:\Users\12447\.conda\envs\hajicar\python.exe data\demo0_v11\launch_viewer.py`。不打开浏览器的检查：末尾加 `--no-browser`。网页服务无需在会议前手工另开终端，且现已在本机 8767 端口健康运行。单击脚本后浏览器是否弹出仍取决于演示电脑的默认浏览器设置。

会议前建议依次检查：运行选 `demo0_v11_d0real`；任选三段已冻结窗口；当前帧进度条拖到中间；点击中间图的树干、房屋角点或有纹理的区域；检查首/尾图的 R1–R8 和表格；在全帧 Overlay 选择一个 slot，看白色边界随进度条变化。要按时间顺序浏览两段录屏的全部短窗，可选“全部短窗（冻结 + 扩展）”聚合入口；完成的新窗刷新页面后加入。F 模式尾图仅展示、不参与匹配；FL 模式两个端点均可提供参考。

## 网页控件怎么用

| 控件 | 它显示/改变什么 | 易误解处 |
|---|---|---|
| 运行、短窗口、当前帧 | 选数据版本、片段和该片段的相对帧；“全部短窗”合并冻结及已完成扩展窗口；点击中间图或输入 Token ID 选择当前查询 | 同一个 Token ID 在不同帧仅代表同一网格位置，不是已追踪的物体 ID |
| F / FL | 候选参考池仅首帧 / 首尾两帧并集 | F 下尾图仍显示原图，但不参与候选 |
| 消融方法 P1–P5 | 在同一批原始 Top16 候选上逐级加入运动几何、空间、时间、拒绝/稀疏处理 | 不是五个 VACE 模型；P5 较复杂并不保证比 P3 好 |
| 候选数 8 / 16 | 图、局部裁剪和表格显示多少个候选 | P5 实际稀疏允许只从**原始 Top8**选；显示 16 主要用于诊断漏召回 |
| 权重视图：原始候选 | 按描述子余弦相似度的 Raw 排名与分数画框 | 这是 **P0 baseline**，即同网格、同参考池、同描述子，但不用运动投票 |
| 权重视图：投票验证后 | 按 P1–P5 重新分配的候选权重排序，框粗反映权重 | 候选池仍来自 P0；投票不能把 Top16 之外的正确参考找回来 |
| 显示热力图 | 左右图铺色：Raw 采用固定余弦分数区间 0.45–1.0；验证后仅 Top16 非零 | 开启后会遮挡图像纹理；默认关闭，查具体框时建议关闭 |
| 高亮同运动集合 | 中间图按所选 Token 的运动槽**软概率相似度**涂色 | 不是严格物体分割，弱纹理或遮挡处可跨物体 |
| 全帧 Overlay 类型 | 运动槽色、参考端点、置信度或运动箭头的整帧可视化 | 全帧色块更适合看变化趋势，不能替代逐 Token 对应检查 |
| 突出运动槽 | 列出当前帧所有 0–5 槽；选槽后在全帧 Overlay 用白边界勾出所有**硬归属到该槽且未被拒绝**的 Token | 白边界是离散槽成员，不保证属于同一语义物体；换帧时可观察其运动轨迹 |

P1 是 H0（单纯平移速度）验证；P2 是 H1（平移加随图像位置变化的尺度率）；P3 加 RGB 边缘感知邻域一致性；P4 加相邻帧槽传播与身份平滑；P5 再加低置信拒绝和稀疏参考掩码。方法定义和真实指标详见 [VOTING_ALGORITHM_REPORT.md](VOTING_ALGORITHM_REPORT.md)。

## 数字读法

“置信度”是权重峰值、候选清晰度、运动拟合、空间支持、原始分数和纹理的**启发式综合分数**，范围 0–1，尚未按真实正确率校准，不能解读为“90% 正确”。“拒绝概率”目前就是 `1 - 置信度`；在 P5 中置信度低于 0.18 才真正拒绝，并清空允许参考集。P1–P4 不启用拒绝，显示值没有相同决策含义。“纹理置信度”反映局部可区分性，天空低纹理通常较低。“稀疏保留”是当前可见候选中带绿色标记、允许进入未来参考路由的数量；当前只是**保存掩码**，未接入 VACE Attention Value 通路。

天空案例提醒：`simple_multidepth_0180_0300` 的当前帧 60、Token 126 位于纯蓝天空，纹理分数为 0；描述子 Top1/Top2 相似度都约 0.9995，分差只有约 0.000095，Top16 候选熵约 0.811。首/尾图上的很多蓝天框是**外观相似、无法唯一定位**，不是“同一个天空物理像素被成功追踪”；部分靠近屋顶的名义天空格还会因 24/40 像素支持域混入建筑信息。P5 对这个纯天空 Token 给出置信度约 0.112，已拒绝且稀疏允许集为空。网页现在用黄色警示和灰色虚线框明确把这些参考标为“仅供诊断”，拒绝查询也不再高亮同运动集合。原始蓝天的高余弦匹配在不投票 P0 中就存在，不能凭它认为投票算法发现了可靠运动或发生了尾帧泄露。若查询本身位于窗口首帧，首帧同位置是**锚点自匹配**；位于窗口尾帧且选 FL 时也有尾帧自匹配，二者的置信度 1.0 是边界条件，不是跟踪成功证据。建议把进度条移到窗口中段检查天空或物体运动。

“运动槽”是最多六个有相近平移/透视尺度规律的候选运动假设，参数表的 `v=(vx,vy)` 和 `scale-rate` 使用归一化窗口时间及网格坐标，不是世界坐标速度，不含真实深度或语义名称。槽号在同一窗口里用时序对齐尽量稳定，跨窗口不可直接比较。选一个槽看白边框，可以检查同槽 Token 是否随视频一起移动、是否错误跨越前景/背景边界；若发现混槽，在页面“人工核验记录”可以记笔记，但冻结运行的标注不可写，扩展运行完成后才可写新标注。

表格中的 Raw/Voted 分别是原始名次和投票后名次；`参考端点` 表示候选来自首帧或尾帧；`稀疏允许` 的 YES/绿色竖线才是 P5 推荐的有限参考集合。中间绿色实线框是查询 Token 的**名义 16×16 像素格**，白色虚线表示实际描述子最大 40 像素邻域。白框绝不是 VACE 的真实感受野。

## 当前可讲的结论

多数经人工挑选的纹理区域在首/尾帧候选中找到了接近正确的 Token，说明有限参考注意力**有值得测试的方向信号**。但 24 个手选 FL 查询中遮挡树干两例漏召回且被 P5 错误接受；局部代理指标不稳定；目前没有任何 VACE 生成对照。会议上可以展示“参考方向候选已可视化”和“需修复遮挡及 VACE 对齐”，**不能**宣称已经提高生成视频的一致性。
